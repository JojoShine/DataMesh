# 数据流拖拽编排与 Python / JavaScript 代码节点

状态：用户已确认并实施；2026-10-22 已部署主环境。验收见 ../../validation/governance/2026-10-22-code-nodes.md。

## 已确认的目标

数据流支持真正的可视化编排，以及直接编写 Python 或 JavaScript 处理数据。现有来源、模型、质量分流、发布、共享及权限流程全部保留。面向业务人员的常用算子仍可直接配置，代码处理作为专业能力，不要求普通用户学习代码。

界面沿用当前单层 dialog；画布和配置区在同一层，保存、发布、运行、试运行和返回操作位于右下角。不得使用子代理或红绿测试流程。

## 当前实现与缺口

- 现有画布为自绘 SVG 和固定位置节点，能展示依赖关系，无法拖动或直接重连。
- 数据流以固定版本定义执行；后台通过 PostgreSQL 临时数据表串接来源和各处理节点，最终核验模型并登记成果。
- 文本转换仅支持保持原值、去首尾空白、大小写转换。当前没有 Python、JavaScript 或通用脚本执行服务。
- 现有执行过程已经具备来源权限复核、租约、取消、输入及中间结果预算、敏感字段控制、质量分流、成果登记和血缘，新增代码处理必须接入这些机制。

## 编排交互

采用 React Flow 的 React 组件，替换现有画布，保留已有算子配置组件和业务路由。

1. 算子按来源、字段处理、条件与记录处理、关联与汇总、质量、自定义代码分类；支持拖入，也保留点击添加。
2. 拖动节点只改变布局；连接端口才改变处理依赖。拖入空白处不会擅自改写其他连线；在连线上插入须由用户明确执行。
3. 普通处理节点有一个输入；关联节点区分左、右输入；质量节点区分合格、不合格输出。连接时提示缺少输入、重复连接、循环及不支持的分支。
4. 选中节点，在同层右侧配置输入、处理规则和输出字段，展示字段名称、类型和业务含义。已有字段改名和转换不因拖动而丢失。
5. 支持缩放、适应画布、自动排列、撤销和重做。重新打开恢复位置；布局与执行定义分别保存，纯移动节点不触发业务变更或旧成果失效。
6. 已发布版本可浏览布局；修改业务配置或连线须创建修订，保留历史版本。后端仍完整验证图结构与权限。

## 自定义代码节点

新增“自定义代码”算子，节点内选择 Python 或 JavaScript，直接编辑对应语言代码。代码与依赖环境版本固定到已发布的数据流版本，重试沿用原代码，不执行最新草稿。

第一阶段明确采用逐行转换接口，支持完整语言语法，不是公式输入框：

```python
def transform(row, context):
    result = dict(row)
    result["name"] = (row.get("name") or "").strip()
    return result
```

```javascript
function transform(row, context) {
  return { ...row, name: (row.name ?? "").trim() };
}
```

- `row` 是当前节点已授权的输入字段；`context` 提供本次只读业务参数，不包含连接凭据或任意资源访问能力。
- 每条输入返回一个对象；输入、输出数量一致。需要筛选、分支、汇总时继续使用对应算子，避免第一阶段混入整表脚本、任意行扩增或外部写入。
- 输出字段必须声明名称、数据类型、精度、可空性和业务含义；默认可带入上一步字段，用户补充新增字段。返回缺字段、多字段、类型不匹配或超出约定精度时，明确指出节点、字段和原因。
- 金额等精确小数通过十进制字符串传递；大整数不得自动转换成 JavaScript Number。Python 可使用固定环境提供的 Decimal；JavaScript 配套固定版本十进制工具，避免金额或编号悄悄损失精度。
- 提供两种语言的可运行示例、输入字段补全和错误行定位；代码编辑器按需加载，不增大其他治理页面的初次加载负担。
- 第一阶段提供固定运行环境及已登记的库清单；运行中不在线安装包。后续库扩展通过运行环境发布办理，固定版本后复用。

## 真实执行与原流程衔接

来源 → 已有算子 → 代码节点 → 已有算子 / 质量检查 → 模型输出 → 成果核验发布。

新增独立代码执行服务与每次运行独立的隔离任务环境。业务服务只通过受认证的窄接口提交固定语言、代码、已授权数据与配额；不把主环境 Docker socket、数据库密码、对象存储凭据或宿主目录交给脚本。Python 和 JavaScript 执行器均不得在主业务进程内直接运行用户代码。

任务环境采用固定镜像、非特权用户、只读基础文件系统、受限临时空间和禁止外网访问；限制 CPU、内存、进程数、运行时长、输入输出及日志大小。脚本异常、超时、取消或权限失效须终止该任务环境，不能仅停止页面等待。主环境不支持隔离运行时，代码节点显示不可运行原因，不能退化为无隔离执行。

脚本只消费上游已经读取和授权的数据，不能自行连接来源。后台分批传输，累计配额沿用现有数据流限制，不一次把完整数据集读入内存。代码结果回到现有中间处理区，重新核对字段和类型，并继续执行质量和模型门禁；成功提交前不登记可发布成果。

代码节点失败则整个运行失败并回滚待提交结果，记录节点、错误类别与代码行号；默认不在持久日志中记录数据值。代码引入的输出血缘先保守关联全部代码输入字段，并标明“代码处理，保守追踪”，不声称能自动精确分析任意脚本。敏感性不得因为脚本改名或生成字段而被降低。

试运行也使用同样隔离环境和权限，只处理明确限量的样本，展示输入与输出差异；样本结果不登记为成果、不代表完整运行通过。

## 兼容与交付

- 旧数据流不需要修改即可继续浏览和执行；新增脚本字段为可选结构，接口和 OpenAPI 同步扩展，不删除旧字段或改变原节点语义。
- 画布位置保存为布局信息，业务定义保留现有依赖结构；代码、输入输出声明和运行环境版本属于业务定义。
- 新增运行环境的健康状态、取消和配额结果接入现有运行详情；不创建第二套成果发布流程。
- 交付包含前后端实现、真实 Python / JavaScript 执行环境、可运行示例、字段说明、部署备份、回滚办法和主环境验证记录。

## 验收条件

1. 鼠标拖入、移动、连接和重连节点可实际改变并保存正确关系；刷新恢复布局；撤销重做不丢配置。
2. 两种语言分别执行客户姓名清洗及精确金额处理，真实结果与声明一致；继续通过质量检查和成果发布。
3. 旧数据流回归通过；固定代码版本重试，既有成果不被改写。
4. 无限循环、异常、超大输出、取消、权限失效、错误字段类型、敏感字段血缘及精度边界得到实际验证。
5. 非授权文件、网络、凭据和跨任务数据不能被脚本获取；没有隔离执行器时不能误报成功。
6. 试运行与完整运行有明确区别，样本不能发布为成果；1920宽及窄屏可操作，单层 dialog 与右下角操作栏保持一致。
7. 修改后做针对性检查、构建和真实执行验证；不使用子代理，不采用红绿测试流程。完成后部署主环境并验证原有业务数据保持。
