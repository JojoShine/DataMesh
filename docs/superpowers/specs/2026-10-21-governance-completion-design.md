# 治理能力补齐设计

状态：按用户已确认的范围实施；分批验收，本文范围尚未全部完成。

## 目标与边界

建立“责任与标准 → 元数据与模型 → 可执行数据流 → 可调度工作流 → 质量整改 → 版本化成果 → 发布共享”的闭环。沿用现有账号、部门、加工授权、掩码、审计、数据源连接、结果归档和资产发布，不新建平行权限体系。沿用唯一字号规范，复杂编辑进入独立工作区，避免嵌套弹窗。

治理不是只有规则配置或成果绑定。建模必须支持概念、逻辑、物理模型，定义字段、主键、关系、标准与输出契约；数据流必须实际处理数据，工作流必须实际控制运行。界面只能展示已实现能力，不把未来能力标记为可用。

## 版本及责任

主题域、术语、标准和模型由部门治理人员维护。记录责任人和维护人；跨部门编辑拒绝。定义每次保存形成独立版本；发布后定义不可改，后续修改创建新草稿版本。发布、停用都有审计，工作流只引用明确的已发布版本，停用不抹除历史。并发保存使用基准版本拒绝过期写入。

采用独立的治理定义与版本表，不改变既有 business_records 的 kind 约束；保留已有业务数据、权限与历史审计，治理业务统一切换新流程。标准和模型关联使用 id + version，发布检查引用状态、类型、部门及字段约束。版本对比明确字段删除、类型变化、主键变化、收紧可空、降低敏感等级等破坏性变化，保留历史。

## 元数据、标准及建模

1. 主题域与责任：业务说明、责任人、维护人。
2. 术语与标准：术语解释、业务编码、类型、长度、精度、取值码表、空值及敏感要求；发布形成版本。
3. 元数据：真实来源对象与结构版本，业务描述、主题域、责任与字段标准关联；结构刷新保留差异证据。画像明确全量或采样及覆盖量，敏感样例遵守授权。
4. 模型：概念/逻辑/物理层级、实体字段、复合主键、实体关系、标准关联。物理模型输出经类型映射和标识符转义的 PostgreSQL/MySQL DDL 预览，预览不自动执行建表。真实建表作为明确且可审计的独立操作，检查目标写入权限和白名单，禁止自动覆盖已有表。
5. 输出契约：模型版本、结构约束、质量门槛、鲜度、责任与变更说明。变更影响必须可见；破坏性发布需显式说明迁移办法，不能静默替换运行中的契约。

## 数据流与工作流

不引入新框架或未授权服务。先复用现有 Go 执行服务和受控数据库执行能力，输入通过现有授权入口读取，按运行隔离中间结果，输出事务提交。禁止把任意用户 SQL/表达式直接执行于业务库。算子定义为受限结构，支持选择、投影、清洗、码表映射、过滤、去重、关联、聚合、质量分支、模型输出。图校验包含环、悬空节点、端口及字段类型、连接键、聚合与输出约束。参数有限定类型，引用版本固定。

每次运行固定图版本、输入对象与快照、标准/规则/模型版本、操作人及授权范围。节点记录状态、输入输出量、耗时、有限诊断和错误码；不把敏感记录写入普通日志。取消、超时、权限中途撤回必须停止并清理未提交结果。存在提交不确定性时标记 unknown，先核对再允许重试，禁止盲目重复写入。

工作流负责数据流和检查等任务间依赖、串并行、条件、参数、手动/定时/依赖触发、失败恢复、产出登记与发布申请；数据流负责数据本身的转换。定时必须有时区、并发策略、错过策略和启停。沿用持久租约和运行记录，重启不能产生重复提交。

## 质量、血缘与成果

复用六类现有规则，增加跨字段/跨表检查、模板、质量门禁、历史趋势与按记录定位。质量失败可生成有责任人与期限的问题单，支持处理记录、复测、通过后关闭，历史不可覆盖。坏数据分支独立隔离，不能混入成果。

新输出契约允许过滤、去重与聚合改变行数及主键，但必须证明算子输入/输出关系、执行完成、模型约束、质量门禁、授权与输出提交一致性。旧的手工成果绑定入口、同名字段/同主键/同条数逐行核验及固定示例处理流程由新流程替换，不维持双轨或兼容入口。已有成果及历史证据保留可查，不将旧核验结果冒充新模型契约的合格证明。

自动登记治理成果版本，关联模型、运行、标准、质量与字段血缘；发布仍经现有资产发布审核。字段血缘覆盖投影、转换、连接、聚合、规则和产出；影响分析能够定位到引用版本和下游发布资源。运行运维提供真实状态、日志、失败恢复、鲜度与告警；保留、停用和清理不能破坏审计证据或在用下游。

## 信息架构

治理总览、元数据管理、标准与术语、数据建模、开发与编排、质量管理、血缘分析、运行运维。基础实现阶段仅开放已实现入口；元数据、质量规则和质量检查整合进新工作区；旧业务入口不并行保留。权限与资产发布复用已有模块。

## 验收

两份授权来源 → 关联与清洗 → 码表标准化 → 去重/聚合 → 合格/不合格分流 → 目标模型 → 治理成果版本 → 现有资产发布与共享。检查固定版本、节点进度与日志、取消与失败回滚、重试、授权撤回、并发与重启恢复、字段血缘及质量整改复测。必须真实数据库与真实接口验证，不能用画布或样例 JSON 代替后端能力。

主数据融合、完整指标语义系统和 AI 辅助治理属于后续专项；本轮不将其作为已经支持。
