# 多类型资源挂载与真实交付设计

状态：用户已确认修订方案（Excel 仅导入实际数据）；实施计划待审阅，尚未实现。日期：2026-10-16。

## 已明确需求

- 共享交换覆盖库表、文件、API 资源的真实挂载与交付。
- 从目录行打开挂载，无独立挂载菜单。居中弹窗、固定步骤和底部操作栏。
- Excel 仅导入实际数据；目录维护阶段已有数据项定义，不再提供数据项定义导入入口（按用户最新说明修订）。
- 保留原始数据与治理成果的区别，以及现有管理员、普通用户授权规则。

## 现状与本次边界

现有资源解析仅支持 raw_object / governed_dataset，挂载校验只接受 database + query，交付接口只有库表受控查询。数据源和数据读取仍有本地样例地址、customers 表及固定字段限制。文件对象存储客户端和加密凭据机制可复用，但上传下载、Excel 解析入库、通用表发现、API 代理尚未实现。

本次须真正补齐适配器和交付接口，不能仅去掉前端“不支持”提示。保留现有 CDC、质量和血缘路径，新增数据库直读挂载与 Excel 导入资源，不将它们伪装为已有 CDC 归档。数据库首批通用适配 PostgreSQL、MySQL；Oracle 原有能力保留，不虚称已有通用表发现与直读。

## 方案选择

采用现有单体服务内的类型适配，复用目录、挂载修订、审核、授权、审计及 Docker 存储。相较只扩充表单，此方案能完成交付；相较新建文件服务/API 网关，部署和操作更轻。不新设第五个平台。

目录的数据层（原始/治理成果）、载体（库表/文件/API）、接入方式（数据库/Excel/上传/API登记/已有成果）分别表达，避免把 Excel 文件下载和 Excel 数据入库混成一件事。

## 业务流程

### 库表：从数据库挂载

目录行“挂载资源” → 数据库 → 选择已有数据源（也可打开现有新增数据源表单）→ 连接检查 → 选择 schema / 表或视图 → 读取真实字段与有限预览 → 映射目录数据项 → 保存挂载草稿 → 校验 → 审核 → 启用。

增加 PostgreSQL/MySQL 元数据发现和只读分页查询；不要求所有库表先建 CDC 任务。标识符只允许来自元数据发现结果并按驱动引用，过滤参数绑定，不能提交任意 SQL。无稳定唯一键的资源允许登记，启用前明确提示配置稳定排序键或转为导入快照，避免不稳定分页。

已有原始归档及已发布治理成果继续可选；治理成果引用现有数据集和契约版本，不重新采集。连接检查成功不等于挂载启用。

### Excel：导入实际数据

入口放在库表挂载中的“Excel 导入”。目录已维护的数据项是唯一结构依据，导入不新增、覆盖或自动修改目录字段和类型。

按技术字段名或业务名称自动建议匹配，歧义由用户确认。每个目录字段只映射一个 Excel 列，禁止重复映射。必填字段缺失时阻止导入，可空字段未匹配时填空；多余列列出并明确提示不导入。类型、长度、精度和可空性按目录定义校验，不从样例值推断后覆盖目录。若目录尚未维护数据项，提示先完成目录维护。

上传 .xlsx → 选择工作表/表头行 → 匹配已有目录字段 → 样例预览及映射确认 → 按目录定义完整校验 → 确认导入 → 生成可查询的版本化库表资源 → 保存挂载草稿 → 校验、审核、启用。

首批支持 .xlsx；旧 .xls 明确提示另存为 .xlsx，不提供失效入口。首批限制 20 MiB、100 列、5 万数据行；在界面和服务端同步提示和校验，可根据实际容量再调整。数字精度、日期和空值按确认的契约转换，技术 ID 默认保留字符串，避免丢前导零。公式、外部链接、宏不执行；公式单元格要求转为值后上传。校验错误给出工作表、行号、列名和原因，失败不能产生“可用”资源或部分生效数据。

原文件存私有对象存储，结构化数据存独立导入数据表，以资源版本和行序号索引。不为每次上传创建任意物理表。保留来源文件摘要、导入人、行数和批次。重新导入建立新版本，审核启用前旧版本不变。

### 文件挂载

目录行挂载 → 文件 → 上传 → 展示名称、类型、大小、摘要及版本 → 保存挂载草稿 → 校验实际文件可读取 → 审核 → 启用。

复用 RustFS/S3 私有存储，不使用浏览器传来的路径作对象键。首批允许明确配置的 PDF、文本、CSV、常见 Office 文档，默认 50 MiB；检查扩展名、内容类型和实际内容，拒绝可执行文件、脚本、宏和归档包。临时上传超时或确认失败可清理；已引用版本不得清理。

文件按完整文件版本授权下载，不承诺任意文档逐字段脱敏。需要字段级限制的 Excel/CSV 应走库表导入。普通使用者审批获权后通过平台下载，服务端复核授权与挂载状态并记录审计，不暴露存储凭据或永久公开链接。

### API 挂载

目录行挂载 → API → 配置地址、只读操作、参数定义、鉴权方式及响应结构 → 服务端测试 → 返回字段映射 → 保存草稿 → 校验、审核、启用。

首批支持 JSON 查询 API，GET 或明确声明为查询的 POST；鉴权支持无鉴权、Bearer、API Key。鉴权值加密存储，仅可替换，不在详情或日志回显。请求参数白名单和类型校验，消费者不能更换目标 URL、路径、鉴权头或任意透传请求头。

消费方从平台调用代理接口；平台检查授权、有效期、挂载状态，限制超时、响应大小和调用频率，对结构化响应投影批准字段并脱敏。响应结构不符、上游失败不能被标记成功。网络目标采用管理员配置的允许列表，明确放通指定本地 Docker 服务；不简单开放全部内网或自动跟随重定向。

## 权限与生命周期

三类资源共用挂载草稿、校验、提交审核、审核通过、启用、暂停、卸载流程。目录草稿允许先关联资源，正式交付仍须目录发布和挂载启用。

普通维护者需要相应部门/资源维护权限，普通使用者需要对应交付动作和范围的授权；查询、文件下载、API 调用不得互相冒用授权。admin 按现有用户批准规则拥有全部业务权限，但不绕过有效状态、输入有效性及网络目标策略。所有真实调用、下载和查询保留审计，不记录凭据或完整敏感响应。

更换资源、响应结构、字段映射、文件版本和鉴权目标需产生修订并重新校验审核。暂停/卸载和授权撤销后，后续交付请求立即拒绝。普通用户跨部门不能凭资源 ID 绕过管理与使用权限。

## 数据与兼容

保持已有接口和 raw_object / governed_dataset 的含义；用兼容扩展表达新资源类型和访问方式，不给旧记录强制补不存在的属性。目录 DataLayer 继续表达原始/治理语义，新资源引用类型独立处理，避免把 API 当成治理成果。应用授权材料扩展交付动作，默认旧记录仍为 query。

新增导入批次与行数据、文件版本和 API 配置等存储；挂载版本引用不可变资源版本。迁移只增不删，契约 JSON Schema、Go 类型、前端类型和接口文档同步修改。外部 IO 不占用长数据库事务，完成后通过版本检查短事务确认，失败回收暂存文件或保留可重试批次。

## 实施顺序及验收

1. 公共资源类型、交付动作和权限门禁兼容扩展。
2. 数据库元数据发现、字段映射和通用只读查询；保留旧 CDC 路径回归。
3. Excel 与已有目录字段匹配、实际数据预览、全量校验、入库和查询。
4. 文件上传、版本挂载、受控下载。
5. API 登记、真实联调、代理调用及字段范围控制。
6. 三类目录在本地 Docker 完成从挂载、审核、启用、申请授权到真实交付的验证。

测试必须覆盖：数据库不同表名与字段的实际读取；Excel 工作表选择、表头歧义、必填列缺失、多余列排除、错误行、前导零及小数精度，以及导入不修改目录定义；上传失败无半成品启用；文件下载内容摘要一致；API 请求参数和返回字段真实生效；未授权、跨部门、过期、撤销、暂停、版本变化均被阻断；管理员操作符合已有约定；现有样例原始与治理查询不回退。

前端检查居中弹窗、固定导航及操作栏、步骤校验、输入提示和默认 AntD 尺寸。在 1920×1080 及窄屏验证。用可控本地 API 测试服务做联调，不把返回固定成功结果当作真实接口接入完成。
