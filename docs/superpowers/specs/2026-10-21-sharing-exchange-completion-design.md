# 共享交换第一批补齐设计

状态：待用户审阅，尚未实施。日期：2026-10-21。

## 目标与范围

沿用现有数据源、CDC 接入任务、ETL 数据交换和运行明细入口，完成已确认的三项工作：远程 CDC 接入、授权资源批量交换、交付对账。沿用既定字号；业务操作单层展示，返回保留选择及表单。不得绕过目录发布、使用授权、加工授权、脱敏、质量门禁或可信连接范围。

三项独立验收，逐项交付；任何未通过验收的数据库或资源类型都明确显示能力边界，不以测试连接成功代替可采集或可交换。

## 现有代码约束

- tasks.go 以数据库类型作为 Binding；runtime.go 和 archive.go 据此拼接样例连接器及主题。对象登记与预检同样依赖内置模板。需要共同解除固定绑定，保留旧任务兼容。
- etl_resources.go 一次性读取资源；原始资源从完整归档事件重建当前值，治理资源经 assess 校验。archive.go 另有事件数、压缩文件及解压读取限制；runtime.result/sourceRows 也固定样例查询。仅改 ETL 限额无法扩容。
- 直接库表 ETL 已有流式读取、目标整轮事务、持久队列、租约、目标占用及 unknown 人工核实。资源模式须复用这些控制。
- Written 是提交处理行数，不等于新增唯一行数；跨系统提交结果仍可能不确定。对账不能改写这些事实。

## 方案选择

采用在现有执行链路上补齐能力的方式：复用 Kafka Connect/Debezium、Kafka、对象存储、平台数据库及 Go ETL worker。

不采用仅解除前端限制/提高常量的方案，因为固定绑定及全量内存读取仍会阻断真实数据。现阶段也不引入新的调度或计算框架，避免形成两套任务和授权体系。

## A. 远程 CDC 接入

### 使用流程

数据源选择已登记库表 → 查看数据库条件和平台条件 → 配置采集任务 → 校验配置 → 创建 → 启动首次快照及持续增量。任务明细展示实际连接器状态、所选表、快照完成情况、事件进度、位点及错误处理指引；运行状态不再自动意味着治理结果已生成。

覆盖 PostgreSQL、MySQL、Oracle，按数据库分别实现及验收。Oracle 明确记录服务/CDB/PDB 与 LogMiner 条件；不能自动确认的条件标为待管理员核对，不能静默通过。缺少运行所需驱动或条件时，禁用启动并说明原因。

### 身份与隔离

- 新任务保存明确的连接器名、主题前缀、表范围、结构版本、配置版本和数据库专属标识。名称由平台生成；MySQL server-id、PG slot/publication 等避免冲突。
- 初期每个任务对应一个表和一个独立采集作业；同源同表重复创建需在平台阻止或复用明确绑定，禁止覆盖已有作业。旧样例任务继续通过旧绑定解析。
- 复用加密数据源凭据。只向内部采集服务提交所需配置，接口响应、审计、错误和导出均不得包含密码。
- 启动及恢复重新核验操作权限、白名单和数据源配置版本。白名单移除或账号停用后，通过受控核查暂停相关新作业，不允许凭旧配置继续新启动。
- 配置校验不改变业务表。PG publication/slot 等外部对象的生成方式及归属在启动前展示，禁止重用或删除无关对象；不自动修改日志级别、账号权限或重启外部数据库。

### 生命周期与故障

新建、启动、暂停、恢复、重试失败控制动作和实际状态核查均持久记录。控制操作必须可重入：平台落库与采集器创建之间失败，重新核查实际配置及归属后恢复，不能创建重复采集器或重置位点。

暂停/恢复保留已有位点；表结构变化需明确告警并阻止不兼容交付。连接器运行、快照完成、归档完整、可用于交换分别展示，不能混成一个“成功”。本期不提供删除外部日志对象或任意历史位点重放。

### 归档与交付连接

归档改用任务绑定的实际主题、分区和范围。清单记录分区起止位点、结构版本、压缩块摘要及总量；分块流式写入对象存储，验证成功后才发布清单。缺段、位点过期、快照未完成不得生成“完整”交付快照。

原始资源选择固定清单版本进行交换，不在运行中追读变化的范围。按主键重建快照时使用有界批次和受控暂存，不能用百万条事件的内存 map；重建保留更新及删除语义。该重建不意味着本期已支持向交换目标传播删除。

## B. 授权资源批量交换

### 读取与权限

将资源读取改为按批消费的内部接口，与现有 ETL 流式写入配合；不扩大普通交付查询接口的分页上限。库表资源、原始归档资源和治理资源分别适配；不通过操作者的连接运维权限替代使用授权。

- 开始执行时固定目录发布版本、资源契约、输入快照、字段范围和适用授权。
- 使用既有授权和脱敏规则先投影数据，再做字段转换；转换仍要求允许派生成果的加工授权。
- 每批及提交前重新核验授权有效性、撤权、目录/挂载状态；失效后停止并回滚，提交结果不明仍进入 unknown。
- 只读一致性事务读取数据库资源；归档资源使用固定完整清单；治理资源保留质量门禁。治理结果的动态库表绑定必须先具备正确来源及规则版本，不能把样例 Doris 结果当成任意治理成果。

### 容量与行为

目标为三种资源模式都支持受配置控制的大批量交换，默认与直接库表模式一致：200 万行、1 GiB、30 分钟。按资源类型公布实际能力，通过某一类型测试不得把其他类型上限一并放开。

超限显式失败并回滚，不截断成功。每批沿用最多 500 行及受控字节缓冲，保留精确小数、超大整数、空值与时间类型处理。敏感主键脱敏后冲突或失去可映射主键时明确拒绝，不回退使用未脱敏值。

目标仍为整轮单事务；本期不引入分段提交或断点续传。大数据量归档、快照暂存及失败清理有独立容量上限和过期回收，不把授权数据持久放入普通日志。

## C. 交付对账与回执

### 状态分离

保留现有 ETL 执行终态，新增独立对账记录和验收记录：执行结果、技术对账、业务验收三者分别展示。历史运行标为未执行对账，不能补写成已通过。

技术对账状态：待核对、核对中、通过、不一致、核对失败。业务验收状态：待验收、已接收、已驳回。只有确认已提交且技术对账通过的运行可确认接收；unknown 运行先完成事务核实。

### 对账范围及算法

- 对账以本次实际交付的最终主键集合及映射字段为范围，不比较目标整表总行数，不计未映射字段和其他批次数据。
- 期望值使用本次读取快照经授权脱敏及转换后的结果，不能重新查询变化后的源库来代表原输入。
- 通过目标类型规范化比较精确数值、时间、二进制、null 等；主键等价和重复键按实际 upsert 的最终结果处理。区分读取行数、处理行数、去重后的交付主键数和核对行数。
- 写入事务内读回映射字段校验；不一致则提交前失败回滚。提交成功后另行读回本次范围，形成交付核对报告；外部修改造成的差异如实记录，不把已提交运行改为已回滚。
- 保存有界的核对索引及规范化摘要，限制权限和保留期；不保存原始字段值或可直接识别的敏感主键。摘要使用带密钥的摘要并按运行绑定，避免低熵字段被枚举；后续重新核对所需主键索引加密保存并及时清理。
- 报告包含运行/配置版本、输入范围、核对时间、计数、摘要结果、差异数量和安全错误码；页面及导出不泄露字段值。技术核对失败可单独重试，不触发重新交换。

接收人或具备明确管理权限的管理员填写接收/驳回说明，保存身份与时间；管理员代办需记录代办原因。回执不新增数据使用权限，不修改原运行和原授权；后续处理追加记录，保留历史。

## API、界面和兼容

新增字段采用可选字段与向后兼容迁移。现有任务、授权及运行查询保留原语义；新 CDC 配置和技术对账/回执使用明确的新请求，更新 OpenAPI 及严格前端类型。

CDC 诊断、配置与结果在现有任务界面分步展示。ETL 运行明细增加“交换结果 / 对账 / 验收”内容，保留日志和告警入口。不得增加原始数据交换独立菜单或叠加业务弹窗。

## 实施与验收顺序

1. CDC 任务绑定及控制改造，依次完成 PG/MySQL/Oracle 真实集成验证；旧样例任务、岗位和白名单行为回归。
2. 批量资源接口及库表资源；再完成原始归档重建和治理结果批量适配，每类独立公布容量与验证结果。
3. 同步实现写入校验、提交后对账及业务回执；前两阶段的最终交付必须经过该闭环验收。

必须验证：

- 同类型两个独立数据库及不同表并行，连接器/主题/日志对象不互相覆盖；快照和 insert/update/delete 真实事件一致；暂停恢复保留位点；控制超时、服务重启、权限撤销可核查。
- 普通授权账号超过 1 万行且最终百万行的真实交换，跨部门授权、敏感字段脱敏、途中撤权、质量失败、超限、精度与事务回滚；不得只用 admin 证明授权路径可用。
- 三种资源读取模式分别做规模与内存检查；不把直接库表百万行的历史成绩当成资源模式验收。
- 目标有额外历史行、重复键、触发器改值、提交后外部改值、对账服务中断、unknown 核实后的核对、回执越权及重复提交。
- 单元、集成、前端交互、类型和构建检查；桌面及窄屏检查，凭据与敏感值不出现在日志和报告。

真实验证先使用隔离测试库。现有用户业务库可做已授权的只读条件检查；不自动改变其数据库日志配置、创建日志对象、启动持续采集或写入业务表。生产接入作为明确展示配置和影响后的上线动作。

## 本批不包含

定时/事件调度、增量 ETL 水位与补跑、自动退避重试、断点续传、通用复杂转换、Oracle 直接 ETL 写入、字段血缘、外部通知及整个平台高可用。以上不妨碍三项已确认目标的独立验收，但不能宣称已经实现。
