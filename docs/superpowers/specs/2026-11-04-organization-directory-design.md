# 组织人员与目录表单联动

用户已同意核实后的补齐建议；直接在当前工作区实施，不使用子代理、不重复确认、不提交 Git，集中做必要验证。

- 复用统一账号、平台角色、资源范围授权、事务、审计及幂等；增加组织/部门树，组织为根、部门可多级，人员归属既有 department_id。历史标识不变，历史单位名称可完善，真实单位代码由管理员维护，不编造。
- 管理入口在数据安全“身份与权限”，管理员账号菜单增加直达；普通人员不能取得管理权限。组织单位支持新增和修改名称/代码/状态；所属层级创建后固定，避免跨组织隐式转移资源。存在在用人员或下级时不能停用。
- 人员支持新增、编辑姓名/所属部门/平台与角色、禁用及启用。权限修改使会话失效；调岗撤销原资源范围及加工授权，原资源和历史审批归属不变；自降权、自禁用禁止，保留可用管理员。
- 新建目录从所属组织读取提供单位名称和代码，只读展示；编辑他人目录按目录原部门读取。更新周期为选项，保留历史自定义值。分类路径只从编码字典选择，字典更换清理无效路径。
- 资源编码由服务端按主管配置并核验的字典模板分配，支持 {provider_code} 和 {sequence}，序号位宽可配且事务内并发安全；生成结果仍须符合 code_pattern。未配置模板允许先存未编码草稿，说明原因；历史编码和已发布编码保留。模板不是国家标准的替代物，不从正则猜测编码规则。
- 字典配置增加生成模板和位宽，复用主管权限；已有字典可修改生成配置，不改变已有字典的分类、校验规则或来源。草稿编码分配即登记保留，发布后不变。
- 关键字段提供持续可读说明或标签旁解释，数据项明确业务名/技术名/类型/长度/精度/小数位/敏感/可空含义；沿用既有字体、控件和固定底栏规范。
- 现有挂载基数及治理成果并存规则保持，用户本轮未要求放开普通多主挂载。

验收覆盖组织层级及停用边界、非管理员拒绝、人员调岗及会话失效、并发唯一编码/重试/历史保留、目录字段自动带入与选项及辅助说明。升级前备份，保留业务数据及两项公开演示资产。
