## 2 方案选择与四平台衔接

推荐在现有工作流中新增“目录条目”和“挂载单”，复用资源、申请、授权及审计。相比直接扩充资产数据集，它能覆盖前道原始数据；相比另建独立目录服务，它保持当前单体架构和本地部署复杂度。

| 平台 | 职责 | 与目录的关联 |
| --- | --- | --- |
| 共享交换 | 接入、政务资源编目、挂载、共享申请及交付 | 维护唯一目录条目和目录编码；原始对象、治理成果均可关联 |
| 数据治理 | 技术元数据、清洗、字段映射、质量及血缘 | 给编目和挂载提供真实字段与质量证据 |
| 数据资产 | 治理成果登记、质量门禁及资产发布 | 保留数据集标识，引用共享目录条目；不重复编目和发码 |
| 数据安全 | 分类分级、敏感策略、授权及审计 | 审核和交付共同执行安全约束 |

原始对象与治理成果是不同资源，分别编目，并以来源关系关联。数据资产已有“数据目录”入口保留为治理成果视图，详情展示关联资源编码并可跳转共享目录。当前公开首页仍仅展示已发布资产摘要；政务内部目录不会自动出现在匿名门户。

### 2.1 治理成果怎样进入共享交换

业务路径：原始资源 → 授权治理加工 → 质量核对 → 治理成果登记与资产发布 → 关联共享目录并挂载 → 申请及授权 → 共享交换交付。

治理成果保留在结果存储中；共享交换挂载的是“数据集 ID + 契约版本 + 对外交付字段映射 + 交付策略”，不把结果重新注册为外部数据源、重新采集一遍，也不复制一套归属不同的成果。数据资产提供“发起共享”操作：创建或关联唯一目录的草稿，带出元数据和质量证据，随后跳转共享交换完成编目审核与挂载，不自动启用共享。

一期沿用后端受控分页查询交付。交付服务使用受限的内部读取身份访问真实治理结果，核对生效目录、挂载、资产状态、质量及水位，再按当前用户授权投影字段和脱敏。消费方取得的是授权后的数据和交付记录，拿不到 Doris、源数据库或对象存储的账号，也不直接访问内部结果表。内部读取身份与消费方授权分别校验，不能因为服务端可以读库就跳过用户权限。

资产发布、目录发布、挂载启用分别是独立状态：资产可管理不代表可共享，目录可发现不代表可取数。普通业务数据更新在契约和策略不变时沿用有效授权，交付携带处理水位；新增敏感字段、扩大范围、更换资源或不兼容模式变化必须产生相应修订并重新审核，不随更新自动扩权。

一期不把文件下载、批量推送、消息订阅或应用凭证接入显示为已支持；这些方式后续接入相同授权门禁。当前仅承诺实际已实现的查询方式，不将现有单一治理模板宣称为任意数据集的通用结果路由；不支持的成果显示不可挂载及具体原因。

### 2.2 成果责任归属

保存数源部门、治理成果责任部门、业务责任人、编制人、受托治理人等不同身份。创建人仅是操作留痕，不是判断管理权或共享审批权的唯一依据。

一期单部门来源的治理成果默认延续该部门的数据责任。指定业务责任人维护成果和共享规则；治理人员只在获派范围内加工和执行质量任务。更换责任人必须有部门授权及审计，不能通过“复制成果”“换创建人”转移共享决定权。

跨部门受托治理需单独记录处理授权：来源资源、允许字段、加工目的、执行人、期限、是否允许形成成果及对外提供的依据。既有消费授权仅允许按目的使用，不能直接用于受托加工后对外发布。没有处理授权或共享依据的跨部门成果阻止发布和挂载，不因数据已脱敏就自动放行。

多部门融合成果须先明确牵头责任部门、各来源约束和审核依据，再进入共享审批；不能由治理人员或平台管理员单方决定。现有数据模型只支持单来源，本次不额外实现通用多方会签引擎；未具备上述依据或多来源能力时明确阻断，而非套用单部门默认规则。

涉及向第三方提供共享所得数据，须遵守原提供部门同意要求，不能以治理加工改变用途边界；依据为[《政务数据共享条例》第 25 条](https://www.stats.gov.cn/gk/tjfg/xgfxfg/202506/t20250609_1960124.html)。上述责任角色与系统授权是产品实施设计，不构成对数据法律所有权的认定。

## 3 目录内容与编码

分类采用“基础、主题、部门”业务分类，另行记录数据库/API/文件等载体，避免混为同一个分类维度。分类树和编码规则记录来源、版本，不随意生成看似正式的地方编码。

目录编辑分四组：

- 基本信息：名称、摘要、分类路径、资源编码、提供单位及其代码、责任人、更新周期、数据格式、来源关系。
- 数据项：中文业务名称、技术字段名、逻辑类型、长度或精度、可空性、说明、敏感标记。已有元数据自动带出，人工补全业务含义；敏感布尔值不能替代资源分类分级。
- 共享规则：共享属性、共享方式、使用依据、适用范围与用途、申请材料、使用期限、分类分级、开放属性及开放条件。不予共享需填写理由及法律依据。
- 审核记录：部门负责人审核依据、相关评估结论及材料引用、报送和主管审核意见、版本与发布时间。初期只存材料编号或受控引用，不新增任意文件上传服务。

内部 ID 与资源编码分别保存。草稿允许暂缺正式编码，发布时校验编码来源、结构、唯一性和必填信息；未配置已核实编码字典时阻止正式发码，不能以随机 ID 冒充国家资源编码。首次发布后编码不复用；分类调整保留身份和历史关联。原始对象名或表名不直接充当业务资源编码。

## 4 两条独立流程

### 4.1 目录编目与发布

流程：草稿 → 部门审核 → 主管审核 → 已发布。任一审核可退回，编制人员修改后重新提交；提交人可在待审时撤回。已发布目录可发起变更版本或下架。

部门审核检查业务内容和负责人审核依据，主管审核检查目录规范与发布范围。已发布版本只读；变更草稿不覆盖当前版本。新版批准后原子切换，保留差异及审核记录。目录可以在尚未挂载时发布，显示“待挂载”，不能发起数据使用申请。

### 4.2 资源挂载与启用

流程：草稿 → 校验通过 → 待审核 → 审核通过；之后单独执行“启用”，成功才成为已启用。支持退回、撤回、暂停和卸载，均记录原因。审核通过与运行可用分别展示。

挂载步骤：选择目录 → 选择已有资源 → 核对字段映射及共享范围 → 运行校验 → 提交审核 → 启用。

一期真实可挂载目标为已有原始对象与治理数据集。载体可以登记为 API 或文件，但缺少对应可用适配器时只允许编目，界面明确“暂不支持挂载”，不会生成假成功状态。

校验必须检查：目录版本及部门归属、目标资源版本、数据项映射唯一且完整、敏感策略、可交付性。原始资源检查真实归档及可读取证据；治理成果检查资产已发布、质量通过和完整性。连接测试成功不能替代上述检查。

一期每个目录只有一个生效挂载，每个资源契约只有一个生效共享目录，避免授权入口产生歧义。更换挂载先建修订，审核并重新校验后原子切换。保存历史绑定，不能修改生效映射后继续沿用旧授权。

## 5 共享与权限

目录可见、资源可用、具有数据访问授权是三种不同条件。申请入口须同时满足目录已发布、挂载已启用、共享属性允许、当前用户有申请权限。

无条件和有条件共享都沿用申请、答复、授权记录。前者不额外添加业务准入条件；后者按已公布条件审核。不予共享的目录禁用申请，服务端同样拒绝。申请补充使用依据、场景、范围、方式、时限及需求部门负责人同意记录；材料缺失进入补正流程，不能仅以缺材料直接驳回。

部门提供方继续负责共享答复，现有字段白名单、脱敏、期限和禁止自批规则保留。初期按人工审核实现，不把“无条件共享”做成匿名访问或未经负责人确认的自动批准。账号绑定部门是系统权限基础，不能把本地演示部门宣称为已核验政府机关。

复用现有角色，增加显式的部门审核人配置和平台目录审核人配置：

| 操作 | 执行人 |
| --- | --- |
| 编目与修改 | 本部门 provider |
| 部门审核 | 本部门指定 provider，且不是该版本提交人 |
| 主管审核、发布与目录下架 | 指定目录审核 admin，且不是该版本提交人或部门审核人 |
| 挂载编制、校验与启用 | 本部门 operator |
| 挂载审核 | 本部门指定 provider，且不是挂载提交人 |
| 数据使用申请 | 有 exchange 能力的消费方账号 |
| 审计查看 | auditor，保持现有审计权限边界 |

配置由现有账号管理入口维护，不能由编制人自行指定审批身份。无合适审核人时显示缺失原因并阻止提交，不以管理员身份自动代审。普通本地演示不模拟真实行政授权，审核记录明确标为测试。

### 5.1 管理、加工与使用权限分别授予

统一登录只统一身份。一次请求须同时满足“可进入平台、可执行操作、资源在授权范围内、当前状态允许”；涉及读取内容时还须满足专门的数据授权。不能仅以同部门、admin、governor 或 provider 标签推导所有数据内容可读。

| 身份 | 默认管理范围 | 数据内容权限 | 不能据此获得的权限 |
| --- | --- | --- | --- |
| 技术运维 operator | 获派数据源、采集任务及挂载运行维护 | 无默认业务取数权；诊断结果按最小必要脱敏 | 对外共享批准、原始或治理数据下载 |
| 治理人员 governor | 获派资源的规则、映射和质量任务 | 服务端作业按处理授权读取；页面样例另行受控且默认脱敏 | 成果归属转移、对外共享批准 |
| 业务责任人及指定 provider | 获派本部门目录、资产、共享条件 | 元数据可见；业务内容仍需使用或处理授权 | 本部门全部数据自动可读、自己申请自己批准 |
| 目录审核人员 | 规范审核、审核记录和必要元数据 | 不自动获得数据内容 | 用目录发布代替数据使用授权 |
| 使用方 consumer | 自己的申请、授权和交付记录 | 仅批准的资源版本、字段、用途和期限 | 修改数据、治理规则、发布、再授权或转供 |
| 安全审计 auditor | 策略与审计记录的授权范围 | 日志不包含明文敏感数据；无默认业务取数权 | 任意导出数据或代替责任部门审批 |
| 系统管理员 admin | 账号、岗位配置及平台运行管理 | 无默认全量业务内容读取权 | 自动成为业务责任人、共享审批人或消费者 |

一人可以兼任多个岗位，但兼任须明确配置，禁止自批等约束仍生效。管理员指定为目录审核人时获得的是目录审核权，不能因此批准所有资源的使用申请。特权配置及变更保留操作者、理由、前后范围和审计，不能在取数接口运行时自动补齐权限。

数据授权先沿用现有“具体用户 + 部门 + 资源契约 + 字段白名单 + 用途 + 期限”，增加目录和挂载快照。部门有一人获批，不代表全部门账号可取数；代办或人员更换不能直接复用旧账号授权。同一资源的管理人也不能在页面预览中绕过交付策略。

一期不新增通用行级权限引擎。业务要求按地区、人群等筛选行时，必须先形成并验证限定范围的独立治理成果，再按该资源授权；无法形成可靠隔离结果时拒绝挂载，不用前端过滤或人工约定代替服务端隔离。

处理授权与消费授权分别维护。处理授权失效时停止相应加工作业，并按成果共享依据复核依赖资产；仅撤销某使用方的原始数据查询授权，不会自动撤销其他部门独立合法持有的成果授权。成果自身授权撤回、挂载暂停或资产失效均直接阻止其后续交付。

### 5.2 当前实现与目标之间的必要调整

已核对：治理数据集已具有独立资源类型和授权交付入口，源于同部门对象；当前审批依赖资源 OwnerID，通用管理辅助函数存在 admin 放行，治理交付会核对质量与水位。因此不能仅增加页面和挂载记录就声称上述权限已落实。

本次实现需有针对性地补齐资源责任人及岗位范围检查，区分管理接口、加工任务和业务取数；审批不能只判断创建人或 admin，内容预览、质量失败样例和交付也不能共用宽泛管理权限。结果读取身份应限制到需要的表和只读操作，不沿用可写数据库身份承载对外交付。不全局删除管理员能力后冒充完成，而应逐个保护相关业务操作并验证兼容影响。

## 6 页面组织与尺寸

共享交换新增三个入口：

1. **资源目录**：分类树、检索和列表；按提供部门、共享属性、原始/治理成果及可用状态筛选。名称为蓝色链接，详情展示业务信息、数据项、共享条件、关联资源及可用性；操作为标准实体按钮。
2. **编目与挂载**：本部门条目，使用“目录编制 / 资源挂载”页签；编目分步表单，挂载使用步骤条并展示真实校验报告。
3. **审核工作台**：部门审核、主管审核、挂载审核三个任务视图，按权限显示。查看提交快照、版本差异、材料引用、通过及退回理由。

保留数据源、接入任务、原始数据交换、申请审批和我的授权入口。原始数据页增加关联目录和挂载状态，不能继续提供绕过目录的申请按钮。

遵循 `docs/design/interface-standard-v1.md`、`web/AGENTS.md`：平台字号与现有数据源管理一致；搜索和表单用 Ant Design 官方 large，表格、标签和行操作使用默认尺寸；区块间距 24px。不修改门户、登录页和其他平台的视觉风格。页面检查覆盖 1920×1080 与窄屏。

## 7 实施边界与现有数据

现有 `business_records`、幂等写操作、事务和审计继续复用。新增目录、目录修订、挂载和审核记录类型，通过向前兼容的显式迁移扩展类型约束，不引入工作流中间件或独立权限服务。

新增接口使用独立的资源目录与挂载路径，不把 `/datasets` 重命名或改变成另一种资源。目录修订号、物理契约版本、挂载版本分别保存；申请及新授权增加对应快照引用，旧请求结构通过原资源引用解析唯一生效挂载，响应保持既有字段兼容。

所有写操作保留会话认证、CSRF、幂等键、部门检查与审计。旧申请接口、审批发授权以及两种交付入口均接入相同目录/挂载门禁。不能只限制新页面。

目录下架、挂载暂停、资源版本或政策发生不兼容变化时，阻止新授权和后续交付。版本切换及授权检查使用一致事务锁顺序，避免并发审批绕过。已经交付的数据不能被系统物理追回；处置要求通过审计和部门流程落实。

存量资源默认标记“待补编”，不得自动伪造正式编码或审批通过。先在本地完成补编、挂载审核及新授权验证，再启用统一门禁。切换前安排维护窗口，停止共享写入并重新核对资源版本，确认迁移完整后统一开放；不发布可被用户绕过的新旧双通道。历史授权和审批记录保留可查，缺少目录/挂载快照的历史授权切换后不直接交付，需重新申请授权。此项是明确的行为变化，实施时须展示受影响条目数量。

本期不自动计算法定工作日期限，也不对外承诺完成全部条例配套制度；保留提交、补正、答复及实际交付时间，供后续工作日历和督办使用。审批流程、目录和挂载是本次验收范围，法定时限督办、争议协调及纠错子系统另行建设。

## 8 验收闭环

- 原始数据：接入并形成可读归档 → 编目双级审核发布 → 挂载校验及审核启用 → 跨部门申请与答复 → 有效授权交付；不依赖先治理。
- 治理成果：治理质量通过并资产发布 → 关联目录与独立挂载 → 申请交付；资产撤回或质量失败后禁止继续交付。
- 治理人员完成加工后无权自行批准共享；被指定的责任部门审核人可处理审批，不要求其是资源最初创建人，申请人仍不能自批。
- 运维、目录审核、安全审计或 admin 单独登录时不可直接读取业务内容；管理详情、质量样例及历史交付记录同样不泄露敏感值。
- 某用户获批后，同部门另一个账号不能复用其授权；治理成果授权不允许访问原始资源，原始资源使用授权也不能自动发布治理成果。
- 资产“发起共享”只创建关联草稿，不新增重复采集任务；交付返回的是治理结果，使用方接触不到数据库连接凭证。稳定契约下数据更新不要求反复审批，不兼容范围变化不能自动扩权。
- 目录已发布但未挂载时允许检索，禁止申请；挂载审核通过但启用失败时不得显示可用。
- 越部门编目、提交人自批、伪造审批配置、缺编码发布、不予共享申请、跳过挂载调用旧接口均被服务端拒绝。
- 退回及补正可重新提交；变更期间继续展示旧有效版本，生效后旧不兼容授权被拒绝；暂停、下架、撤权后下一次请求被拒绝。
- 审批及启用重复点击不会创建重复挂载、审核记录或授权；并发切换、失败回滚和过期校验结果有针对性测试。
- 覆盖目录字段校验、状态迁移、权限及双链路集成验证；前端构建和必要组件测试通过。真实中间件失败不能由预览数据或成功提示掩盖。

以上为已批准设计。实际实现与验证结果见 docs/validation/resource-directory/report.md；设计说明不替代运行验收证据。
