## 需求与依据

沿用项目已确认一期设计：统一登录、部门/资源岗位、字段及期限授权、敏感字段脱敏、即时撤权、失败审计和四平台闭环。原始需求V0.4的历史下载路径已失效，本设计依据仓库已确认设计与当前代码。

当前安全入口为资源权限、授权管理、审计记录、账号管理。后台已有共享与加工授权、固定资源版本、敏感布尔标记、普通账号基础掩码、数据服务凭据、交付审计。安全分级、可版本化防护策略、独立安全事件和安全水印需要补齐。

## 联动与归属

1. 共享交换登记技术资源、目录和挂载；安全侧只引用同一资源标识，不复制目录或资源状态机。
2. 分类扫描仅使用有权限的来源与有界样本；识别结果先为候选，经复核后形成安全标签。业务分类和安全分级分开管理，不把“主题信息”当安全级别。
3. 治理加工携带字段来源及敏感标签。派生、聚合或字段变化触发复核，不能因更名或类型转换自动丢失保护标记，也不能未经复核自动降级。
4. 资产目录与产品展示已批准安全标签、使用限制和适用水印要求。产品认证不产生数据访问权；每个成员仍按资源与版本检查。
5. 业务审批继续由共享交换办理；安全策略只进一步限制已有授权，不产生额外授权。加工授权不等于使用或外部共享授权。
6. 查询、文件下载、API调用、ETL逐入口检查当前有效身份、授权、共享版本和策略。批量任务在可中止检查点再次核对撤权及策略变化。
7. 风险处置或撤权反馈到交换交付、治理任务及资产状态。质量问题、契约违约与安全事件分别记录，按证据关联。
8. 跳转只携带对象标识，目标接口重新鉴权；不在URL传递凭据或原始敏感数据。

## 建议初始基线与审批分工

以下为本次设计补齐的默认方案，不冒充用户已经逐项确认的安全制度；初始模板处于草稿，预检、复核并绑定资源发布后才执行。存量资产先盘点，不因升级菜单而自动改写授权或阻断交付。

| 业务安全级别 | 建议初始保护模板 |
| --- | --- |
| 公开 | 继续执行现有平台访问、共享审核、授权与审计；标签不自动开放匿名访问 |
| 内部 | 在现有授权、字段与期限内交付，保留原有敏感掩码与审计 |
| 敏感 | 默认按批准字段脱敏；页面可见标记；文件外发要求受支持的内容标记，API/ETL要求签名交付凭据；格式不支持时须拒绝或取得限期例外 |
| 高敏 | 默认关闭批量下载、导出、API/ETL外发；受控页面查询仍需有效授权、脱敏及可见标记。特殊外发须另行审批并指定范围、期限与保护要求 |
| 未分级/待复核 | 保留当前有效保护，不按公开处理；启用严格安全发布门禁的资源，未经复核不能发布新外发版本 |

上述名称为项目业务标签，不是法定数据类别。规则识别不自动降低现有保护；发生规则/字段变化先标记待复核。

职责复用现有角色与资源职责：
- 识别规则、安全策略、水印模板由admin管理；策略/模板发布与例外由另一位admin复核，auditor保持只读核查。
- 资源标签由具有该资源manage_resource职责的负责人提出，由另一位具备该资源share_approve职责的负责人或admin复核。缺少复核人时不以自批替代。
- 业务申请及授权继续按原职责审批，不因安全平台角色扩权。
- 紧急安全冻结可由admin立即执行并记录理由、资源范围和事件；恢复须由另一位admin复核证据后批准。只冻结相关资源，不停止无关数据链路。
- 后续若需要独立安全管理员角色，应单独评估角色迁移，不在一期悄悄改变auditor含义。

## 数据水印与交付溯源

### 模块及用语

在“策略与防护”提供水印管理：模板、资源/分级适用范围、策略版本、格式能力、预检、例外审批。审计侧提供水印交付记录与溯源验证。

现有 `watermark`、`latest_watermark`、`cutoff` 是处理位点和数据范围，保持原契约。安全侧使用独立的 security watermark / delivery proof 标识与存储，绝不覆盖现有进度水位。

三类能力分别展示：
- 可见水印：页面、预览或受支持文件的可见接收方与交付标识。
- 交付溯源标识：关联主体、资源、授权与内容摘要的交付证据，可通过交付编号核对；它不等同于已嵌入数据内容的隐式水印。
- 隐式水印：须先选定载体、算法及鲁棒性验证，独立形成验收；本轮不宣称自动支持任意表格或文件。

### 按载体实施

| 场景 | 设计行为 | 能力边界 |
| --- | --- | --- |
| 页面查询/预览 | 按资源策略显示账号或代号、部门、时间与交付编号的可见标识 | 页面标记不代表下载文件、打印或复制后仍保留水印，不承诺阻止截图 |
| PDF等可嵌入文件 | 经格式适配验证后，对交付副本生成可见水印并核对输出 | 先核对加密/签名/损坏文件；不支持时不标记成功。模板能力按格式独立登记 |
| Excel | 使用现有Excel能力提供说明页或页眉页脚标记，并明确显示其实际呈现范围 | 打印页眉页脚不等于工作表网格内动态水印；不改业务单元格、公式、主键与记录数 |
| CSV/JSON/API | 通过独立交付编号、响应头或伴随清单形成签名溯源证据 | 不向现有业务记录插列、加注释或变更值；不声称旁路元数据能抵抗删除或重新保存 |
| ETL交付 | 关联实际运行、接收方、源/目标范围和交付/对账记录，保存可验证凭据 | 不向目标业务表注入水印列或扰动业务值；嵌入式数据库指纹另行验证 |

### 水印策略与证据

- 模板变量采用白名单：平台/资源名称、资源版本、接收方账号或代号、部门、用途、交付时间、交付编号；默认不含手机号、身份证号、密码或令牌，不执行模板代码或加载外部资源。
- 配置版本发布后不可原地修改；变更须创建新版本。管理员例外须显式记录依据、范围、期限和操作者，不能默认忽略必加水印。
- 在授权及脱敏完成后，针对批准的交付内容生成水印副本/清单，原始存储对象及其校验值保持不变。水印不是脱敏、加密或访问控制的替代措施。
- 每次实际交付生成不具备授权效力的随机交付编号，关联主体、部门、申请/授权、资源版本、策略/模板版本、实际输出摘要与时间。任务失败、取消及重试保留真实状态。
- 按“准备、生成中、待核验、可交付、失败、取消、传输中、已完成、传输中断、结果未知”记录事实；生成成功不等于传输完成。幂等重试引用同一交付事实，不能错配到其他接收方。
- 可验证清单采用服务端签名，并记录签名密钥版本；不使用浏览器可见秘密。该签名支持验证清单来源与完整性，不将一段可见文字当作不可伪造的证据。
- 相同数据向不同接收方交付不得误复用水印缓存。缓存键至少区分资源/内容、授权与字段范围、接收方、策略/模板版本；过期和撤权后重新校验。
- 资源要求必须嵌入水印，而载体不支持、生成失败或输出未核验时，阻止该次交付并显示原因；不静默降为仅写审计记录。明确批准的例外单独记录。
- 溯源验证仅向有权限的审计人员展示必要信息。验证结果分别为“与记录匹配、内容不同、签名无效、未找到或无法验证”；关联记录是调查线索，不直接作唯一责任认定。

### 依赖故障与交付结果

- 对要求审计的受保护交付，在返回内容或提交目标事务前持久化交付意图与授权/策略版本；无法可靠持久化时拒绝启动交付，不以仅存在内存中的待补记录继续放行。
- 要求签名凭据或内容水印的交付，在签名密钥不可用、生成失败或完整性未通过时拒绝发送；未启用水印的已有业务继续执行其原有授权及审计契约。
- 数据已经发送或目标事务提交后，若完成事件写入失败，原有持久化意图保持待核对/结果未知；不得谎称已撤回，也不得自动重复发送或提交。恢复后按实际证据补齐事实。
- 可流式或分批交付按批次保存证据并在后续批次检查撤权。跨系统提交结果未知时沿用现有ETL对账机制，签名或审计异常不构成绕过对账的理由。

## 实施顺序及验收门槛

1. 整理六组导航与安全总览，保留旧路由；补充只读安全上下文与跨平台定位。
2. 建立标签复核与策略版本，接入已有授权/交付校验，防止新增菜单形成旁路。
3. 第一批水印：页面可见标记、Excel明确范围的内容标记、签名交付清单、API响应头与ETL关联；交付记录和审计联动。文件嵌入适配逐格式通过验证后启用。
4. 接入水印要求的预检与禁止交付路径；再补充PDF等文件适配，不预先把全部上传格式标成支持。
5. 补齐访问证据后启用风险规则和处置闭环。真实行数/字节数未采集时不把请求次数解释为泄露规模。
6. 隐式水印单独做专项：明确允许的载体与业务误差，验证复制、删行、重排、改格式等操作下的提取、误报和性能；没有通过的能力显示未支持。

验收必须覆盖：自批/越权、策略收紧、撤权后继续分页及批次、跨接收方缓存、资源版本变化、格式不支持、签名或加密文件、生成超时、传输中断、幂等重试、密钥轮换、审计失败、原文件不变与业务数据不变。

## 保持的工程约束

沿用Go/Gin/GORM、React/AntD与现有会话、CSRF、幂等、审计和单层PlatformDialog；沿用已确认字号。默认不引入独立IAM或策略中间件。任何PDF/文档依赖须先验证支持范围、许可证、资源限制和部署方式，再锁定版本。

本设计当前只保存需求与边界，未修改运行实例。后续实施按功能批次验证，数据库迁移和升级分别保留备份及回退证据。
