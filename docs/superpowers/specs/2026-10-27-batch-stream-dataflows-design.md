# 批流治理与数据分层：已确认设计

用户已确认正式实施。此设计替代先前以 PostgreSQL 保存实时计算结果的未完成方案。

- PostgreSQL 只管理定义、权限、运行、发布证据。新业务数据在 Doris 中计算、保存；历史 PostgreSQL 成果保持可读。
- 有界任务从获授权的中间库/资源取得固定输入，存入 ODS，在 Doris SQL 中清洗、关联、去重、汇总；代码节点继续在隔离服务执行。
- 持续任务复用共享交换 CDC，Kafka 保存变更，Flink 按固定定义处理更新和删除，Flink 输出 Kafka 事务结果，由受控服务去除回滚事务并幂等写入 Doris 最新状态，避免把 Doris 凭据嵌入 SQL。作业提交、恢复点和授权撤销必须可核对，不自动重复提交状态不明的作业。
- 执行方案展示处理方式、输入通道、实际引擎、选择原因、结果位置和更新进度。不根据行数暗中切换引擎。
- Doris 区分 ODS、DWD、DIM、DWS、ADS。临时计算和质量隔离是内部区域，不是额外业务分层。各层不要求逐层经过。
- 模型现有 layer（概念/逻辑/物理）保留。新增 data_layer 表示仓库分层，两者不可混用。分层与部门、目录、发布权限独立。
- 原始副本保持原资源身份；治理结果有单独身份和来源血缘。单表治理保留原部门和目录；多表明确负责部门。
- 输出只有整份验证成功才登记供读取，失败中间表不能发布。稳定逻辑成果通过明确的版本绑定访问；不对未完成批次暴露“最新”。
- RustFS 保存原始归档和按需的成果快照（版本、时间、行数、校验值）；不建立双向同步，不把对象文件当实时结果。
- 不放宽任何原权限/脱敏/质量门槛，不把凭据或行数据写入运行日志。

实施约束：原地执行，不使用子代理、不提交 Git、不进行红绿仪式；保留已有工作，运行针对性的实测。

执行边界：当前持续任务接入完整单分区 CDC 历史，最多2个并发任务；脚本及不支持的流式质量规则在启动前阻断并提示批量方式。流式实时预览与经过核验发布的固定成果分开。暂停使用预先持久化的 triggerId，依据 [Flink 1.20 REST 接口](https://nightlies.apache.org/flink/flink-docs-release-1.20/docs/ops/rest_api/) 核对停止与保存点结果；不重复创建状态不明的作业。
