# 质量检查与治理衔接实施计划

**Goal:** 将质量入口收敛为检查记录、检查方案、问题整改、质量趋势，并关联真实数据流执行。

**Architecture:** 复用现有运行、质量模板、整改和成果核验接口；只调整前端业务入口和上下文传递，不改执行引擎、数据库和权限契约。保留旧地址，历史来源规则在历史成果办理处使用。

**Tech Stack:** React、TypeScript、Ant Design、Vitest。

**已批准设计:** 本对话中用户确认的质量业务路径：选择数据 → 配置检查 → 运行 → 查看问题 → 整改/清洗 → 复查 → 核验成果。

## 约束与核对重点

- 检查定义不等于已执行；成功运行不等于所有质量要求通过。运行列表刻意不返回结果，进入详情后按既有权限读取证据。
- 旧规则、模板版本、旧地址及历史成果检查继续可用；不自动发布、替换数据流引用或运行。
- 保留治理空间、数据流版本和运行编号；无权限或证据缺失显示真实错误。
- 复用现有字号、控件、单层对话框和底部操作区；检查宽屏和窄屏。
- 不包含上线操作，不改此前尚未发布的日期控件。
