# 治理实施计划

Spec: docs/superpowers/specs/2026-10-21-governance-completion-design.md

用户已授权按讨论范围实施。当前会话内执行，不另行提交，不覆盖现有未提交文件。按用户最新要求由当前代理直接实现，不使用红绿测试流程，不委派子代理；完成后运行必要的集成、类型与构建检查并记录证据。

## Task 1: 版本化治理基础与建模

新增向前兼容迁移、治理主题域/术语/标准/模型定义与版本生命周期；校验责任人、部门边界、固定版本引用、类型/码表/模型约束；提供差异与安全 DDL 预览。前端独立编辑页提供标准与术语、数据建模和主题域管理，不嵌套弹窗。文档登记新增 API。

验证：Go 纯逻辑测试覆盖错误输入、复合键/关系/精度、契约破坏性变更和 SQL 标识符；真实 PostgreSQL API 测试覆盖版本、发布、引用、幂等、跨部门、失效用户、并发与审计；前端测试覆盖创建及版本保留。运行类型检查、构建和合约校验。

## Task 2: 元数据与画像

在真实结构元数据基础上增加业务注释、标准关联、刷新历史与差异。实现受授权的采样/全量画像，持久化覆盖范围及敏感处理，复用源连接和资源授权。画像任务支持取消与超时。

验证：真实来源结构变化、精确版本引用、未授权/撤权、空表、重复与空值、采样覆盖标识、敏感样例和边界。

## Task 3: 可执行治理数据流

实现受限节点/边协议、校验及可编辑图工作区，复用读取、授权与租约；完成选择、投影、转换、码表、过滤、去重、关联、聚合、质量分支及模型输出。先纵向打通真实运行，再补齐算子；不开放尚无执行器的节点。每个运行固定定义与依赖版本，安全隔离中间数据。

验证：算子单测与多来源真实执行、类型/空值、输出唯一性、权限掩码、批次边界、内存/行数/字节限制、取消/超时/撤权回滚、重启及提交不确定性。

## Task 4: 输出契约与治理成果

新数据流产出与模型绑定，形成输出快照、质量与算子证明，自动登记成果版本。替换旧手工绑定和逐行核验流程，保留历史证据可查。接入既有发布申请及 ETL 资源选择，记录字段血缘。

验证：过滤/聚合改变行数、派生键、坏数据隔离、成果不可伪造、共享授权、契约变更和未通过质量不能发布。

## Task 5: 工作流、调度与运维

实现数据流/检查/成果登记依赖图，串并行、条件及参数、手动/定时/依赖触发、暂停/取消/失败恢复。持久化租约、节点日志与计数、调度时区与并发策略；运行运维呈现真实任务、鲜度、告警和可恢复行为。

验证：依赖失败、条件分支、重复触发、错过调度、重启恢复、撤权、并发上限、失败日志脱敏与未知提交禁止自动重发。

## Task 6: 质量整改、血缘影响与生命周期

增强规则模板、跨字段/跨表检查、质量历史；问题责任/期限/处理/复测闭环。实现可追溯字段图、上下游影响和根因查询，使用真实版本/运行证据。补齐保留、停用、下游迁移与受控清理。

验证：问题指派和越权、复测失败不关闭、版本依赖、敏感诊断、在用成果禁止清理、审计证据保留。

## Task 7: 总体验收与代码复核

完整双来源端到端验收、现有分享回归、契约、Go、前端类型/测试/构建、1920/1440/窄屏验证。由当前代理检查衔接与边界，修正后再验证；部署前备份及兼容迁移，未开启用户实际治理作业。

Review focus: 固定版本引用与停用语义；跨部门和加工权限/掩码贯穿算子；旧流程退场、历史证据保留且不冒充新契约证明；派生敏感性和行数变更的输出证明；未知提交与重试；定时重启不重复；质量问题复测及日志脱敏。

## 当前实施记录

本轮已直接接通数据流工作区与运行管理、自动成果登记发布/共享/ETL、工作流与固定间隔调度、质量整改、血缘及总览运维。2026-10-22 已完成主环境备份恢复验证、迁移至 19、应用更新及按功能分类的侧栏；43 项线上只读核验通过，未创建用户治理作业。实际验证和仍未实现的高级范围见 [治理现状与补齐记录](../../validation/governance/2026-10-21-completion.md)。高级能力仍有缺口，本计划不能整体标记为完成。
