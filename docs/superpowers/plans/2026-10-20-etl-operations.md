# ETL 运行控制与日志 Implementation Plan

> 按本会话已批准的核查建议连续执行，优先交付第一阶段。复用现有执行器、事务、权限和数据库，不引入框架，不提交 Git。

**Goal:** 任务草稿/版本/启停/复制/归档，运行取消/安全重试/未知结果核实，追加日志与站内告警。
**Architecture:** 现有 business_records 继续存任务和运行；新增独立运行控制、事件与告警表，避免控制请求被进度覆盖。取消仅在提交前生效；未知结果禁止重试直到管理员带证据核实，活跃执行器不能被人工改终态。事件按运行和尝试组织，凭据与数据值不进入日志。
**Tech Stack:** Go/Gin/GORM/PostgreSQL，React/Ant Design。
**Spec:** docs/validation/sharing-exchange/2026-10-20-review.md（优先阶段 1）

## Constraints
- 兼容现有创建/执行接口。普通账号仍需拥有任务及目标运维职责，执行前与提交前重新鉴权。
- 编辑产生新版本，旧运行保存原定义与版本；草稿、停用、归档不可执行。
- 重试只接受已确认 failed/cancelled，创建新尝试并明确重新读取当前来源；unknown 禁止直接重试。
- 日志追加写入，分页筛选、下载，默认保留90天；告警保留处置记录，人工关闭。
- 故障/超时/无进展告警为站内告警，不向外部发送消息。
