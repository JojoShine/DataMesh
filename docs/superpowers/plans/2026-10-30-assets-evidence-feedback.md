# 资产详情、更新证据与反馈衔接实施计划

**Goal:** 按用户已确认的下一轮范围完善资产说明、真实时效及使用反馈闭环。
**Architecture:** 详情从已审核目录、共享字段、固定治理运行和文件/API配置读取证据，不复制数据、不展示凭据或内部SQL。反馈独立记录使用者的问题和公开回复，治理质量管理受理，并关联现有整改单；整改仍遵守原有权限、空间和真实复测约束。
**Tech Stack:** Go/Gin/GORM/PostgreSQL、React/TypeScript/Ant Design。
**Spec:** 本轮确认的资产能力建议及三项优先建设内容。

## Constraints
不使用子代理，不采用红绿测试，不提交无关改动。资产发现只涵盖可共享数据；本人反馈仅本人可见，治理受理按部门与空间限制。记录版本与当前上游状态分开；缺少截止时间和服务时限不推测实时性或延迟。不会因反馈自动启动治理或发布结果。

## Tasks
- [x] 新增受控详情与安全证据DTO：业务说明/字段口径、责任人、固定成果质量与时间、API实际来源证据、上游运行状态、文件归档证据。
- [x] 反馈持久化及版本控制；提交、本人跟踪、治理受理与回复；确认质量问题后关联既有整改流程。
- [x] 资产详情分区呈现；在发现/已授权使用页面提交反馈，“我的资产”查看本人反馈；治理质量管理增加使用反馈页内入口。
- [x] 权限、隔离、并发、版本/时效、整改闭环及窄屏验证，更新指南，备份后部署核验。

## Review focus
未共享资产和内部配置泄漏；描述的生成时间被误认为数据截止时间；绑定API最新模式选错成果；无真实异常的用户反馈被丢弃；治理内部笔记泄漏给外部使用者；跨部门、跨空间及他人反馈越权；关联整改未复测就完成反馈。

验证与部署记录：`docs/validation/governance/2026-10-30-assets-evidence-feedback.md`。API 反馈未带实际交付快照凭证时由提供部门核实，不自动绑定最新运行。
