# 治理首页与整理发布引导实施计划

用户已明确授权按上一轮方案实施并部署主环境。采用 writing-plans / executing-plans 工作方式，由当前代理直接完成；不用子代理，不用红绿测试，不提交 Git。

目标：从治理首页在一个 Dialog 中完成选择真实来源、确认并发布结果定义、设置处理和质量检查、完整运行、质量核验和成果发布。专业页面继续可用。

约束：复用现有接口、权限和发布校验，无数据库迁移或依赖增加。单层 Dialog，标题和底栏固定，按钮右下角16px间距。遵循 interface-standard-v1 固定字号。恢复只存账号/部门隔离的对象引用，不存记录值或 API 参数；未保存表单在当前页面关闭重开时保留。

- [ ] 首页：突出整理发布、继续工作、真实近期运行及待办；其他工作入口打开带说明及明确目标的 Dialog，复杂专业工具保留。
- [ ] 引导：选择分页来源及字段，读取最新结构并采样核验；新建/复用模型；文本处理、可选去重和检查；保存/发布实际数据流，完整运行及结果计数；重查质量、核验发布，明确发布和共享区别。
- [ ] 恢复与错误：按用户/部门保存已提交对象引用；恢复时重新读取接口和权限，处理过期引用、读取失败和不兼容模型；修改配置创建版本并保留旧证据，不覆盖已发布对象；重试不重复已成功提交的阶段。
- [ ] 验证：实现后运行相关验证，覆盖单层弹窗、右下底栏、真实提交、模型复用不兼容、权限阻断、恢复和失败重试；再做类型检查、完整前端检查及构建。
- [ ] 主环境：使用现有客户来源从新入口实际跑通一次；备份并隔离恢复核对，部署仅重建服务，核验首页及静态资源、已有数据与1000行治理成果；主环境截图及操作说明。

重点审查：不能用样本通过替代全量质量；不能猜测加工授权；源敏感范围不得降低；更改来源/模型后旧运行不得充当新配置成果；跨账号不得恢复别人的工作；底栏提交保留表单校验；关闭运行窗口后可重新查询；重复点击和未知提交不能创建多份版本/运行。
