# Governance flow improvements implementation plan

**Goal:** 实施已获用户同意的流程审查建议，降低非技术用户操作成本。
**Architecture:** 复用版本化数据流、模型、现有调度与流式执行器；兼容扩展接口，保留授权和审计。布局沿用固定字号和组件，不引入依赖。
**Tech Stack:** Go/Gin/GORM/PostgreSQL，React/Ant Design，Doris/Kafka/Flink。
**Spec:** docs/validation/governance/2026-10-28-governance-flow-audit.md，用户已要求按照建议优化。

## Constraints
- 不覆盖已发布定义、不自动运行、不复制调度、不使用轮询时间冒充数据更新时间。
- 文档使用通用业务表述；无无关重构、依赖升级或用户数据重置。
- 调度按所选时区填写；夏令时不存在或歧义时刻明确处理，保存前可见未来触发预览。
- 修改计划保留 ID 和触发历史，乐观锁避免覆盖并发修改，执行目标仍须已发布且权限有效。
- 流式来源时间、处理时间、积压量必须有证据，未知就标明未知。

## Tasks
- [x] 模型回绑：从运行进入模型保留来源上下文，发布后返回原数据流，以当前版本为基准创建待复核草稿；不立即保存或运行。拒绝无效/跨空间/非发布模型；回归覆盖已有新版本和未保存修改。
- [x] 调度变更：兼容新增更新接口，事务锁和 base_version；重新校验目标和参数，保留状态/历史。前端原计划调整、变化摘要、常用周期、时间单位、时区一致和未来五次预览；DST 拒绝或明确处理。
- [x] 流式时效：来源采集/计算/Doris 分段状态和真实时间/积压证据，未知明确标记。无模式或结构重设计；相关回归。
- [x] 普通窗口布局：业务模式一个主要滚动区、精简重复说明、固定操作栏与横向步进保留；逻辑/概念模型隐藏物理字段。
- [x] 成果引导：无成果指向运行与空间核对；搜索提供可访问名称；共享阶段展示真实状态或“待核对”，不根据挂载数量推断授权。
- [x] 合并验证：Go/前端测试、契约、类型/构建；独立复核；真实数据库集成，1920/1280/窄屏。
- [x] 授权部署：备份恢复验证、保留旧镜像、必要迁移、线上资源及业务数据核对。
