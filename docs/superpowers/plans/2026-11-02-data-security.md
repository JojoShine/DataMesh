# 数据安全与水印实施计划

> 按用户后续要求：单人实施，不使用子代理，集中验证关键边界，减少逐项红绿循环。下方保留原分期计划，最新交付范围见文末执行记录。

**Goal:** 在现有四平台权限与交付链路中增加安全分组、分类分级、策略防护、水印与溯源，并保留原业务事实与接口。

**Architecture:** 业务审批、目录、加工和交付仍由原模块负责。安全模块管理版本化规则并在受保护操作中执行校验，水印使用独立交付事实，不复用CDC进度水位。先完成通用安全上下文和交付标识，再逐格式启用已验收的内容水印。

**Tech Stack:** Go/Gin/GORM、PostgreSQL、React/AntD、现有Excel库；PDF等适配通过依赖与格式验证后单独加入，不预先承诺支持。

**Spec:** `docs/superpowers/specs/2026-11-02-data-security-design.md`

## 统一约束

- 保留目录、共享、使用授权、加工授权、资源版本和现有watermark/cutoff契约；策略只收紧已有授权。
- 新增表与接口，不用安全模块直接改写其他模块事实；数据库迁移按实施时的实际版本分配编号。
- 写操作复用CSRF、幂等、审计及乐观版本；新策略默认不生效，发布前展示作用范围与交付影响。
- 策略发布与例外审批的操作者、复核人分离；第一版复用现有admin管理与auditor只读核查，涉及资源的业务批准仍按现有资源职责执行，不让审计角色自动获得取数或撤权权限。
- 元数据规则识别只生成候选标签；原有sensitive标记继续生效，不能因未识别而清除保护。
- 原文件、业务值、目标表结构与现有业务响应体保持不变；交付标识使用新增响应头或独立清单。
- 界面沿用既定字号、控件与PlatformDialog；支持1920和窄屏，菜单按角色过滤。
- 不提交用户原有未跟踪文件，不因本计划自动升级运行实例。

## 审查重点

1. 使用人、部门、字段范围或授权变化时，旧交付证据/水印缓存不得被其他主体复用。
2. 强制内容水印遇到不支持格式、加密/签名文件、超时或生成失败时，不能返回无水印内容。
3. “生成可用”与“传输完成/中断”分别记录，重试与撤权不伪造成功证据。
4. 现有CDC水位和数据响应契约不受影响；签名不包含自身内容摘要形成循环引用。
5. 标签、策略、模板或源版本变化后的交付重新校验；证据无法验证应显示原因，不强行归因。

## 批次二：标签与防护策略版本

新增后端文件 `security_classification.go`、`security_policy.go` 及对应测试；新增前端 `SecurityClassification.tsx`、`SecurityPolicies.tsx`。修改交付执行点：`delivery.go`、`table_delivery.go`、`api_resources.go`、`file_resources.go`、`etl_resource_reader.go`；所有修改局限到调用统一策略校验和展示明确结果。

接口边界：标签采用设计中的公开、内部、敏感、高敏及未分级/待复核状态；初始基线为草稿并经预检及复核后按资源发布。标签固定到资源版本/可选字段；规则识别结果为候选，人工确认才成为有效标签。策略版本分为draft、submitted、published、retired，存储资源/标签范围、主体条件、动作、保护方式和批准依据；`securityPolicyCheck` 接受当前主体、Resource、动作、字段及交付上下文，返回允许/拒绝、脱敏要求、水印要求及固定策略版本。它不创建grant。

- [ ] 测试候选标签不能解除现有敏感保护；源字段变化触发复核；来源授权不足不能执行扫描。
- [ ] 测试策略发布分离、旧版本不可改写、未发布策略不影响现有交付；公开标签不生成匿名权限，未分级不解除保护，高敏外发默认拒绝，例外须限期复核。
- [ ] 测试“已有授权但策略拒绝”仍拒绝、策略不能扩大字段或期限、分页与批次撤权后停止后续读取。
- [ ] 验证失败后实现元数据识别、复核及策略版本，先提供基于已有敏感标记的保护能力，再扩展行级条件。
- [ ] 对每种交付载体分别增加策略执行回归；未支持的行级条件或文件保护明确拒绝配置为已支持。

## 批次三：水印模板与交付证据基础

新增 `security_watermark.go`、`security_delivery_proof.go` 及对应测试；前端新增 `SecurityWatermarks.tsx`，审计侧复用原追踪入口。新增独立模板、模板版本、交付证明记录；不改进度watermark字段。

第一版接口：
- 模板管理与版本发布采用 `/api/v1/security/watermark-templates` 与 `/:id/versions`、`/:id/submit`、`/:id/approve`，管理与复核分离，auditor只读。
- `/api/v1/security/delivery-proofs` 支持有权限的审计检索；`/:id/verify` 验证提交的内容摘要和服务端记录，不能按猜测编号公开其他人的记录。
- 交付Proof包含随机delivery_id、主体/部门、Resource、授权引用、策略与模板版本、生成时间、最终内容SHA-256、签名密钥版本、生成/核验/传输状态。DTO不返回秘密密钥、凭据或原始敏感样本。
- 服务端使用单独的版本化签名密钥，保留旧记录验证能力。模板内只嵌入delivery_id等白名单内容；先生成输出字节，再计算摘要与签名，避免把最终文件摘要嵌入文件自身。

- [ ] 测试未授权交付不能生成可用Proof、模板变量越界被拒、模板不得引用秘密与执行代码；水印模板与例外不得自批。
- [ ] 测试相同接收方幂等重试、不同接收方/字段/策略隔离、密钥轮换及篡改验证；未知密钥显示无法验证。
- [ ] 测试原始文件不变，新增交付头不改现有JSON/CSV业务记录，现有cutoff仍表示原数据范围。
- [ ] 测试生成失败、超时、取消、传输中断和审计失败，不得标记交付完成；无法持久化意图或缺少必需签名时不得发送；发送后完成事件失败保留结果未知，不自动重复交付。
- [ ] 失败测试后实现页面可见标记、Excel说明页/打印范围标记、API新增交付响应头、CSV等独立清单及ETL对账关联。
- [ ] 测试要求嵌入内容水印但当前格式未支持时拒绝交付；明确批准的例外独立存储，不默认降级。

## 批次四：文件水印适配与风险闭环

文件内容水印逐格式形成独立子计划，不能仅根据上传扩展名宣称支持。先验证PDF适配的依赖许可、资源限制、中文字体、分页、加密/签名文档与输出可读性，再确定锁定版本和具体实现；同样分别验证Office与其他载体。

- [ ] 对拟支持格式形成真实输入集，记录内容呈现、文件可读性、原件不变和接收方隔离。
- [ ] 实施前先写强制水印失败关闭、签名文件拒绝及大文件资源上限测试，再实现适配器。
- [ ] 补充策略命中、实际交付行数/字节数等必要观测后，按受保护资源范围建立风险规则与处置记录；未采集的维度显示未知。
- [ ] 风险事件关联原授权/交付/任务，复核后恢复；不把治理质量整改或产品契约违约直接改成安全事件。

隐式水印作为独立专项立项：先确定载体及允许的业务变化、提取方法、误报阈值、鲁棒性输入集和性能门槛，通过后才进入正式功能支持清单。

## 首批执行记录（2026-11-02）

已实施六类安全导航及真实总览，保留账号、资源职责、使用授权和审计旧入口。分类识别仅处理字段元数据，候选须另行提交复核；负责人标签按原资源管理/共享复核职责分离，管理员维护其他规则与模板，审计员只读。配置通过统一的 `security/controls?kind=...` 管理不可改写的版本，避免为同一审批状态机创建重复实现；水印使用 `kind=watermark`。

资源安全上下文已接入目录、资产详情和数据产品成员，可定位安全工作台。资源契约换版本时，旧标签或资源策略会触发待复核门禁；存量治理成果按字段血缘继承来源保护，没有字段血缘时保守保护全部输出字段。当前治理执行或预览无法满足新增脱敏/水印要求时明确阻止；不会先丢弃保护要求再加工。

真实查询、API、文件下载及资源型ETL均重新核对授权与有效策略。普通查询/API可额外脱敏并返回可见标记与交付编号；管理员也受明确发布的保护约束。文件支持Excel交付说明页与打印页眉，拒绝带数字签名、活动内容或超出资源限制的副本生成；原文件与业务单元格不变。ETL不改目标表结构，签名摘要绑定提交前运行清单，清单随凭据保存，采用排序键的紧凑JSON表示；不冒充目标全表摘要。

新增迁移为 `000038_data_security`。运行环境可选配置 `SECURITY_WATERMARK_KEY_ID` 和 `SECURITY_WATERMARK_KEYS`（最多8个版本标识到32字节十六进制密钥的JSON映射）；水印密钥与数据源加密密钥分离。轮换时保留仍需核验的旧版本。缺少有效密钥会拒绝发布/执行必需签名的策略，不会自动生成生产密钥或改变存量策略。新代码的就绪检查包含新增安全表。

交付先持久化意图，再写出内容；完成审计与凭据状态同时提交。签名/意图审计失败不发送内容，传输失败记录中断，完成事件失败保留待核对状态；每次实际GET/调用形成独立交付事实，不缓存或自动重复发送。原CDC进度watermark及cutoff契约未改。风险规则仅主动核对已发布资源范围内失败/拒绝次数，事件保留处置历史；冻结对应资源版本，恢复须独立复核。

当前未开放：PDF内容水印、隐式水印、任意行级条件、限期例外、数据库内容指纹及实时风险推送。强制要求但载体/入口尚不支持时明确拒绝，不降级成仅写日志。直接数据源运维仍执行原有来源职责；新增资源策略按平台Resource引用生效，不声称覆盖源数据库的所有外部连接。

验证采用集中单元/隔离数据库/页面检查。已验证模板变量边界、签名与JSONB规范化、接收方隔离、未知密钥与轮换、Excel原件不变、不可自批、审计失败关闭、传输中断、撤权、ETL凭据和不可用密钥回滚。安全相关前端38项通过，桌面1920、1440及390窄屏33个布局通过（布局使用API夹具，业务验证使用真实隔离PostgreSQL与文件存储）。前端全量检查曾出现5项既有治理交互超时，已停止扩大整套循环；对应治理文件33项单独重跑全部通过，安全与操作指南8项也通过（其中安全用例与前述38项有重复）。Go内部测试及vet、前端构建、19项契约测试和OpenAPI校验通过。负责人标签、版本门禁与字段更名继承检查在真实隔离PostgreSQL通过。额外的治理成果端到端检查报Doris 1105；只读状态核对确认当前Doris计算节点Alive=false，因此该扩展检查未通过，未将其解释为已完成真实Doris加工验证。
