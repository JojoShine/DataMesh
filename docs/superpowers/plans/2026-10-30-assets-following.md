# 资产收藏、关注与站内提醒实施计划

**Goal:** 完善可共享资产持续使用链路，支持收藏、关注共享变化和授权到期提醒。
**Architecture:** 复用审核共享快照与本人授权；独立保存本人收藏/关注偏好及站内提醒。进入或手动刷新时显式核对已关注资源，不声称后台实时推送或完整变更审计。
**Tech Stack:** Go/GORM/PostgreSQL、React/Ant Design，无新依赖。
**Spec:** 本轮用户要求继续拓展资产业务，延续只处理可共享资产的已确认边界。

## 选择与约束
采用轻量的站内核对，避免为首版引入消息队列消费者、邮件服务及新调度。用户偏好优先：直接推进合理范围，不请求常规确认；不使用子代理、不做红绿测试、不提交无关改动。
收藏与关注分开，均不生成授权。不可用资源保留用户曾见名称，但不透露未共享的新版本信息。个人数据包括管理员也按本人限定。关注取消不删除历史提醒。到期提醒不延长授权；重新申请仍复用原审批。

## Tasks
- [x] 新增偏好及提醒表与服务；受控创建/更新、个人分页、显式状态核对、去重及已读。
- [x] 资产详情操作、我的收藏/关注、我的提醒入口；共享不可用时引导重新发现，无重复申请旁路。
- [x] 验证隔离、共享变更/恢复、去重、到期、取消关注与前端交互；指南与宽窄屏检查。
- [x] 生产构建、备份恢复、迁移上线及受控只读核验。

Ruling: 每人最多保留 100 份有效收藏/关注，核对操作按用户串行、单次事务完成，避免无界查询与重复提醒；此上限在指南及错误消息中明确说明。暂不增加邮件或后台推送。
