# 元数据自动维护实施计划

沿用已确认的元数据核查方案，由当前会话直接实施，不使用子代理或红绿测试。首批完成自动维护与变更确认闭环，文件/API 保留真实能力说明，不把登记契约冒充内容探测。

- [x] 接入资源自动发现：优先资源负责人，其次本部门已获该资源治理权限的有效治理人员；无授权时等待，不能借自动任务扩大权限。
- [x] 每日默认采集，可在单层 dialog 调整周期或暂停；执行前重新核验人员、部门、授权、资源状态。失败退避重试，保留历史及错误码。
- [x] 复用真实库表读取及契约快照；无变化不增加结构版本。技术结构和人工业务注释独立维护，不自动改写交换契约。
- [x] 展示最近成功、下一次、失败、过期、来源不可见等状态；结构变化生成待确认项，处理前展示影响范围并要求说明。
- [x] 补充数据库字段注释与默认值；元数据单表读取不受前1000张表列表限制，元数据字段限制与加工限制分开。
- [x] 元数据列表、详情、采集设置、历史和变更处理复用现有组件；24px分区间距、单层dialog、右下固定按钮、字段悬浮说明、业务例子。
- [x] 补充API契约、迁移、真实PostgreSQL集成验证、前端交互验证、构建及桌面/窄屏查看。
- [x] 主环境备份恢复验证，兼容迁移、部署及严格HTTPS核验；自动采集新增记录与原业务数据分别核验。

后续独立深化项：文件结构推断、OpenAPI导入、外部SQL/视图血缘、外键索引完整目录。首批不伪造这些能力。
