# 数据服务与业务初始化 Implementation Plan

> 使用 executing-plans 在当前会话直接完成。用户禁止子代理并要求减少重复测试，无额外确认或 Git 提交。

**Goal:** SQL 数据服务可正常创建，六类业务初始化可复现、可迁移。
**Architecture:** 延续 Go 白名单 SQL 编译与受控交付；React 复用 DirectoryEditor；Python 确定性生成源 PostgreSQL 表，通过真实平台 API 注册、治理及发布。
**Tech Stack:** Go、React/Ant Design、Python 标准库、PostgreSQL、Doris。
**Spec:** docs/superpowers/specs/2026-11-04-business-scenarios-design.md

## Global Constraints
不使用真实个人敏感资料，不编造国家编码规范，不改权限门禁；既有非初始化数据保留；初始化可重入和迁移；无新依赖。

## Review Focus
- 服务 SQL 常见写法不得变成可执行任意 SQL 的入口。
- 同目录接口只使用原目录已审核字段，源共享失效时阻断接口。
- 初始化同名但未知或已人工修改的表不得被覆盖。
- 跨场景主键、关系和业务状态一致。
- 重试不重复创建目录、任务、资产或增加记录；迁移不依赖旧机器随机 ID。
