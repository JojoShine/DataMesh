# 组织人员与目录表单 Implementation Plan

> 使用 superpowers:executing-plans 在本会话直接执行；用户明确禁止子代理并要求减少红绿测试，无额外确认、提交或分支操作。

**Goal:** 提供组织人员管理，并让目录表单使用真实组织资料和受控编码规则。
**Architecture:** Go/GORM 延续现有 mutate 事务和身份验证；增量迁移组织单位/编码序号与预留表。React/Ant Design 复用 PlatformDialog、账号页与导航。
**Tech Stack:** Go、PostgreSQL、React、TypeScript、Ant Design。
**Spec:** docs/superpowers/specs/2026-11-04-organization-directory-design.md

## Global Constraints
保持历史 department_id、资源与审批归属、已发布目录和编码；不编造单位代码或国家标准；不增加依赖；维持既有字体和控件规范。禁止普通账号管理组织人员。

## Review Focus
- 调岗及角色修改必须清除会话，调岗撤销旧范围授权。
- 单位停用不能留下有效人员或子部门。
- 序号并发唯一，重复请求按幂等复用；不能覆盖历史编码。
- 管理员不能在当前会话取消自身管理能力或停用自身。
- 未配置组织代码/模板时明确提示，保存草稿仍可用。
