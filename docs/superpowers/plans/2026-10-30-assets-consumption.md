# 可共享资产发现、申请和使用 Implementation Plan

**Goal:** 完善资产侧发现、申请、使用闭环，不纳入尚未共享的内部台账。
**Architecture:** 复用已审核目录、挂载、申请、授权和交付服务；资产读取只提供已共享目录和本人记录。治理提供质量与来源证据。原审批职责、共享状态校验和匿名门户边界不变。
**Tech Stack:** Go/Gin/GORM/PostgreSQL、React/TypeScript/Ant Design。
**Spec:** 用户本轮确认：暂不需要内部资产台账，先完善可共享资产发现、申请和使用。

## Constraints
不使用子代理，不走红绿测试，不自动提交；不新增依赖或数据库表；不引入按调用者的行级权限；保留旧路由兼容性。只将消费操作开放给资产平台，目录维护、审核、资源登记仍要求共享交换权限。

## Tasks
- [x] 后端新增资产只读入口；限定审核共享目录、本人申请及本人授权；消费端认证支持资产用户，保留全部授权校验。
- [x] 资产发现页面复用目录详情和申请表，补充真实字段、质量与来源信息；我的申请、我的资产复用现有交互并去掉管理命令。
- [x] 验证资产单平台账号隔离、审批与使用衔接、下架/到期限制、前端菜单与响应布局；更新指南。

## Review focus
内部草稿不可发现；同部门/管理员的“我的”列表也不扩大范围；资产账号不能审批/维护；资源或版本变化不能继续交付；无治理证据时不宣称已通过质量检查。
