# 四平台职责和共同标识

共享交换位于前道，负责三库 CDC/API 接入、原始交换和归档，并向治理提供原始事件；治理后的成果也通过共享交换申请、授权和交付。数据治理负责元数据、清洗转换、规则质量和血缘。数据资产负责目录、负责人、版本发布与下架。数据安全负责策略和审计，保护所有环节。

| 业务事实 | 唯一负责模块 | 其他模块如何使用 |
| --- | --- | --- |
| 来源、采集对象 | source | 引用 source_id、object_id |
| 接入任务、运行、原始事件范围 | ingestion | 引用 task_id、run_id、event_id 及 Kafka 范围 |
| 原始归档清单及补偿范围 | storage | 引用清单和水位，不直接读取存储凭据 |
| 技术模式、规则、质量和血缘 | governance | 引用 schema_version、规则版本及治理数据集标识 |
| 目录、业务版本、发布记录 | catalog | 引用 dataset_id、contract_version、发布记录 |
| 申请、审批、授权、查询交付 | exchange | 授权明确 raw_object 或 governed_dataset、资源与字段范围 |
| 共享账号、部门和平台能力 | identity | 每请求校验当前账号和平台能力 |
| 受控审计记录 | audit | 追加写入；业务账号无修改与删除权限 |

原始对象和治理数据集通过血缘关联，不视为同一授权资源。治理权限不自动授予原始层权限。原始接入已可靠接收、治理完成、Doris 可查询、归档完整分别跟踪；治理失败不改写已完成的原始接收事实。

治理成果交付同时校验发布、质量、处理与归档完整性及授权。原始交换按来源许可、原始交换契约、交付范围和安全策略判断，数据明确标记为未经治理。交换协议不向用户泄露 Kafka、数据库或对象存储管理账号。

统一登录为本地共享账号和会话；四平台同源复用 Cookie，能力名固定为 exchange、governance、assets、security。平台访问能力不替代数据集授权，也不代表可访问原始数据。
