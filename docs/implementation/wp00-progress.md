# WP-00 执行记录

依据：`docs/superpowers/plans/2026-10-15-wp00-contracts-docker-plan.md`。结果和未覆盖项统一见 `docs/validation/wp00/report.md`。

## 用户决定

- 不使用子代理；按功能批次集中验证，不逐项红绿循环。
- 当前目录无 Git 仓库，直接建设，不创建工作树或提交。
- 共享交换承担前道原始数据接入及交换，也承担后道治理成果的申请授权交付。
- 没有外部身份系统，使用 Go 与平台 PostgreSQL 维护一套共享账号和会话；不引入 Keycloak/OIDC。

## 已落地

- 四平台职责、资源授权分层、事件、状态、组件适配与 OpenAPI 契约；原始与治理资源不跨层继承授权。
- 原生 ARM64 Docker 镜像与插件精确锁定；独立网络、命名卷、平台/源库及本机端口；预检拒绝冲突、缺失组件和资源不足。
- Kafka、Debezium、Flink、Doris、RustFS 与 PostgreSQL/MySQL/Oracle 专用样例。
- 轻量共享登录后台，独立迁移，最小权限应用账号、审计保护、禁用清理会话和并发登录串行化。
- 三库最终版本快照及快照后增删改，Flink 转换入 Doris、有界原始归档与清单校验、保存点恢复和隔离数据库备份恢复。
- 运维入口和文档；身份测试使用临时数据库，结束后清理。

## 实施中修正

- Docker Engine 可拉取固定镜像；没有因宿主部分 DNS 请求失败修改系统代理。
- MySQL 样例客户端显式使用 utf8mb4，避免中文在初始化和联调时被错误编码。
- Flink 状态卷按实际 JVM uid 9999 初始化，只修改专用卷，不放宽为全员可写；SQL 客户端不保存历史，诊断日志脱敏。
- Doris 适配镜像认证行为并保留密码检查；根据真实进程用量调整本项目限额，没有关闭内存保护。
- Oracle 使用最终版本支持的 LogMiner 与原生镜像；三库快照均核实最终 Debezium 版本。
- 登录发会话与禁用清理通过账号行锁协调，避免重新启用时复活并发残留会话。
