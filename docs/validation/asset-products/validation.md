# 数据资产后台能力验证 · 2026-11-02

## 实现

- 数据产品：最多10个已共享资源的固定版本组合；产品草稿、发布版及个人检查记录分离；资源仍分别申请使用授权。
- 版本审批：维护者新建草稿、提交，另一位本部门治理人员或管理员审核；包括管理员在内均不能审核本人产品。编辑草稿不会替换旧发布版。
- 契约：对固定字段、类型、保护标识、成果生成时效、当次运行隔离比例主动核验。数据缺失显示未知；已知共享不可用或违约显示违约。结果保存到个人历史，相同发布版与相同证据的违约提醒去重。
- 认证与生命周期：人工审查有效期最长366天；认证过期显示过期；弃用可指定替代产品，停用后移出消费视图，不撤销原资源授权。待审草稿不能直接弃用，被退回的草稿需先编辑保存新版本再提交。
- 业务语义与安全关联：引用有权读取的已发布治理业务域/术语，消费侧仅查看产品审核过的名称与说明；产品关联资源进入原资产发现与证据页，不公开内部来源SQL、凭据或未共享节点。
- 运营：当前账号成功查询、下载和API交付审计按1至90天UTC时间窗口汇总；不将请求次数当行数、字节数或人数；成本与价值为null。

## 审查与回归记录

独立审查发现：API共享状态仍有效，但其内部来源已不可交付时，证据接口会返回Notice与空错误，产品审批原先误将其视为可认证。先用真实数据库测试复现“返回200、应返回409”，再修改快照校验拒绝非空Notice；最终5项数据库回归包含此修复并通过。另补充“停用产品不再提供历史待审版本的审批入口”用例，先观察失败，再收紧返回的操作权限。

初次业务语义测试的版本fixture缺失created_by外键，已补齐真实创建人。并发验证时曾出现治理导航15秒超时，随后导航8项独立复跑通过。初次带竞态检测的隔离运行在高负载下登录503，未将其计作通过。随后使用项目标准脚本对相同5个场景再次执行 `-race -count=1`，全部通过（209.147秒），临时数据库按脚本清理。
