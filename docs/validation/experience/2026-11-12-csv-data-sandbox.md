# CSV 数据沙箱与轻量治理验收

2026-11-12，18443 主环境升级至迁移 `000048`。统一菜单为“处理数据 → 轻量治理”，页面内以“可视化处理”和“SQL 数据沙箱”切换；原 `/platform/governance/sandbox` 深链继续打开 SQL 页签，两个处理方式均可传递已选文件。复用现有 Go 服务、PostgreSQL、Doris 和 RustFS，无新增计算集群，Docker 保持已批准的 12 GiB。

## 使用闭环

1. 创建私人沙箱，上传 CSV 并命名逻辑表；也可从轻量治理选择已有文件进入沙箱。
2. 使用 MySQL 兼容的单条 `SELECT`，支持 `WITH`、关联、过滤、转换和分组汇总。整数转换使用 `CAST(字段 AS SIGNED)`，小数使用 `CAST(字段 AS DECIMAL(30,6))`。
3. 运行预览，或输入新的表名保存完整查询结果为逻辑表。
4. 下载 CSV，或将逻辑表送入轻量治理。后者创建独立文件，关闭原沙箱后仍可读取，再由用户命名并保存治理单元。

原始 CSV 按文本导入，保留前导零；SQL 转换后保留大整数与小数精度。页面显示 `NULL`；CSV 下载的 NULL 编码为空字段，轻量治理交接通过独立的类型化数据副本区分 NULL 与空串。

每份上传最多 20 MiB、100 列、100,000 行，每个沙箱最多 8 张表、80 MiB 总存储；每位使用者最多 4 个有效沙箱。预览最多 1,000 行、4 MiB。普通账号的私人沙箱保留 7 天，公开完整体验按本次登录隔离并保留 24 小时，重新登录不会获得上次登录的私人数据。

## 防护与恢复

SQL 通过语法树解析、函数白名单和沙箱表映射后执行；阻断多语句、DDL/DML、跨库访问、外部文件及网络读取。Doris 专用读写身份仅获 `datamesh_sandbox` 权限，实际跨主业务库读取被拒绝。

CSV、结果和交接文件使用现有运行密钥加密保存。后台任务使用数据库租约、幂等操作、版本和取消检查；无法确认的写入先核对固定标签及内容，不盲目重放。关闭与到期只清理登记归属该沙箱的对象。交接后的轻量文件继续独立保留并受原有授权控制。

迁移前已备份，在现有 PostgreSQL 内的独立临时库恢复并核对 22 组保护数据；空沙箱结构的迁移升级、降级通过。正式迁移前后核对原数据，最终再次确认六组共 579 条原始记录未改变。备份和部署清单仅存于受保护的 `.local/deployments/`。有数据时降级会拒绝删除沙箱表，不能用结构降级代替数据恢复。
