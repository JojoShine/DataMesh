# 数据共享交换补齐验收（2026-10-21）

状态：本批实现、独立审查修复、数据库回归、六轮百万行验收及本地发布均完成。

## 本批功能

- 独立远程 CDC：PostgreSQL、MySQL、Oracle 可从真实库表登记采集草稿，检查完整条件，再启动、暂停、恢复和核对。每个任务独立使用连接器、主题及位点。Oracle 明确区分 CDB/PDB，并诊断专用账号、表日志及工作表空间条件。
- 原始归档：按分区与位点验证首次快照，分块存放，验证摘要、连续范围及实际对象后才发布。事件按主键重建加密快照；不完整、损坏、缺段或不支持的部分行明确阻断。
- 授权批量交换：PG/MySQL 库表、完整原始快照及已核验治理结果流式读取，默认200万行/1GiB/30分钟。Oracle 查询、Excel 和旧归档保留兼容的小容量边界，页面按实际资源显示容量。
- 治理结果：显式绑定实际 PG/MySQL 结果表、原始归档、契约及规则版本。完整范围质量检查及逐键结果验证通过后才能发布、交换；不代替治理计算。
- 交付核对：按目标数据库实际主键语义记录本轮最终期望，主键加密、值摘要使用每轮密钥。提交前读取全部最终键和映射字段，不一致回滚；提交后单独只读对账，可独立重新核对、导出和查看历史。
- 业务验收：实际收方引用最新报告提交接收/驳回回执。管理员代办记录原因和实际操作人，版本冲突要求重新查看；不覆盖旧回执。未知提交结果须先核实。
- 生命周期：保留原有任务版本、启停、归档、排队、取消、安全重试、未知事务人工核实、日志及站内告警。页面把交换结果、技术对账和业务验收分别展示。

## 使用顺序

1. 管理员在“数据源管理 → 可信数据源白名单”配置数据库类型、真实地址、端口和数据库/服务名。登记数据源时先“测试连接”，通过后保存。
2. 持续采集进入“CDC 接入任务”：选择源和真实表，PG填写由DBA配置的发布名；Oracle填写目标PDB后刷新库表。点击“检查CDC条件”，按每项给出的负责人、当前值、要求、步骤和只读SQL处理。SQL连接成功不代表完整采集条件满足。
3. 保存采集草稿后从列表启动。先核对首次快照，再“归档当前范围”。任务详情显示已验证的归档清单和分区范围；暂停/恢复保持已有位点。
4. 治理人员在成果中绑定已生成的实际结果表，选择固定原始归档及支持的转换，等待完整质量和结果核验通过后发布。
5. 使用方在“ETL 数据交换”选择已获授权的原始数据或治理数据、目标表和转换规则。运行后在同一窗口查看交换结果、对账与验收、日志与处理；确认提交及最新对账通过后填写接收回执。缺少授权仍按原申请审批流程处理。

## 权限与异常控制

运行固定资源契约、目录及挂载修订、所选授权和脱敏策略，在批次与提交前复查。中途撤权、身份范围、共享版本或脱敏依据变化时回滚。兼容适配器同样拒绝需要脱敏的源主键和目标主键。提交后核对、报告与回执继续检查实际收方当前权限。

目标保持整轮单事务，不传播来源删除。提交结果不明确时保留 unknown，不自动重跑或签发接收回执。原始快照默认24小时、交付索引默认7天，活动及 unknown 运行保护证据；清理加密正文不删除报告和回执。

## 独立审查与修复

一次独立、只读的全量审查确认6项问题，均以复现测试与回归修复：

1. 运行中替换共享版本及授权后，旧脱敏依据仍能继续交付。
2. 小容量兼容适配器遗漏脱敏主键保护，可能将不同键覆盖为一条。
3. CDC 外部控制期间发布新归档，旧整段任务正文覆盖了归档引用。
4. PG 使用最后一个空闲复制槽后，旧容量检查会误停自己的任务。
5. 旧样例保护只比较数据库名称，误拒绝不同实例的同名库表。
6. 新 CDC 任务已有验证归档时，接口仍显示“待归档”。

修复回归195.556秒，开启 Go race；覆盖实际交错写入、槽满时的保留/恢复、新任务阻断、物理实例区别、兼容键保护、共享规则变更回滚、延迟触发器、UUID/char最终键、提交后独立重核、回执版本及保留期。审查未提出其他已确认的严重或一般问题；最终规模验收单独执行。

规模测试发现两种查询计划退化：目标增长后复用空表计划，以及重复同步时统计信息暂为零导致全索引扫描。PostgreSQL 查询改为按主键关联的有界查询，每次只选择映射字段，保留重复结果检测；目标事务在服务支持时按批重新规划，不支持该设置时保持服务器原有计划设置。本次实际验证 PostgreSQL 17，不能据此扩大旧版本兼容结论。50万行增长表与2万行过期统计分别用真实扫描工作量上限复现，修复后的最终规模结果另列。

## 百万行结论

六轮均完成普通账号授权、脱敏、全部最终键和值核对、零差异提交后报告及实际收方回执。三次空目标同步204.401–242.237秒，中位数226.225秒；已有主键更新194.057秒；原始冷快照373.963秒（含110.654秒重建）；已核验治理结果249.808秒，前置完整校验另334.568秒。

详细阶段、内存、环境、原始结果与测量限制见[百万行验收](../etl/authorized-million-row.md)。目标写入本身约11.5–17.6秒，主要开销为交付索引及两次完整核对；不能将写入时间当成交付总时间。测试报告阶段计时的指针复用问题已用28.10秒失败演练复现、值复制修复后23.06秒通过；正式测试经过时间与正确性不受影响，阶段数据从持久化运行记录独立导出。

## 执行决定与范围

- 当前分支无提交，原有文件全为未跟踪状态：在原工作区修改，保留基线和验证记录，不创建无依据的 Git 历史或覆盖用户改动。
- 新 CDC 使用保留类型信息的事件信封，旧作业保持兼容；真实三库采集及归档分别验证。
- Oracle 每个任务使用独立 LogMiner 工作表，避免两任务共用工作表冲突；连接白名单分别覆盖登记的 CDB 和目标 PDB。
- 治理结果必须显式绑定批准的归档与实际物化表，不将任意查询结果视为治理成果。归档范围或规则改变需重新核验。

- 定时调度、自动退避重试、增量 ETL、断点续传、HA、任意治理计算、Oracle直接目标写入及来源删除传播不在本批范围。
