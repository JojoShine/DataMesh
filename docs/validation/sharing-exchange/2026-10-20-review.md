# 共享交换能力核查（2026-10-20）

依据：当前仓库实际路由、执行代码、页面和测试；文档仅作辅助。没有对真实客户数据库进行生产负载或故障演练。以下“建议”不是已经完成的能力。

## 目录入口

资源目录与目录注册都读取 `/resource-directories`，并都提供新增目录、维护目录与挂载入口。前者使用已发布修订用于发现/申请；后者通过 `scope=mine` 查询职责范围内草稿、修订和审核状态。职责不同，但无需两个侧栏菜单。

本次合并为唯一的“资源目录”菜单：页内“已发布目录 / 目录维护”视图复用原实现。使用方仍可发现并申请；provider/operator/admin 可进入维护视图，具体操作继续由既有岗位与后端权限判断。新增、挂载和资产发起共享统一进入目录维护。旧 workspace/mounts 地址兼容，已发布修订与未审核草稿的隔离保持不变。

依据：`web/src/pages/ResourceDirectory.tsx`、`DirectoryWorkspace.tsx`、`DirectoryCenter.tsx`、`web/src/app/App.tsx`、`internal/modules/workflow/resource_directory.go`。

## ETL：有基本执行闭环，尚无完整生命周期

| 领域 | 实际已有 | 缺口 |
| --- | --- | --- |
| 任务定义 | 创建并校验任务；不可变定义；原始/治理资源或直接库表；字段转换 | 草稿编辑、配置版本、复制、启用/停用、归档；没有完整任务状态流转 |
| 运行状态 | queued、extracting、loading、committing、succeeded、failed、unknown；读取/提交行数；100 行批次结果 | 取消、受控重试、尝试编号、独立开始/结束时间与阶段耗时；失败后“执行”是一次新的运行，并不保证读取同一输入范围 |
| 事务安全 | 主键更新/插入，单事务；失败回滚；同任务禁止并发；CSRF/请求幂等；提交前再鉴权 | 跨任务目标冲突控制、同一输入批次的交付去重及完整核对闭环 |
| 调度及可靠性 | 手工触发；进程内执行；共享并发限额 2；5 分钟上限 | 持久执行队列、优先级、心跳/租约、定时/事件触发、依赖编排与安全补跑；满额直接失败，不是排队等待 |
| 重启和未知结果 | 服务启动将未完成 ETL 运行标为 unknown，阻止直接重跑 | 页面/API 无核实结果、证据记录和关闭 unknown 的操作；状态写入或进程故障可能需要人工查库；多实例前需用执行租约隔离，不能每个实例启动都全局重置运行 |
| 范围及连接 | 直接来源和写入目标支持 PostgreSQL/MySQL；平台表资源按适配器读取；单次 10,000 行/20 MiB；少量文本转换 | 大批量分片、可恢复检查点、运行级输入水位、增量/删除传播、结构漂移处理；Oracle 直接 ETL 来源与目标不支持，连接测试成功不代表可用于所有任务 |

依据：`internal/modules/workflow/etl.go`、`etl_resources.go`、`http.go:New`、`web/src/pages/ETL.tsx`。

## 日志：运行摘要、审计和技术日志尚未统一

- 已有运行记录：运行状态、最新 message、读取/提交数量、字段映射和批次范围。
- 最新 message 每次更新被覆盖，没有追加式阶段事件历史。批次记录只有行范围和事务状态，没有完整带时间的处理日志。
- 已有审计：创建/触发请求及拒绝访问记录，可按对象、动作和 trace_id 查找。运行请求被接受，不等于异步 ETL 最终交付成功；最终成功/失败尚未形成完整运行结果审计链。
- 已有服务技术日志：JSON 输出到标准输出，部分基础设施错误带 run_id；并非每次正常阶段、连接/转换/SQL 失败都有可检索的诊断事件。
- 缺少任务/运行/尝试级日志接口及页面、级别与阶段筛选、错误码与安全脱敏原因、实时追踪、导出、保留期限和访问策略。部署文件也没有显式配置集中采集与日志轮转策略；宿主默认配置不在本次结论范围内。

建议将运行记录、运行事件、操作审计分开管理并关联：task_id、task_version、run_id、attempt、trace_id、stage、timestamp、level、error_code。日志记录诊断上下文，不记录密码或原始数据值。

依据：`etl.go:ETLRun/persist/executeETL`、`http.go:audit/mutatePath`、`cmd/server/main.go`、`web/src/pages/Security.tsx`、`compose.yaml`。

## 共享交换的其他缺口

| 领域 | 已有基础 | 建议补齐 |
| --- | --- | --- |
| 资源/授权 | 目录与挂载修订审核、暂停/下架、申请补正、字段/期限/部门授权、撤权与脱敏 | 用途与交付范围的持续核对、明确的行级范围策略和下游使用/转供约束；过期本身已有拦截，不应重复实现 |
| CDC 与恢复 | 三库样例连接器、暂停/恢复/状态核对，归档校验；旧版本重放明确拒绝 | 任意远程源连接器的配置、隔离与发布，位点监测、日志保留/DDL 异常处理、持续归档、断点补偿和经过验证的重放；当前控制绑定 datamesh-{数据库类型} 的样例连接器 |
| 质量及交付验收 | 治理成果质量门禁；文件/归档校验；库表事务提交记录 | ETL 通用写前/写后质量规则、源目标数量与摘要核对、对账报告和接收回执；目标提交成功不自动代表业务验收通过 |
| 可观测性 | 页面运行轮询、基础健康检查 | 运行/连接器级成功率、吞吐、延迟、数据新鲜度、积压、失败/长时间无进展告警和告警处理记录 |
| 血缘及契约 | 治理数据集已有来源对象/规则/归档的表级关系；ETL 保存映射与资源版本 | ETL 运行级及字段级血缘、输入水位、输出批次、契约变更影响分析；不能将已有基础表级血缘描述成“完全没有血缘” |
| 接入成熟度 | PG/MySQL/Oracle 连接测试与库表发现；数据库、Excel 导入、文件及 API 挂载 | 远程 CDC、Oracle 直接 ETL 来源/目标、通用治理计算和大数据量处理分别验收；还需统一 TLS/证书及凭据轮换等连接配置，不能把一种连接检查结果泛化为全链路支持 |

## 建议实施顺序与验收

1. **优先：ETL 生命周期 + 运行日志。** 先支持任务启停/版本、运行取消、失败重试与 unknown 核实；取消在提交前回滚，提交阶段或结果不明时进入核实，不把未知事务直接标成功/失败。日志应能串起发起人、配置版本、阶段、异常及最终交付结果。
2. **优先：执行可靠性 + 告警。** 持久队列、worker 心跳/租约、重启恢复、超时与失败告警；压测并核对并发任务和同目标冲突。每次运行必须能追踪到终态，无法确认时保留 unknown 及处理责任人。
3. **随后：调度与增量。** 定时/事件触发、依赖、重试退避与次数、输入水位/补跑批次；验收重复请求、重复调度及恢复后不产生重复交付。
4. **随后：验收对账与血缘。** 源目标数量/摘要、质量规则、交付回执、运行与字段级关系、契约变更影响；大批量与各数据库/载体独立验收。

这些能力可以逐步补齐，是否引入外部调度/日志产品应由规模与运维条件决定，本次未引入新框架或依赖。
