## 可以照着做的步骤

1. 数据治理 → 元数据管理，找到 `public.customers`，按“数据库表”及资源编号区分同名采集对象。打开并点击“读取最新结构”。本次选择 `32420854dbeb98975f984ca223ae3805`，观察结果与当前契约匹配。
2. 在同一弹窗的数据剖析区域选择全量、id/name/amount，执行后确认1000行，id无空值且不重复、金额无空值。
3. 数据建模 → 新建模型，选择逻辑层，填写责任人与下列字段。保存草稿后打开详情发布；本次名称为“客户基础标准模型（主环境实跑）”。

| 技术字段 | 类型 | 精度/小数位 | 可空 | 主键 | 敏感 |
| --- | --- | --- | --- | --- | --- |
| id | 整数 | 0/0 | 否 | 是 | 否 |
| name | 文本 | 0/0 | 是 | 否 | 是 |
| amount | 精确小数 | 20/6 | 是 | 否 | 否 |

模型鲜度3600秒、允许不合格比例0。字段名、类型及精度需按实际处理结果填写，主键不能可空。

4. 数据流开发 → 新建数据流。选中来源节点，按类型和编号选择上述数据库表，只选id/name/amount，取消其他字段。
5. 选中来源节点 → 添加文本转换，name选择去除首尾空白；id、amount保持原值。
6. 选中文本转换节点 → 添加质量分流。添加五项检查，均勾选“失败进入隔离分支”：id必填、id唯一业务主键、name必填、amount必填、amount数值范围下限0。
7. 点击模型输出节点，确认输入为质量节点的合格分支，选择已发布模型版本。保存草稿、发布后点击运行已发布版本。本次名称为“客户基础清洗与质量校验（主环境实跑）”。
8. 修订节点、连线或模型引用后，发布新版本前填写迁移说明。本次第2版说明保留v1及其成果，现有下游固定旧版本，后续逐项核验切换。
9. 等待运行成功，在运行详情核对四节点各处理1000行、隔离0行，并记下成果编号。
10. 质量检查 → 按成果编号定位 → 运行检查打开Dialog → 在Dialog内运行检查，确认门禁通过、输出模型版本2、通过1000行、阻断0行。
11. 数据资产 → 发布管理，按成果编号打开详情，核对字段敏感标记、质量和完整性，点击“核验并发布”。普通数据流成果走此入口；只有工作流待审批任务才走“治理成果发布审批”。
12. 查看发布状态已发布。需要后续共享时再发起共享编目、维护目录挂接并办理授权。

## 实跑发现及修复

- 历史采集对象契约缺少真实表中的updated_at字段，实际执行被SOURCE_SCHEMA_CHANGED阻断。通过元数据观察确认差异，保留旧契约及告警，使用主环境已有、结构匹配的数据库表资源完成本流程；未自动扩大既有契约或授权。
- 原来源下拉框对同名对象只显示名称和版本，无法区分资源。现增加资源类型、编号摘要，选中后展示完整编号；元数据列表也显示编号。
- 明确金额精度、小数位和敏感范围的模型配置要求，增加版本切换迁移说明提示。
- 普通数据流成果的直接发布与工作流审批需要不同说明。增加独立“治理成果核验与发布”指南，将发布、下架收进单层成果Dialog，展示编号、状态、质量和完整性。
- 同名多次运行成果在列表显示完整成果编号，避免误认另一份快照。
- 自动成果的质量结果将版本标签明确为“输出模型版本”，历史规则成果显示“质量规则版本”。
