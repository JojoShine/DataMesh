# 数据治理流程完善验证

## 已实施

1. 运行结果进入生成模型时保留来源运行；模型修订、发布后可以返回数据流。服务端只读核对模型来源、已发布版本、空间、最新数据流和输出契约，返回候选修改。用户明确确认后形成未保存修订，再保存、运行。保留当前未保存修改保护及版本冲突校验。
2. 在原调度计划中调整版本、周期、时区和参数，显示变化摘要及未来五次触发；保留计划编号、暂停/启用状态及历史。拒绝更换为其他任务、未发布版本、无效授权和过期编辑版本。
3. 周期支持每小时、每天、工作日、每周及带单位的固定间隔；高级 cron 按需填写。首次触发按所选时区解释，夏令时不存在或有歧义的首次时刻需重新选择。
4. 持续运行分别展示采集、Flink、Doris 进度证据；来源事件时间来自可读日志的 source 时间，待转入位点数仅覆盖已采集范围。缺失、快照和墓碑事件时间显示未知，状态检查时间不充当数据更新时间。
5. 业务步骤使用一个主要滚动区域；普通窗口上下排布阶段与配置，桌面保留左右布局；处理方式说明可展开，保留横向步进和底部命令。
6. 概念、逻辑模型隐藏物理库表和物理主键说明；历史隐藏字段保存时保留，切换回物理模型仍可查看和修改。
7. 无成果时说明生成条件并指向数据流、空间核对，搜索无结果可清空条件；成果搜索提供可访问名称。共享办理分别读取真实目录、挂载、修订状态；证据不可见时显示待核对，使用申请与授权按具体使用方办理，不由挂载数量或启用状态推断。

## 实际验证

- Go 内部测试、vet、服务构建通过。
- API 契约 19 项及 OpenAPI 校验通过，接口为兼容性扩展。
- 前端相关 10 个文件、69 项测试通过，类型检查和生产构建通过。早期并行测试受资源争用超时，合并后串行运行全部通过，未提高测试超时或移除断言。
- 临时 PostgreSQL + 真实 Doris/Kafka/Flink 集成通过（271.472 秒）：模型回绑来源与空间保护、最新版本保留、只读无写入/自动运行、类型不匹配、调度历史/状态保留、并发编辑只接受一份、失效来源拒绝、直接调度、旧工作流、目录归属和真实 CDC 链路。
- 独立复核提出的调度锁顺序疑点通过确定性 PostgreSQL 测试核对：治理写入统一入口在进入调度处理前已取得全局锁，等待该锁时不会占用计划行锁。因此保留生产机制，新增回归防止退化。
- 窄屏补充检查发现原 sticky 底栏在长表单下离开视野，改为固定底栏并按实测高度为内容预留空间；修复后数据流 30/30 项回归、类型检查与构建通过。窄屏 540×900 实测文档宽 532，小于视口宽 540；底栏位于 y=835–900，实测高度 65，与内容预留高度一致。阶段和配置区 overflow 均为 visible，桌面业务区由一个主要滚动区承载。

## 实际限制

当前 Flink 成果没有记录来源事件时间传递的完整证据，因此“已处理到的来源时间”和“端到端延迟”明确显示未知。本次没有修改流式转换或检查点语义，来源待转入位点也不代表全链路积压。

正式成果的质量/完整性门禁和按使用方办理的授权继续生效。只读界面检查不提交业务资源或发布申请；自动化集成使用隔离数据库及测试来源。
