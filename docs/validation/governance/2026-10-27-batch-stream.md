# 批流引擎与数据分层验收（2026-10-27）

## 实现范围

- 批量：授权资源读取 → Doris ODS → Doris SQL/隔离代码节点 → 分层 Doris 成果。平台 PostgreSQL 不承载新数据流的业务运算和成果行；原有成果读取保持兼容。
- 持续：共享交换真实 Debezium CDC → Kafka → Flink SQL → Kafka 事务结果 → Go 受控落库 → Doris 最新状态。消费者核对事务提交、过滤回滚及控制记录，按位点幂等落库。
- 暂停保存恢复点并排空已提交结果，再生成独立固定成果，经过同一模型、质量、发布检查；恢复不重复提交状态不明的作业。
- RustFS：按需生成加密、可校验的不可变成果快照，下载重新授权并校验；没有双向同步。
- 数据分层：ODS / DWD / DIM / DWS / ADS，模型、输出、元数据、成果、血缘展示；内部计算和质量隔离独立。部门、目录和原模型层次保持独立。

## 本地运行边界

- 当前持续入口要求首次 CDC 快照完整且保留完整单分区变更历史，本地 Flink 容量为 2 个持续任务（暂停保留名额，结束后经实际作业停止核对释放）；不符合条件在启动前说明原因。
- 连续代码步骤及尚不支持的流式规则在预检查阻断；批量代码仍使用隔离执行器。精度上限为 38 位数值与微秒时间。
- 不提供跨独立源库的原子快照保证。批量明确标记每个来源的读取边界。
- Flink 状态、Doris 与 Kafka 为本地单机部署，本次没有验证高可用和生产规模容量。
- 验收发现 Doris 原内存配额不足：FE 被 OOM 终止、BE 拒绝分配查询内存。FE 配额调整到 1536 MiB，BE 配额到 3072 MiB（内部限制 2304 MiB）；修复 FE 等待 BE 扫描系统表导致的启动退出，使用纯元数据检查。
- 本地资源有限，批量兼容测试期间暂时停止无活动作业的 Flink 服务，持续链路已先单独验收。Oracle 样例源容器保持停止、数据卷保留。
- 未执行按“无主库引用”批量清理 Doris 表；自动审批认为启发式判断可能误删有效表，测试残留予以保留。
