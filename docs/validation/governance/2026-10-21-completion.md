## 检查结论

开始检查时，主题域与责任、术语标准、版本化模型、元数据观察及采样/全量剖析已经有实现和历史验证。数据流也已有受控执行器与加密结果，但编辑页面缺失、运行重试未接通，成果、编排、整改和运维没有组成完整业务路径。

本次补充后的范围：

| 模块 | 当前实现 |
|---|---|
| 治理基础 | 复用已有主题域、责任人、术语、标准及概念/逻辑/物理模型；明确版本引用、发布、停用与破坏性变更说明 |
| 元数据与剖析 | 复用已有真实结构、业务注释、结构观察历史及采样/全量剖析；保留敏感统计隐藏、任务取消和授权检查 |
| 数据流开发 | 接通独立编辑工作区、自动排列的节点图、输入连线和算子配置、版本历史、发布与运行；支持来源、投影、文本转换、过滤、去重、关联、汇总、质量分流、码表和模型输出 |
| 执行与恢复 | 固定定义及模型/标准版本，检查来源与加工授权，记录节点计数和耗时；支持取消、按原定义版本创建新运行，并保留原运行关联；运行列表支持类型、状态及定义筛选 |
| 治理成果 | 合格模型快照、运行成功标记、不可变成果登记证据在同一事务提交；每次成功运行形成独立数据集，契约 v1，关联原数据流和模型版本，不覆盖上一轮成果 |
| 资产与共享 | 复用现有资产发布、目录挂载、数据使用授权和 ETL；发布/交付检查执行证据、快照数量、模型鲜度及有效来源加工共享依据；新成果不允许手工结果绑定覆盖 |
| 工作流 | 版本化任务依赖图引用已发布数据流；无依赖任务并行，支持前置全部成功、全部失败或全部结束的条件；父运行与子任务状态持久化，分别计算排队上限，编排不占用计算工作槽 |
| 调度 | 固定秒数间隔，明确 IANA 时区、首次时刻、错过策略及启停；同一执行人同一工作流禁止重叠，触发与派发在数据库事务中防重；服务重启继续扫描持久状态 |
| 质量整改 | 从真实质量失败或隔离记录登记问题；本部门有效责任人、期限、处理历史及版本并发保护；复测沿用原数据流版本，零隔离且通过真实门禁后才允许关闭 |
| 血缘影响 | 从真实成功运行查看字段来源、资源契约、节点、模型与下游成果；访问时重新检查原执行人的有效来源权限；定义引用保护增加工作流依赖，运行及启用调度保护在用版本 |
| 总览与运维 | 治理定义、运行状态、未关闭/逾期问题与运行查询；查看实际日志、计数、失败诊断，进入运行进行取消或重新执行 |

没有引入新的计算框架、权限体系或外部依赖。业务数据、既有目录、授权、历史成果和审计记录保留。旧成果仍可按历史路径查看；新的标准成果入口来自数据流自动登记。

## 使用路径

1. 在主题域、标准与术语、数据建模中建立并发布需要的版本；准备已有治理职责和加工授权的真实来源。
2. 在“数据流开发”选择来源和字段，添加受控算子、质量分流与明确的模型版本，保存并发布。
3. 手动运行并查看节点统计、模型结果和字段血缘。成功运行自动登记成果；不合格分支与成果隔离。
4. 有资产发布职责的人员在“发布管理”核验并发布成果，后续继续走既有目录挂载、审批与授权交付。
5. 需要多个数据流按依赖执行时，在“工作流与调度”引用已发布版本；按需建立固定间隔调度。调度保存后启用，不会自动替用户创建任务。
6. 在“质量整改”关联实际异常运行、指定责任人及期限；记录处理后发起复测，通过后关闭。运维和血缘入口用于查询真实运行证据。

## 仍缺的高级能力

以下没有在界面或接口中冒充已支持：

- 工作流动态参数、跨任务产物自动传参、独立检查/发布审批任务、断点续跑，以及按当地日历和夏令时调整的 cron 调度。目前恢复是原版本的全新完整运行。
- 独立的跨字段/跨表规则系统、可复用规则模板和完整质量趋势分析。当前可用受控关联与质量分流表达已支持的检查，整改建立在实际异常证据上。
- 物理模型真实目标建表仍未实现；已有功能为安全 DDL 预览，不执行覆盖或自动建表。
- 全量跨系统影响图、完整字段变换语义展示、外部通知渠道和可配置告警规则。当前影响追溯到实际字段来源与治理成果，诊断和逾期提示在页面内展示。
- 治理快照的自动保留到期、受控清理及完整下游迁移工作台尚未实现；当前保留执行与成果证据，不自动删除在用数据。
- 文件/API 契约仍属于元数据登记，不作为通用数据流结构化输入；治理成果也没有开放为任意后续治理计算来源。
- 主数据融合、完整指标语义系统和 AI 辅助治理仍为独立专项。
