# 代码节点运行环境

代码节点是逐行一进一出的专用业务处理。普通姓名去空格继续用文本转换，复杂客户编码整理或精确金额计算可用 Python / JavaScript；筛选、关联、汇总和质量检查仍有各自的算子。

数据通过原来源加工授权读取，再发给独立任务。整数和小数以十进制字符串传入，Python 使用 Decimal，JavaScript 使用 decimal.js 10.6.0。每条输入返回一个对象，字段、类型、精度和可空性必须与输出声明一致。任一批失败则整次运行回滚；只有完整运行通过质量与模型门禁才登记成果。

试运行每个来源最多读取20行，展示目标代码节点前20条输入输出；这是来源顺序样本，不代表全量检查，不登记成果，也不参与完整运行成功率。样本加密保存，读取时重新核对运行本人或管理员权限、账号、来源和固定引用。

## 部署与维护

1. `python3 scripts/build_governance_code.py` 构建摘要固定的官方运行基础环境及包装器，保留只供主服务和执行代理使用的本机私有令牌，并将实际镜像ID写入本机环境配置。令牌不进入源码或日志。
2. 构建现有 server 镜像，其中包含独立 `/app/code-runner`；应用迁移26和27，更新 `code-runner` 与 `server`。代理不公开端口，只在内部 `code_control` 网络提供固定协议。
3. `GET /api/v1/governance/code-runtimes` 返回真实可用环境及不可变ID。数据流版本引用此ID；镜像不可用时明确拒绝代码处理，旧SQL数据流不依赖代码服务健康。
4. 升级运行环境时保留仍被已发布数据流引用的旧镜像。新环境需要新数据流版本明确选择，不能让重试自动换成最新镜像。

每个任务均为65532非root用户，无网络、无宿主挂载、无平台凭据；只读根文件系统和32MiB临时空间，256MiB内存、1CPU、32进程、最长120秒，空闲30秒回收。Docker socket仅执行代理可连接，脚本任务没有该挂载。缺失资源隔离能力时代理拒绝启动，不降级到主进程执行。代理最多同时运行2个任务，取消、超时或重启只清理本代理命名空间的任务。

每批最多250行/2MiB，单行256KiB；累计数据量继续受既有ETL预算限制。代码日志不保存行值，诊断保留节点、错误类别、用户代码行列及不合规字段名。任意代码的血缘按全部输入字段保守追踪，敏感性继承输入并集。

## 回退

使用部署清单记录的旧 server 镜像恢复应用服务，并停止新增执行代理。迁移26、27为兼容增加，旧版服务仍可读取原定义；已有代码定义与预览记录必须保留，不应直接删除。迁移27的down在存在预览历史时会拒绝执行，避免丢历史。需要数据库整体恢复时使用已完成隔离恢复核验的部署前备份；实际恢复前需核对部署后新增业务数据。
