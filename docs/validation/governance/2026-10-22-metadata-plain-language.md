# 元数据按用途组织交互

## 变更

按已确认方案将对象详情分成四个用途页签，不缩减业务功能：

| 页签 | 用户要解决的问题 | 主要操作 |
| --- | --- | --- |
| 数据结构 | 有哪些字段、类型和必填要求 | 检查最新结构；文件/API保存登记结构版本；文件保留读取方式配置 |
| 业务说明 | 字段代表什么、谁负责、与标准术语如何关联 | 补充业务说明；历史说明仍可查看、修订、发布及追溯 |
| 更新与变化 | 结构是否及时更新、哪些使用方受影响 | 设置自动更新、单次检查、变化核查及处理意见 |
| 数据情况 | 数据是否缺失、重复，数值如何分布 | 检查部分或全部数据、报告、历史、取消、重试及日志 |

- 底栏只显示当前页命令，通常连同“返回列表”共2至3个按钮，统一固定右下角。
- 设置和变化核查直接替换当前页内容；保留单层dialog。写入期间保留等待与禁用行为。
- 页签切换保留已填检查范围、字段和更新周期，后台任务及实际资源版本参数不变。回到结构页重新读取结构记录。
- 原术语“开始剖析”改为“检查数据情况”，“登记业务注释”改为“补充业务说明”，“采集设置”改为“设置自动更新”。保留必要的技术字段并提供悬浮解释。
- 各页说明用途、前置授权及后续关系，用CRM客户编号和商品含税价格举例。明确保存结构记录、检查数据情况和修改业务数据的区别。
- 保留既有类型、权限、字段选择、采样与全量、敏感信息保护、发布和变更校验；未修改后台接口、数据库结构或权限。
- 保留既有字号、24px分区间距、表格内部滚动；用途页签随内容滚动保持可见。
