## 保护条件

- 治理输入、执行和发布持续检查当前授权、固定契约版本及来源状态；工作流内部成果传递只依靠同账号的持久化任务证据，不伪造加工授权。
- 发布审批要求具有成果管理职责的资产提供方；普通执行者不得自审批。
- 建表只支持明确的 PostgreSQL/MySQL 新目标，目标 Schema 需预先存在；不修改既有表，不自动建立外键。
- 告警外发仅使用管理员批准的 API 目标；不随部署启用任何通知；载荷仅含通知编号、运行编号、诊断码和时间。接收方按通知编号去重。
- 发布中成果、未关闭质量整改、有效授权、在用挂接、有效定义、交换任务、排队或执行中的剖析及工作流、迁移计划及仍保留的后继计算成果都会阻断清理。保留中的后继成果继续保护祖先快照，需要从无引用末端逐步清理。
- 历史草稿不永久阻断清理，最新草稿和已发布版本受保护；归档交换任务和已解除挂接的历史版本不作为在用依赖。
