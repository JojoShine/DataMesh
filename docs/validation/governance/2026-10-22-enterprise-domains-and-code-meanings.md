# 企业主题域与码值含义核验

变更：企业统一主题域由管理员维护；部门以独立版本登记责任人、维护人和职责范围，固定引用企业定义。既有部门主题域保持原样。只有已发布企业定义可以跨部门读取，其他部门分工、标准、草稿及业务资源不随之共享。数据标准以业务编码表达，逐项保存允许值与业务含义，历史版本无需迁移或改写。

验证：

- Go 格式、静态检查及既有治理检查通过。
- 前端目录、元数据、导航、看板及使用性检查通过；新增覆盖企业定义只读、单层弹窗登记部门分工、码值含义必填与提交、旧标准提示。
- 独立 PostgreSQL 验证通过：跨部门企业定义引用、同部门普通治理人员也不能编辑企业定义、草稿及历史隔离、他部门分工和标准不可读、非法责任人及重复分工拒绝、在用企业版本禁止停用。
- 独立 PostgreSQL 验证通过：码值含义缺失、空白及不匹配拒绝；旧标准仍可读取；补充旧码值含义可正常发布，改写已有含义需要迁移说明。
- 企业定义的部门看板计数与可见范围核对通过；原看板基准在独立验证库通过。
- 接口契约组件结构、引用及参数唯一性检查通过。
- 1920 宽屏、1280 页面及 540 窄屏核对，沿用单层 dialog、右下角固定操作和既有字号。截图为开发专用只读示例，非主环境业务数据。

入口：管理员在“主题域与责任”新建“企业统一主题域”并发布；部门打开已发布定义后登记本部门责任。数据标准中使用例如 common.enable_flag 的业务编码，填写 0＝停用、1＝启用；付款状态的 0/1 应使用另一份标准。

主环境发布结果另存于私有部署记录，发布后对已有主题域、标准与术语及新筛选接口进行严格证书校验的只读核对，不创建演示业务数据。
