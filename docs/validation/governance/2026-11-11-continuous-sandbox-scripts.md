# 持续脚本与真实流式生命周期验收

2026-11-11，真实 PostgreSQL CDC → Kafka/Connect → Flink → Doris 链路及 Python → JavaScript 持续处理生命周期验收通过。基础流测试与独立体验脚本测试均实际运行；不以单元测试或容器就绪代替业务验收。

## 本次实现

- 延续 PostgreSQL CDC → Kafka/Connect → Flink → Kafka 事务结果 → 受控 Doris 落库，不使用批量任务替代持续处理。
- Python、JavaScript 代码节点通过私有、签名、验证证书与主机名的通道复用隔离执行器；代码和凭据不进入生成的 SQL，脚本容器没有网络及宿主挂载。
- 逐行执行；跨行关联、汇总状态由 Flink 节点维护。结果按固定任务、节点、来源行身份、规范输入加密保存在独立 RustFS 缓存；恢复、撤回、旧值重放复用同一持久结果。
- 原子条件写入只允许首个值成功，确认或重试后回读唯一持久值；最终未知结果报错，后续先读。普通元数据库不保存这些业务行。
- 时间统一到 UTC 微秒，拒绝更细精度；大整数、精确小数保持字符串协议，避免 JavaScript/JSON 路径浮点舍入。缺失字段、输出类型错误和执行超时明确失败。
- 启动、缓存命中和执行结束重新校验固定任务的当前权限、代次和状态；撤销治理角色、平台访问、加工授权或停止任务后禁止继续处理。
- 操作超时或工作器关闭时，仅以5秒独立上下文释放自己仍拥有的控制租约，不继续数据处理，不把未知引擎状态标为已结束。失败请求审计保留3秒独立预算，审计失败仍拒绝。

## 验证边界

本机单机配置不包含 Flink 高可用作业历史。Docker 整体退出后，JobManager 内存历史丢失，控制器保留“待核对”占用且不自动重复提交。此次仅在确认独立应用、提交组件、计算组件全部停止且没有代码沙箱后，对明确归属的虚构测试流进行有记录的人工恢复；保留原失败历史，不将此操作计为自动恢复成功。应用重启、TaskManager 检查点恢复与整个 JobManager/集群重启属于不同验证范围。

完整复测曾被 Doris 进程内存拒绝阻断：实际 RSS 2.27GiB 超过内部 2304MiB 上限，进程分析显示无活跃查询，表元数据约46MiB、普通缓存不足1MiB，分配器及未跟踪占用是主要部分。未删除历史表或重置数据；在既有 3GiB 容器硬限制内，将内部上限改为2560MiB，保留512MiB余量，只重启 BE。健康检查及生效配置核验通过，Docker仍为12GiB，体验工作组及并发限制保持原样。此后继续相同作业，不新建替代作业。

本机冷读时延仍有波动。最终既有六条成果闭环第一次读取返回503，保留失败证据后原断言复测通过；未延长普通应用读取期限。私有脚本探针仅对明确允许的临时GET503做有界恢复并记录次数，不重试未知结果的执行POST，不把重试当作性能问题已修复的证据。
