# 授权资源100万行 ETL 验收

状态：六轮真实100万行测试全部通过，累计600万行交换；完整测试耗时2088.49秒。10,001行演练和修复前初测不计为本次规模验收。本地发布见共享交换总验收记录。

## 测试范围与环境

执行入口：`python3 scripts/benchmark_authorized_etl.py`。脚本编译实际集成测试，在单独命名的临时数据库和受限执行器中运行，结束后删除隔离数据库及本次对象文件，不写客户业务表。`--pilot` 使用10,001行验证六轮流程，报告明确标记为非规模验收。

- 执行器：2 CPU、512 MiB 容器上限，Go运行时软内存目标384 MiB。
- PostgreSQL：来源、目标及平台元数据共用本机同一隔离实例；该容器内存上限384 MiB。原始归档存入实际 RustFS。
- 每轮100万行，映射两列：bigint主键和敏感文本。源含额外未授权列，目标只建两列；文本按普通跨部门账号的使用授权脱敏为 `***`。不使用管理员身份进行资源交付。
- 运行的逻辑字节估算为3500万字节（每行整数估算32字节、脱敏文本3字节），不是物理表大小或网络流量。
- 原始及治理夹具包含100万条首次快照事件，再执行更新、删除和新增。归档为确定的分块测试输入；CDC真实采集的增删改验证另用三库真实连接器进行。百万行计时覆盖资源读取/快照重建、授权、转换、写入、索引和对账。任务经实际服务处理器提交和轮询，底层为真实数据库及对象存储连接；未计入公网和浏览器操作耗时。
- 治理结果在执行 ETL 前已完成完整范围质量与逐键输入/输出核验，其预核验耗时从提交绑定到观察到完整校验结束单独记录，不混入 ETL 同步计时。原始资源使用冷快照重建。

## 场景与正确性

1. PG库表资源：空目标三次独立运行，每次完整核对。
2. PG库表资源：保留100万已有主键，将其中一半的目标值改为旧值，再执行全量upsert。
3. 原始快照资源：从验证后的事件归档重建当前状态，再进行交换。
4. 治理成果资源：从已通过显式结果绑定及完整质量门禁的固定快照交换。

每轮均检查：运行成功；100万最终键逐一存在；所有目标映射值均为批准的脱敏值；没有越权列；更新/删除/新增后的键集合准确；独立提交后报告检查100万最终键且差异为0；实际接收账号成功提交业务回执。并非仅检查总行数。

每次采用整轮单事务。指标分别记录输入准备、读取转换、目标写入、交付索引、提交前核对、提交以及提交后核对。`execution_ms` 包括排队至观察到事务成功，`through_report_ms` 包括独立提交后核对完成；`total_ms` 为领取后的执行器内部计时。内存为运行期间每20毫秒采样的 Go 堆峰值，不等同容器RSS。

三次空目标同步中位数 **226.225秒**，约4420行/秒；含独立对账的中位数 **273.196秒**。已有主键测试实际执行100万行upsert，预先将一半目标值改旧，结束后全部恢复为授权脱敏值。

原始资源的同步时间已包含 **110.654秒冷快照准备**。治理结果在交换前另用 **334.568秒** 完成归档输入重建、整份质量与逐键输入/输出校验；此时间未混入249.808秒的ETL同步。已有固定且已核验的治理快照可以复用，输入或规则变化须重新核验。

## 可复核性与限制

- 测量时 `internal` 与 `tests/integration` Go源码指纹为 `0cffeefc3f2c983bcaa17b55ef42c24053eba4b89245a4ec61d1b69bea8091c7`；运行期间未修改。Go1.25.5、PostgreSQL17.11、RustFS1.0.0，环境版本沿用项目锁文件。
- 正式六轮的经过时间和正确性断言由执行时记录。测试收集器曾复用阶段计时对象，前三轮阶段列从各自持久化运行记录独立导出，结果JSON注明来源，原始输出与导出依据保留在执行记录中。测量后仅补充测试、修复收集器的值复制，并增加每轮计时与数据库原记录一致的回归；未改变正式测试的运行逻辑或经过时间。
- 堆采样覆盖ETL至提交后核对，不含治理前置校验，也不等于RSS；整个测试执行器始终受512MiB容器上限约束。未发生容器内存溢出或目标部分提交。
- 百万行实测的目标是PostgreSQL，表为两列窄表。MySQL四种来源/目标组合另以真实1501行检查精确数值、排序规则及核对；不能据此声称完成MySQL/Oracle百万行测试或公网吞吐测试。
- 默认200万行/1GiB/30分钟是配置上限；本次完成的是100万行正向规模验收。边界回归另用实际2000001行确认行数上限；用较低的20000字节配置跨过已写批次、真实超过4MiB的单行、5秒超时和精确中断测试来源连接，均确认整轮回滚。未实际传输超过1GiB或等待30分钟，缩小配置验证的是同一限额/超时机制。原始大归档为确定的验证事件夹具，三库真实CDC首次快照和增删改另有测试，不能据此声称测得百万行CDC采集吞吐。
- 不能将旧的直接连接16秒成绩与本次增加授权、脱敏、固定快照、交付索引和全量核对后的成绩直接比较，也不据本机窄表测试承诺生产SLA。
