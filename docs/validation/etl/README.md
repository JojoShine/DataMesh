# 可配置 ETL 与共享交换流程

## 使用路径

- 资源目录 → 目录维护 → 挂载资源 → 选择方式 → 接入/选择资源 → 字段映射 → 保存挂载草稿。数据库选表、Excel 导入、文件上传、API 登记沿用真实接口；治理成果目录复用已发布成果。
- 「目录与挂载审核」处理发布和启用；「数据使用申请审批」处理申请人、资源、字段、用途和期限。批准使用申请自动生成「数据使用授权」；「数据加工授权」独立约束治理和派生成果。
- 数据同步 → ETL 数据交换 → 新建任务，选择来源表、目标表及每个目标字段的来源和转换规则 → 保存 → 执行 ETL → 运行与交换明细。

## ETL 边界

支持已允许连接范围内的 PostgreSQL / MySQL 表，来源和目标均须有主键。转换支持直接映射、去除首尾空格、大写和小写；映射两端逻辑类型必须一致。目标表预先建立，账号需有读写权限；不会自动建表、修改表结构或删除目标记录。

按目标主键更新映射字段或插入新行；未映射字段由数据库默认值和约束处理。MySQL 来源和目标要求 InnoDB，并拒绝存在主键以外唯一索引的表，以避免其他唯一键冲突引发错误覆盖。直接库表在只读一致性事务中流式读取，以最多500行、4 MiB的批次写入目标。默认最多200万行/1 GiB，执行时限30分钟；平台资源继续保留原交付链路的1万行/20 MiB限制。不截断超限输入；超限整批失败。不是增量 CDC，也不是 Flink 作业编排。

普通账号目标须与来源属于同一部门，跨部门交付仍走既有数据使用申请审批；管理员沿用系统现有全范围权限。普通账号须有两端数据源运维职责，并具有覆盖来源对象版本、字段、用途「数据治理」和有效期且允许派生成果的加工授权。来源对象须已登记。执行前及提交前重新检查账号、平台、角色、职责与加工授权。关联 ETL 后的数据源连接不能原地变更。

任务及运行写入现有业务记录表（迁移 000005），控制、事件和告警使用迁移 000006 的独立表，租约和目标占用使用迁移 000007。创建与运行接口使用既有 CSRF、幂等键和审计机制；同一任务串行执行。运行阶段、读取行数、事务提交行数和每个实际写入批次（最多500行）的交换范围持久化；不保存数据值或凭据。轮询只读运行记录，不触发执行。

目标写入在单一事务内完成。提交前失败回滚；提交返回不确定时保留 unknown，禁止自动重跑。已排队任务保留并由worker恢复领取；运行中执行器失去租约后转为unknown，禁止自动重跑；运维应核对目标数据库与运行记录后处理，不能把超时直接当成失败或成功。不同任务的执行共用已有并发限制。

## 生命周期、日志与告警

参见[运行控制与验证记录](operations.md)。任务管理支持编辑新版本、复制、启用/停用和归档；编辑后保存为草稿，须重新启用。草稿仍要求完整且可校验的配置。历史运行保存当时的定义、任务版本和尝试编号。

运行明细可取消提交前的运行、对已确认失败或取消的运行创建重试、筛选并下载追加日志。异常运行可核查执行器；已退出的执行器转为待核实，管理员须填写事务结果、核实依据和处理原因。活跃执行器及未知提交结果不可直接重跑。运行告警入口支持确认及关闭，保留处理记录。

## 接口

- `GET /api/v1/etl-tasks`：分页任务列表（本人；管理员全部）。
- `POST /api/v1/etl-tasks`：校验并保存任务定义；默认启用，`draft=true` 保存为草稿。
- `POST /api/v1/etl-tasks/{id}/run`：创建运行记录，201 表示已接收；结果以运行记录为准。
- `GET /api/v1/etl-tasks/{id}/runs`：分页运行、字段规则及批次明细。

OpenAPI 已同步描述新接口，兼容原 CDC 任务，并增加独立远程采集接口。部署需执行迁移至 000011，并重新构建前端与服务端。

## 验证入口

- `npm --prefix web test`：挂载选择流程、权限提示、ETL 执行确认和失败反馈。
- `scripts/check.sh go`：Go 格式、静态检查、单元测试和构建。
- `python3 scripts/test_identity.py --run TestETLRealExchange`：在临时 PostgreSQL 数据库实际执行转换、主键更新、幂等重试、事务回滚、权限及超限测试；不会写业务表。

## 可靠执行与百万行验收

详见[百万行测试与执行边界](million-row.md)。HTTP接收后由持久队列领取，执行中每秒续约，租约30秒失效后保留unknown和目标占用。配置在`.local/runtime.env`设置，修改后重新创建server容器：

| 配置 | 默认 | 允许范围 |
| --- | --- | --- |
| ETL_MAX_ROWS | 2000000 | 1–10000000，直接库表行数上限 |
| ETL_MAX_BYTES | 1073741824 | 1024–17179869184，转换后逻辑字节估算上限 |
| ETL_TIMEOUT_SECONDS | 1800 | 5–7200，领取后执行时限，不含排队 |

`GET /api/v1/etl-capabilities`返回当前范围，页面按实际配置提示。平台资源按选中适配器呈现容量：PG/MySQL 库表、完整原始快照及已核验治理结果采用批量上限；Oracle 查询、Excel 和旧归档等兼容适配器仍取10,000行/20 MiB与配置值的较小值。可通过 resource_type、resource_id、contract_version 查询实际所选资源的容量。目标元数据占用采用数据库类型、库名、schema、表名，保守忽略主机/端口，防止连接别名绕过待核实任务；不同物理实例同名目标也会顺序执行。PG批次使用savepoint兼容数据库主键归一化；固定小数精度缩窄或不明确的有损映射会被拒绝。

排队恢复不是断点续传。目标仍为整次单事务，运行中失联或提交不确定后须人工核实；不自动续传部分批次。定时/增量/重试退避和字段血缘不在本批范围。技术对账及收方业务验收已实现，分别记录。

## 固定输入、技术对账和业务验收

- 授权库表采用一致性流式读取；原始归档逐块验证后按主键重建加密快照；治理成果显式绑定实际结果库表、原始归档和规则版本，完整核验通过后才发布。治理绑定验证已有结果，不替代治理计算。
- 运行固定资源契约、目录及挂载修订、使用授权和脱敏依据。每批及提交前重新检查；撤权、身份范围或共享策略变化将回滚。需要脱敏的主键不得用于交换，包括兼容的小容量适配器。
- 写入后按目标数据库实际主键规则建立加密期望索引；事务内逐键读回映射字段，包含延迟触发器结果，不一致则回滚。处理行数可能包含同一目标键的多次写入，最终键数单独统计。
- 目标提交后异步执行只读对账。失败时可“重核本次交付”，只读目标和已固定的期望索引，不重跑来源或重写目标。执行成功不代表对账通过，也不代表收方已验收。
- 收方根据最新通过报告填写接收或驳回回执；管理员代办必须填写原因，记录实际操作人与收方。版本变化须重新查看报告，历史回执不覆盖。未知提交结果须先核实，不能直接签发接收回执。
- 原始暂存默认保留24小时，交付核对索引默认7天；活动/未知运行保护证据。清理正文不删除技术报告和回执。过期或历史无索引的运行不会补造通过结论。
- 运行页的“交换结果 / 对账与验收 / 日志与处理”复用同一窗口；显示输入准备、读取转换、目标写入、期望索引、提交前核对及提交耗时。

新增接口：`GET/POST /api/v1/datasets/{id}/result-binding`、`GET/POST /api/v1/etl-runs/{id}/reconciliation`、`GET/POST /api/v1/etl-runs/{id}/receipts`。对账 GET 的 `download=1` 导出最新安全报告。
