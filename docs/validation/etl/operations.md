# ETL 运行控制（2026-10-20）

## 页面入口

实际本机服务：<https://localhost:18443/platform/exchange/etl>。

任务列表提供状态、当前版本、执行、运行与交换明细和任务管理。任务管理支持编辑新版本、复制为草稿、停用和归档；草稿/停用可启用。归档保留运行记录，不能重新执行，可复制为新任务。

新建保持兼容，默认保存为已启用，也可保存草稿。编辑后产生新的当前版本并进入草稿，须启用才能执行。草稿要求完整且可校验的连接和映射配置，不支持不完整表单的暂存。配置动作带 expected_version 防止覆盖并发修改；存在未完成或待核实运行时拒绝修改状态/定义。旧运行保存定义和版本快照；未运行过的旧配置没有独立版本归档库。

## 运行动作与事务边界

| 动作 | 条件与结果 |
| --- | --- |
| 取消 | queued 直接取消；extracting/loading 请求中断，实际回滚后才显示 cancelled；committing/unknown 拒绝取消 |
| 重试 | 仅 failed/cancelled，任务版本一致且已启用，重新鉴权；创建新 run_id，attempt 增加并关联 retry_of；重新读取当前来源，旧运行不变 |
| 核查执行状态 | extracting/loading/committing 且执行器已退出时转为 unknown，产生事件及告警；执行器仍活跃时拒绝 |
| 核实结果 | 仅管理员，unknown 且执行器已退出；填写已提交/未提交或已回滚、原因和可追溯依据；核实为失败后才允许重试 |

相同幂等键的请求返回同一运行，重复分发通过事务内 claim 避免重复执行。claim 与 active 标记同事务；取消和提交前检查共享运行锁。等待超时只有在锁内仍为 queued 时才能结束运行。目标 Commit 返回后的异常只进入 unknown，不标记为失败或已取消。

日志保存失败会终止后续写入并尝试回滚、保存失败状态；目标已提交但状态保存失败时尝试写 unknown。若状态库持续不可用，页面可能暂时停留在旧阶段，恢复后通过核查/核实处理，不能凭超时推断提交结果。

## 日志与告警

- 独立追加 etl_events：运行、任务、阶段、级别、事件代码、说明、处理人、追踪号及时间。按运行分页，每页50条，支持级别/阶段筛选；单次导出至多10,000条 NDJSON，导出记审计。
- 任务版本、尝试、开始/结束时间、错误码及核实依据保存在运行中；执行结果另记审计。自动日志不包含 SQL 数据值或数据库密码。用户填写的处理说明会保存，页面提示不要填敏感内容。
- 日志保留策略90天；目前在服务启动时清理超过90天的事件，长期不重启的服务会延后清理。运行记录和告警不会随事件清理删除。
- 失败、超时、未知结果、服务重启和超过一分钟无处理进展生成站内告警。同一运行/诊断代码去重。执行期间每秒更新控制心跳，正常处理进度会重置无进展计时。
- 告警支持待处理→处理中→已关闭，须填说明；确认和关闭分别追加事件，保留两次处理说明与操作者。告警关闭不修改运行结果，运行成功也不会自动关闭此前告警。没有外部消息推送。
- 任务/运行/日志/告警仅本人或管理员可操作；未知结果核实额外要求管理员。沿用平台访问、岗位、CSRF、请求幂等及审计检查。
- 运行明细后台刷新保留已有数据和表单，避免核实依据及阅读位置每3秒被重置；身份和查询范围变更仍清空旧范围数据。

## 接口增量

任务：`POST /api/v1/etl-tasks/{id}/{enable|disable|archive|copy|revisions}`。

运行：`POST /api/v1/etl-runs/{id}/{cancel|retry|reconcile|resolve}`。

日志：`GET /api/v1/etl-runs/{id}/events`，支持 page、level、stage、download=1。

告警：`GET /api/v1/etl-alerts`，支持 page、state、run_id；`POST /api/v1/etl-alerts/{id}/{acknowledge|resolve}`。

详见 OpenAPI。原有创建与执行入口保持兼容。部署先迁移至000007，再更新服务；新增表和索引不更改既有任务定义。回退迁移会拒绝删除已有事件/告警，避免误删运维历史。

## 本阶段边界

本轮已补持久queued记录、受进程生命周期控制的worker、30秒租约和1秒续约、全局ETL配额2及同目标占用。排队不再依赖HTTP回调，也不计入执行时限；已排队任务在重建执行器后继续领取。运行中失联转unknown并保留目标占用，不直接重跑。升级旧运行会回填占用，回填与领取使用同一事务锁并锁定候选行。

提交前元数据检查与外部数据库Commit之间不是分布式事务，无法承诺阻止已经越过提交边界的提交。此时保留unknown、目标占用及人工核实；核实须取得目标库锁以排除旧事务尚活跃的情况。取消遇到驱动断连时，提交前关闭原连接并尝试重新取得目标锁，只有确认事务结束才报告已取消；否则仍待核实。

目标占用保守按数据库类型、库名、schema、表名跨主机串行，以覆盖连接别名；同名但不同物理库也会保守阻塞。这不是数据库中所有应用写入的全局锁，仅约束使用本平台锁协议的ETL。

本机API仍按单实例部署；本轮验证ETL多执行器竞争领取，不代表CDC等其他后台作业或整个平台已经完成多实例高可用验收。定时/事件调度、自动退避重试、检查点/断点续传、输入水位/补跑、业务对账回执和字段级血缘仍待后续交付。直接库表默认200万行/1 GiB/30分钟；平台资源维持原授权、脱敏、质量与1万行/20 MiB边界。见[百万行测试](million-row.md)。
