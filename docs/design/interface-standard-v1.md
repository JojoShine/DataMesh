# DataMesh 界面设计规范 · 已确认字号标准

状态：用户已确认以下字号及控件尺寸，作为唯一执行标准。后续不得自行提出、建立或采用新的字号规范；只有用户明确要求变更时才能修改。历史文档、组件默认值和现有代码与此不一致时，以本标准为准。

## 固定字号与控件尺寸

| 元素 | 字号 | 字重 |
|---|---:|---|
| 页面主标题 | 24px | 加粗 |
| 弹窗标题、区块标题 | 18px | 加粗 |
| 正文、提示框说明 | 15px | 常规 |
| 长篇说明、阅读型内容 | 16px | 常规 |
| 表单标签、输入内容、下拉选项 | 15px | 常规 |
| 导航菜单、标签页、表格内容 | 14px | 常规；表头及选中项适当加粗 |
| 按钮文字 | 14px | 常规 |
| 辅助说明、状态标签 | 13px | 常规 |

- 提示框标题沿用正文 15px，以加粗区分，不使用弹窗或区块标题字号。
- 按钮默认高度 32px；单行输入框、下拉框高度 36px。多行输入按内容设置高度，文字仍为 15px。
- 字号与控件高度分别控制，按钮不得继承表单的大尺寸。搜索区、弹窗、登录及首页中的同类控件使用同一标准。
- 后台窄屏保持以上字号，通过换行、布局调整和表格内部滚动适配。
- 首页及登录宣传展示区域保留下文已有的专用排版，不扩展至后台、表单和弹窗；不得再新增字号例外。

## Ant Design 组件

- 首页资产分页固定每页9条，不提供条数切换（2026-11-05用户确认）；后台列表分页默认每页15条，统一提供15、20、25、50、100条选择；切换条数回到第一页并保留筛选。数量选择器在单页列表与窄屏仍可见，分页栏允许换行。后台分页须按所选数量请求，不得只改变控件显示。

- 复用 `web/src/app/theme.ts`，通过共享组件令牌和必要的公共样式实现上表。不得通过全局增大 fontSize/controlHeight 使所有组件一起放大，不得创建页面级字号主题。
- 不再使用 Form size="large" 或搜索区 large 尺寸作为统一规则。现有 large 用法属于待对齐实现，不能作为新规范依据。
- 内边距、边框及交互状态延续组件规范，不因字号调整而另建一套样式。
- 按语义区分数据项入口与操作命令：可点击的数据源名、任务名、来源对象名、数据集名、申请编号等使用蓝色链接，不加背景和边框；现有抽屉入口使用 Ant Design Button type="link"保留键盘和点击行为，真实页面导航使用超链接。原本不能点击的数据文本不新增交互。申请、测试连接、检查、发布、下架、审批、撤权、禁用等操作使用有背景、有边框的标准 primary/default/danger 按钮（蓝底、白底或危险操作红色表现），操作间距16px。不得将数据名称做成实体按钮，也不能将业务操作做成蓝色文字链接。工具栏、表单及弹窗/抽屉底部继续使用 primary/默认按钮。门户详情和登录返回操作也使用标准按钮。字号及高度按上表，内边距和边框沿用组件默认值。侧栏折叠、账号入口等导航触发器保留既有导航样式。
- 四个平台和详情中的表格复用同一主题。窄屏采用表格内部滚动或换行，不缩小文字。保留组件自身禁用、加载、焦点和状态颜色。

## 页面文字与布局

页面展示文字与组件尺寸分开管理：平台页面标题24px，正文15px、辅助说明13px；其他文字按上表。工作区上下16px/左右24px，自绘业务面板内边距20px，顶栏64px，面包屑下方12px、标题区下方16px。Ant Design 卡片内部使用默认内边距。

首页主视觉52px（移动端32px），四入口标题/说明22px/16px（移动端20px/15px），资产分区标题28px（移动端24px）、资产名称18px、说明16px、元信息14–16px。首页展示文字保留较大层级，首页筛选、按钮和状态标签按上表执行。

首页内容最大宽1520px、两侧至少24px（移动端20px），通栏主视觉高320px（移动端248px）。2026-11-02用户确认四个平台采用主视觉下方的一体式白色入口带，取代四张独立卡片：桌面四列、最小高144px，无独立边框、圆角或阴影，入口间用细竖线区分；中等宽度和手机两列，手机最小高168px，行间细分隔线。入口图标88px（移动端48px），图标与文字间距16px（移动端8px），字号沿用上表。下方资产卡片、筛选和详情保持原样。资产描述与信息栏之间至少24px，信息栏上下16px，底部操作上方12px。维持四入口在上、真实资产在下，底部不重复展示品牌栏。

登录保留左侧约59.5%的连续品牌画面、右侧居中表单，主视觉44px（移动端32px）、标题24px（移动端22px）、表单最大宽400px。2026-11-04用户确认登录页采用更舒展的等高控件：账号框、密码框及登录提交按钮均为40px；输入字号15px、按钮字号14px。返回按钮及其他页面继续沿用原有尺寸。

四个平台共用深蓝左导航、右顶栏及业务区。导航宽220–272px，小屏收起为64px；底部返回门户和折叠按钮放入工具栏。弹窗和抽屉的内容宽度可按信息结构设置，不扩大内部控件。资产说明、字段表、核对范围之间保留24px分区间距。

## 颜色、实现与验收

- 品牌主色 #1677FF，导航 #001B33，一级文字 #102349，辅助 #60749A，背景 #F3F8FE，边框 #DCE6F3，面板白色。绿色仅表示成功等状态。字体 PingFang SC / Microsoft YaHei / system-ui。
- 共享主题为 web/src/app/theme.ts，公共样式为 web/src/style.css，数据源局部布局为 Sources.css，开发要求写入 web/AGENTS.md。不得另建页面级组件尺寸覆盖。
- 验收1920×1080，并检查1440宽及窄屏。生产使用真实接口，权限、凭据、确认、审批、禁用和加载逻辑保持原有语义。一次登录共用四个平台，成功后回首页。
- 共享交换负责原始数据接入和治理成果共享；只展示接口支持的信息。开发专用 web/design-preview.html 使用样例、阻止写入、不打入生产。视觉验证与真实业务端到端验证分别报告。

## 共享交换目录工作区

- 左侧按目录与资源、数据接入与同步、数据共享与服务、审核与加工授权分组。“目录与资源”包含资源目录；“数据接入与同步”包含数据源管理、CDC 接入任务、ETL 数据交换；“数据共享与服务”包含数据服务、数据使用申请审批、数据使用授权；“审核与加工授权”包含目录与挂载审核、数据加工授权。资源目录页内区分“已发布目录”和“目录维护”；维护视图按角色与职责开放。资源挂载从对应目录行打开居中弹窗，不再设置独立目录注册或资源挂载菜单。
- 目录发现页采用同一白色面板内的左侧分类与右侧筛选列表；窄屏上下排列，表格内部滚动。分类使用默认尺寸菜单，不使用单独的大卡片。
- 新增目录、挂载等业务操作保留实体按钮。权限不足时说明原因，不通过隐藏全部入口代替说明，也不放宽后台校验。

## 数据治理工作区

- 数据治理使用白色顶部导航，左侧保留 Logo，不设置左侧菜单栏；“工作台”直接进入治理看板，其余入口按业务流程分为“准备数据”（来源数据、元数据管理、数据建模）、“处理数据”（数据流设计、工作流编排、调度计划）、“检查与交付”（质量管理、成果核验、成果生命周期）、“标准与规范”（主题域与责任、业务术语、数据标准）、“监控与追溯”（运行运维、治理告警、血缘与影响）。质量管理保留检查记录、检查方案、问题整改和质量趋势的页内入口；历史质量页面仍归属“检查与交付”。空间管理继续保留在治理空间栏。菜单顺序表达常规业务流程，各环节可按需直接进入，不构成模型、工作流或调度的强制前置。
- 点击顶部分类后，在该分类正下方展开下拉菜单；子菜单是页面导航链接，选择后收起并进入原业务页面，点击外部或按 Esc 可收起。分类与子项保留现有角色权限过滤，空分类隐藏，当前分类及页面有明确标识。除数据流设计工作区外，业务操作继续使用单层 dialog，按钮位于右下角。
- 顶部平台切换统一使用“平台图标＋当前平台名＋下拉箭头”的紧凑按钮，整块可点击，不在旁边另放“切换平台”文字。下拉仅列出账号已获准进入的平台，每项显示名称和简短用途，当前项使用主题蓝与选中标识；点击当前平台不重置正在处理的页面。保留账号入口；中等宽度将治理分类移至下一行，窄屏允许换行，子菜单改为单列。字号及控件尺寸不变，业务功能与流程完整保留。

- 数据流设计不重复展示页面主标题及描述，面包屑下直接进入工作区；列表收起、学习和新建入口整合到工作区顶部。使用独立工作页面：左侧为可搜索、分页和收起的数据流列表，右侧为编排工作区；节点配置可收起，点选节点时展开。设计、前置核对、版本、实际运行和代码样本结果在同一工作区切换，业务命令集中到底部右侧；切换数据流前保护未保存修改。窄屏改为上下排列并允许页面滚动，保留画布缩放和配置区内部滚动。学习引导仍在单层教学 dialog 中展示。

- 数据流默认展示“选数据、定规则、确认输出”的业务步骤，使用业务名称和具体规则摘要。三个阶段使用横向可点击步进导航，每次展示当前阶段，切换时联动配置并保留已有数据；窄屏保持横向。完整的单一路径中，添加或移除整理步骤自动衔接后续关系，用户无需操作端口；业务步骤支持主表处理链逐张添加独立关联表，明确选择对应字段和关联方式后自动衔接，移除关联时一并移除专属来源。输入节点与内部编号留在高级编排。共享输入、多分支、关联表单独预处理、断线或循环等复杂关系不得自动简化，保留原方案并说明高级编排入口。高级编排继续使用现有画布和代码配置，切换视图保留当前草稿。业务视图窄屏采用页面自然滚动，避免步骤区和表单区多层滚动。

## 输入提示

- 所有文本、密码、数字输入框及下拉选择器都应提供符合字段语义的 placeholder；输入用“请输入/请说明”，选择用“请选择”，多选注明可多选。
- 编码、技术字段、数值范围等提供格式、边界或简短示例；有前置条件的选择器说明操作顺序。占位提示不代替字段标签、必填校验或已有默认值，不填写真实密码等敏感示例。

## 弹窗与目录挂载

- 尽量避免双层或多层弹窗。弹窗中的详情、诊断、选择和编辑优先在当前弹窗内切换内容、展开区域或分步展示，并提供返回入口，保留已填写内容和选择状态。内容复杂时进入独立页面，不继续叠加弹窗。确需二次确认的高风险操作可保留简短确认框；普通查看和操作不得以此为例外。修改相关流程时优先消除现有弹窗叠加。
- 表单、详情、审批及预览默认使用居中的 Ant Design Modal；长内容在弹窗内部滚动，保留关闭、校验和操作反馈。
- 弹窗的关闭、返回、取消、保存、检查、运行、发布和审批等操作统一放在右下角固定底栏，按16px间距靠右排列；不在标题栏或正文左下角重复放置。关闭入口也放入底栏，不保留右上角重复关闭图标，点击遮罩不关闭；可关闭时保留 Esc。共享交换与数据治理统一复用 PlatformDialog，治理专用的 GovernanceDialog 委托该组件，标题、正文间距和固定底栏采用同一套样式。长内容仅在正文区滚动，窄屏底栏靠右换行。字段增删、行内入口和分页控件保留在对应内容处。
- 目录行提供挂载资源入口，自动绑定当前目录并显示其挂载记录与维护操作，无须再次选择目录。目录草稿可先保存挂载；目录发布、字段校验和挂载审核通过后才能启用。

- 分步表单的标题、步骤导航和底部操作栏固定，仅中间表单纵向滚动；上一步、下一步与保存草稿在同一操作栏，避免表单横向溢出。
- 全局原生滚动条使用细、圆角、浅灰滑块及透明轨道，悬停加深；保留滚动和拖动能力，兼容浏览器原生细滚动条。

- 目录数据项在桌面端采用一行一项的紧凑编辑，窄屏自动换行。上一步、下一步及步骤导航切换均先校验当前步骤已定义的必填项，未通过时保留当前步骤并提示错误。

### 资源挂载交互补充（2026-10-16）

- 沿用目录行内「挂载资源」，不新增侧栏资源挂载入口。
- 居中对话框首先按数据库、文件、API 选择挂载方式，不再把“已有资源”或“新建治理成果”列为方式。数据库内默认连接库表，也可选择 Excel 上传导入数据库或平台库表；文件入口只上传完整文件资源，不导入库表。原始数据与治理成果均可接入库表或导入 Excel；目录载体和交付方式不兼容的入口禁用并说明原因。导航与底部保存操作固定，内容区单独纵向滚动。
- Excel 页面明确只导入实际数据：工作表/表头行 → 目录字段匹配 → 校验明细/有限样例 → 完整校验并导入 → 保存挂载。显示阶段文字与加载状态，不伪造百分比；超时可查批次状态。
- 文件资源不要求字段映射；完整文件下载、库表查询、API 调用使用独立操作按钮。API 使用界面只显示已获准的参数，不展示目标凭据。
- 表单使用本文件固定的15px/36px输入组件和14px/32px实体按钮，保留占位说明，不新增页面级字号规则。
