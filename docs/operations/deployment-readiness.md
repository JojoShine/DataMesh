# DataMesh 部署与升级说明

当前结构版本为48。原发行打包入口生成包含源码的离线交付包，不能直接作为生产服务器交付物。此次远程发布按 [deploy-standards](https://github.com/JojoShine/deploy-standards/blob/main/DEPLOYMENT.md) 接入 GitHub Actions／GHCR，服务器只接收部署配置及不可变产物，不上传业务源码或在服务器构建镜像。运行凭据、证书私钥、来源驱动、平台备份与业务数据不进入发行包；旧打包脚本现从完整配对的迁移文件自动取得结构版本，避免清单滞后。

## 目标环境

先确认`release.json`中的操作系统、架构与目标主机一致；本机验证不能替代另一架构的重建和联调。准备Docker Compose、可信TLS证书、固定访问域名及可访问的来源地址。`compose.yaml`默认只绑定本机端口，保持这一边界，通过既有可信代理或受控转发访问；设置与实际访问地址一致的`APP_ORIGIN`。组件版本以`deploy/versions.lock.json`和Compose固定引用为准，资源预检沿用`scripts/dev-env.sh preflight`。

本批没有国产库真实联调实例。达梦、金仓、瀚高、海量的目标版本、驱动授权、兼容模式和认证仍需在目标环境验证；不得把连接器配置可选当作已通过生产连接。Doris等分析组件及来源数据库应分别确认网络与数据持久化。本Compose不是高可用部署承诺。

## 校验发行包

```sh
shasum -a 256 -c <发行包名称>.tar.gz.sha256
tar -xzf <发行包名称>.tar.gz
cd <发行目录>
```

读取`release.json`后，逐文件核对摘要；镜像包含时执行`docker load -i application-image.tar`。将其中`application_image`对应的已核对镜像打为Compose使用的`datamesh-server:0.1.0`。目标架构不同应使用匹配架构重建及重新验证，不能直接沿用本机镜像。

已有环境保留`.local/runtime.env`、加密密钥、签名密钥版本、代码运行令牌、可信证书和固定来源配置，权限目录700、文件600。通过运维受控渠道单独转移，不把它们放入公开工件或聊天。尤其不能重置`CREDENTIAL_KEY`、水印历史验签密钥或来源凭据。全新环境可运行`scripts/dev-env.sh init`生成私密配置，再配置实际域名、证书、来源和所需驱动；不要用shell执行环境文件内容。

## 升级已有平台

1. 暂停外部提交和调度派发，在无活跃数据流、工作流、ETL和流任务时进入维护窗口。记录当前应用镜像、干净结构版本及恢复点；不通过删除任务或命名卷腾空状态。
2. 一致备份平台PostgreSQL、来源数据库、Doris成果及对象存储；如启用流处理，同时保存Kafka位点、Flink状态和保存点。保留私密配置及初始化账本。先在独立环境还原并核对，不能只确认备份文件存在。
3. 停止应用，独立运行迁移。迁移45→46只追加替代链字段和状态，不重写原问题证据。

```sh
docker compose --project-name datamesh --env-file .local/runtime.env stop server
docker compose --project-name datamesh --env-file .local/runtime.env run --rm migrate
docker compose --project-name datamesh --env-file .local/runtime.env up -d --no-deps --force-recreate server
```

4. 检查`/health/live`、`/health/ready`及干净结构48；使用受信任证书访问，检查首页资产、登录、目录浏览、来源字段、治理空间、既有成果、轻量治理中的SQL数据沙箱和变更单。不能以返回首页HTML代替业务接口检查。
5. 执行下面的增量初始化并核对实际试跑。独立业务审核和主体确认仍由人员办理；确认后再恢复正常派发。

全新平台应先启动并验证PostgreSQL、来源、对象存储、Doris、代码运行与所需读取组件，运行全部迁移，再启动应用。不要在已有业务库重复执行来源导出的建表SQL。

## 初始化与迁移后的续执行

全新环境按顺序：

```sh
python3 scripts/initialize_business_scenarios.py --initialize
python3 scripts/initialize_governance_scenarios.py --initialize
python3 scripts/initialize_governance_readiness.py --initialize
```

迁移已有环境时，平台和来源账本、成果、权限、运行证据必须一起恢复；只运行未完成的初始化步骤。每个脚本按账本幂等续执行，不以清除检查点解决失败。恢复源地址变化时，先更新获准目标、连接配置及契约，再重新验证引用和加工授权，不修改历史指纹伪装为未变化。六类源数据为固定截至2026-10-31的虚构业务快照，共21张表、75,300条；不是实时业务数据。详见`governance-initialization.md`。

本次补充形成六个增强流程试跑、六个模型修订及对应12份新审核材料。既有6份指标变更继续等待独立审核；主数据候选不自动确认。流程审核通过后可用新版本重新运行，模型审核后需要显式绑定版本，成果仍须核验、登记和授权交付。

## 回退与恢复

优先保留数据库46结构并回滚到升级前应用镜像；本批迁移是向后兼容的追加结构。先停止派发、记录失败诊断，再切回已留存镜像并验证健康和只读业务。应用回退不会删除新产生的整改、确认或发布记录。

只有确认没有`superseded`或替代引用等新证据时，迁移46的down才允许移除追加结构。已经产生新证据会主动拒绝结构降级；不得改约束或删证据强行回退。需要恢复数据库时，停止写入，按同一恢复点恢复全部关联存储和原密钥，核对来源摘要、成果、权限及初始化账本后再开放。

升级前备份恢复演练、干净结构down/up演练和新证据拒绝down应在独立副本执行，不能把生产库当作演练目标。

## 交付后的业务核对

- 问题复测保留原参数和输入绑定；修改依据走“已替代”，原异常不被标成合格，仍异常必须有后续工单。
- 主数据按未确认筛选、预览、核对来源并填写原因后确认；跨来源敏感占位值不自动判同。
- 中文字段标签、业务含义和固定标准版本可查，旧模型和公开成果不被修订覆盖。
- 通知可按已读/未读筛选，阅读后保留首次阅读时间，刷新同步加载。
- 用两个不同的有权账号完成申请、独立审核、交付及撤权核对，不代替真实业务审批。

## 现有数据真实业务体验（显式full）

主入口18443可通过 `PUBLIC_TEST_ACCOUNTS_FILE` 指定的配置，将专用公开体验身份设置为 `mode: "full"`。最多4个账号、配置最多16KiB，支持两个既有数据部门各自的操作与独立复核岗位。只接受持久标记public_test、活跃、版本匹配且具备非管理员业务岗位的专用身份；现有私有账号与管理员凭据不展示。

每次认证核验当前配置、标记、版本和岗位。有效full身份返回 `full_experience=true`，页面显示“真实业务体验”，直接使用现有数据和服务器工作空间，执行实际查询、治理、加工、申请与交付。正常平台、岗位、具体资源授权、独立复核、脱敏、安全策略、CSRF与审计继续生效。标记丢失立即拒绝登录及旧会话，且不创建新会话；版本或角色漂移回收真实业务能力。

full账号使用既有异常阻断：每分钟600请求、240写、最多8并发写；一分钟20次越权写触发30秒写冷却，普通读取继续可用，请求洪泛则暂限全部请求。计数不授予额外权限。账号管理及管理员操作保持拒绝。

本机已按用户授权开放现有资源，通过正常岗位授权和独立审批建立体验访问，不复制或重置原业务数据。原只读模式仍是缺省配置，见下节。修改公开账号后应重新核对配置版本；转换为私有身份前应撤销会话、移除公开配置并更换已公开密码。

## 登录页默认只读测试账号（按需启用）

需要供用户测试时，在身份服务和来源初始化就绪后执行：

```sh
python3 scripts/initialize_public_test_account.py
docker compose --project-name datamesh --env-file .local/runtime.env up -d --no-deps --force-recreate server
```

脚本生成独立的 `experience_viewer` 体验身份，服务端保留public_test持久边界与consumer角色。四个平台显示完整菜单；共享、资产、安全继续只读。治理使用当前浏览器独立的体验空间，可编辑配置、保存版本、关联与处理示例数据，不能修改正式业务或读取真实来源。密码随机生成，保存在忽略目录；不公开已有业务账号或管理员凭据，也不写入发行包。登录页展示账号、密码、体验范围，点击“填入账号”后仍需用户主动提交正常登录。

公开配置位于 `.local/public-test-accounts/accounts.json`，由 `PUBLIC_TEST_ACCOUNTS_FILE` 指定。默认不配置时返回空列表并不显示账号面板；只有已持久标记为public_test、活跃、版本匹配、角色恰为consumer且平台限定exchange/assets的账号才展示。停用或修改账号版本/权限后提示停止展示。移除环境变量并重建服务可关闭展示；结束体验时还应在账号管理中停用该共享账号，失效现有会话。不要将共享体验账号用于个人、敏感资料或真实业务审批。

迁移已有体验环境时，单独保留账号初始化记录 `.local/public-test-account-provisioning.json` 及公开配置目录，不在已存在同名账号但缺少原记录的环境中强行重建或修改密码。全新部署重新运行脚本生成自己的密码。运行所需可信证书及`APP_ORIGIN`应已正确配置。


## 默认只读账号的强制安全边界（结构47）

体验账号在服务端仍为持久标记的只读身份，不具备普通consumer账号的业务接口能力。标记保存在用户记录，关闭登录页提示、增添角色或直接调用接口均不能绕过。身份接口仅放行查看本人登录状态和退出；四个平台入口及平台切换展示完整菜单、分类和原业务页面，不再替换为精简体验页。共享、资产与安全的提交由前端和服务端分别拦截；治理体验的允许操作在浏览器本地处理，不调用正式写入接口。目录与资产页面仅从公开目录接口读取已审核信息；内部管理、审计、账号和运行记录显示“未公开”，不伪装成零条数据，不获取内部接口，也不提升实际角色。源数据查询/下载、申请、SQL、上传、脚本、任务、授权与配置操作在服务端拒绝。

升级已存在体验账号时，迁移47后使用新版本管理程序执行 `restrict-test-user`，永久收紧身份并失效旧会话，再更新公开配置版本。初始化脚本包含此步骤。普通用户默认不设置该标记，原有工作流和审批权限不变。

公开账号登录每账号每分钟最多10次；认证请求按该账号跨IP累计每分钟最多60次；公开资产与测试账号提示接口每来源IP每分钟最多60次。超限返回429和Retry-After。以上为单服务进程限流，不能替代公网入口防护，也不能保证免受分布式拒绝服务攻击。

当前Compose应用端口和数据库端口绑定127.0.0.1，不直接改为0.0.0.0发布。正式开放时仅经可信HTTPS入口代理，并配置统一限流/连接和请求体上限；数据库、对象存储管理口、Doris、源读取和代码运行组件不向公网开放。多实例或共享代理出口应在入口统一计数，按目标网络配置可信代理范围，不信任任意客户端传入的IP头。

安全边界存在时禁止结构降级删除标记。若必须回滚到不认识该标记的旧应用，先停用公开体验账号并撤销会话，不能仅隐藏提示后启动旧版。实际公网域名、入口和防火墙尚未指定，本机只验证应用侧限制，不表示已完成公网抗攻击或渗透测试。

入口部署依据：[Docker端口发布边界](https://docs.docker.com/engine/network/port-publishing/)、[Nginx请求限流](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html)。本机未配置目标公网入口，以上入口策略需在实际部署环境落地和验证。

## 默认只读配置的浏览器治理体验空间

公开测试账号进入治理后自动打开本浏览器的“治理体验空间”。内置80条居民信息和100条报名登记的虚构样本，可用于清理文字、筛选、去重、关联、整数汇总、质量分流、字段检查、模型/标准/术语配置和普通数据流工作流运行。版本、输入、处理计数、输出和质量趋势保存在当前浏览器，不是服务器业务运行证据，不与其他访问者或设备共享。

轻量治理可以在浏览器导入UTF-8 CSV，每份最多1 MiB、50列、1000行，每个单元最多8份；每次处理最多1000行、30个节点，工作流最多10个普通数据流任务。本地记录总大小限制3 MiB。导出的CSV对可能成为公式的文本作安全处理；文件与计算结果不会上传正式服务。

主数据匹配确认、指标专用计算、持续监测、自动保留清理及真实审批需要正式治理环境；体验空间可以维护相关配置。自定义Python/JavaScript、自定义正则标准、外部连接和回调、持续任务、后台定时调度、物理部署及正式发布审核不在该空间执行。普通账号仍使用原接口和权限。页面的“治理体验 · 当前浏览器生效”标记与“重置体验空间”入口用于说明范围和清理本地数据；重置需要再次明确点击确认，不删除服务器数据。

## 智能问数悬浮入口（预留）

首页、操作指南与四个平台显示统一的右下角智能体图标；登录页不显示。点击可展开AI智能问数的待接入说明，关闭或按Esc返回入口。业务弹窗打开时隐藏入口，治理固定操作栏出现时自动留出位置；窄屏及安全区域保持可操作。当前不接入模型或数据库、不发送问题、不创建问数会话。


## 2026-11-11 完整体验与安全扩展

完整体验使用[独立环境部署说明](../isolated-experience.md)的单独Compose项目和19443入口，保留主实例18443的public_test身份边界。全部配置、账号、密钥、数据库、对象存储、消息队列、运行状态及样例源独立，不从正式库复制数据。正常身份走真实接口和独立审批；不再依赖浏览器本地模拟完整业务。

应用新增SESSION_COOKIE_NAME隔离同主机不同端口的会话；只接受默认datamesh_session及datamesh_experience_session。体验部署使用后者。Doris FE支持DORIS_PRIORITY_NETWORKS独立私有/24网段，默认主实例网段不变。

受控下载支持PDF逐页中文内容水印（32MiB、200页）、Excel说明页/页眉，以及PDF页面内容和Excel包内的隐式溯源标识。标识HMAC绑定交付主体、资源版本、密钥版本和交付编号；最终文件SHA256和签名在实际副本生成后记录。提取接口要求登录、CSRF、凭据访问权限，串行限制并发，临时上传不写入对象存储；支持PDF32MiB、Excel64MiB。标识不承诺抵抗任意编辑，签名匹配不单独认定接收完成或责任归属。

行过滤为绑定资源版本的类型化AND谓词，不执行用户SQL；值使用参数绑定，并在分页、脱敏和ETL转换前执行。当前支持原生数据库表查询/ETL、Doris治理成果查询、未映射数据服务查询。未实现过滤的载体、继承转换、文件下载及维护预览会拒绝交付，不能用后置裁剪或返回空结果冒充过滤。MySQL/Oracle/Doris的实际过滤运行仍须在完整环境进行验收；PostgreSQL已使用隔离数据库验证。

默认方案已改为轻量独立应用、业务元数据库、对象存储与会话，Doris复用计算但使用独立命名空间、服务身份及工作组预算；代码、流式组件和其他来源按需启用。完整复制全部组件是可选模式，其内存上限合计不是本机体验的最低内存要求。实际容量与业务验收以轻量环境的preflight/up/bootstrap/verify为准，不能在验证完成前宣称可用。
