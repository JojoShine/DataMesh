# 六类业务治理配置初始化

版本：2026.11.9。依赖业务来源初始化2026.11.1及数据库迁移45。

在已配置管理员和运行环境的新平台，依次执行：

```sh
python3 scripts/initialize_business_scenarios.py --initialize
python3 scripts/initialize_governance_scenarios.py --initialize
```

治理脚本复用业务初始化登记中的21张表、六个空间与现有资产流程，不执行来源建表、数据替换、账号创建、授权或资产下架。初始化账本保存在`platform_initializations`的`municipal-governance-scenarios`项，私密本机检查点位于`.local/governance-initialization/2026.11.9/`。每个成功步骤即时保存；失败后核对诊断并重跑原命令，复用已登记的定义及运行，不删除账本或重复建立对象。

六个空间分别追加编号标准和关联模型、完整落标核验、每日监测及实际基线、分类统计口径和真实计算、可复用关联治理方案。人口和法人追加主体模型、主数据精确匹配及候选。示例记录为按业务结构生成的虚构数据，不使用真实自然人资料。

初始化不会替人员确认主体，也不会伪造独立审核。六份统计口径说明修订完成实际完整试跑后，保持“等待审核”。实际治理人员应在主数据候选中逐项确认；另一位有权治理人员在变更发布核对试跑、变更与使用范围后办理审核。审核前原版本继续保留。

六个空间完成初始配置后，数据模型、数据流、工作流、主数据、场景方案启用独立审核策略；后续直接发布也执行该策略。共享标准、术语及元数据继续按原全局权限管理。平台原有其他空间保持原策略，不扩大跨部门权限。

迁移已有平台，应同时恢复平台PostgreSQL、来源PostgreSQL、Doris及对象存储，并安全转移私密运行配置。平台账本、来源摘要与已完成运行一同迁移后，运行匹配版本脚本核对续执行。不得只复制本机检查点，不得在已有业务库直接运行导出的建表或替换数据SQL。独立主数据快照必须连同匹配运行、候选和不可变确认版本一并迁移；只有原来源及派生权限仍有效才能继续计算；登记和交付继续核对原来源允许共享的有效批准依据。

失败后保留账本及原运行，先查诊断，不删除步骤重建资产。不把试跑成功当作审核，不代替人员确认12,000个主数据候选。
