# 共享交换操作指南

共享交换负责接入数据、维护资源目录、办理加工和使用授权，并把治理后的数据提供给需要的部门。按本次工作选择下方流程，无须先完成所有菜单。

## 先判断要办理什么

- **提供数据**：登记数据源 → 确认资源可用 → 维护目录和挂载 → 提交审核 → 启用共享。
- **整理和治理数据**：确认来源和字段 → 取得数据加工授权 → 进入数据治理系统处理 → 核验成果 → 回到共享交换关联目录。
- **申请使用数据**：查找已发布目录 → 选择原始或治理后资源 → 填写用途和所需字段 → 提交申请 → 获批后按授权使用。
- **持续同步数据**：根据来源条件，选择 CDC 接入任务或 ETL 数据交换，检查真实运行和交付结果。

## 账号与职责

操作菜单随账号的平台权限、角色和资源职责显示。看得到入口，不代表已经拥有某份数据的读取或加工权限。

- 数据源登记、CDC 与 ETL 通常由接入运维人员办理。
- 原提供部门维护目录、资源挂载并办理本部门相关审批；具体以账号分配的职责为准。
- 治理人员需要取得来源和字段的加工权限，才能在治理空间中使用。
- 使用方只能查询和交付授权范围内的数据。

找不到操作入口时，请让管理员核对账号的平台权限、角色和相应资源职责，不要重复创建目录或数据源。

## 登记数据源

入口：[数据源管理](/platform/exchange/sources)。

1. 新建数据源，填写名称、连接方式和所需连接信息。按分类选择数据库类型；文件或 API 资源在目录挂载时另行登记。
2. 执行连接测试，按诊断修正网络、账号、凭据或访问范围。
3. 选择实际需要接入的对象，确认字段、类型和业务含义。
4. 保存登记，并确认资源已达到可使用状态。登记成功不等于已经完成目录发布或共享授权。

密码和访问凭据只填在专用表单中，不写入资源名称、目录说明或申请材料。

### 可接入类型与能力

- 通用关系型：PostgreSQL、MySQL、Oracle、SQL Server。
- 国产数据库：达梦 DM、人大金仓 KingbaseES、瀚高 HighGo、海量 Vastbase。
- 分析型数据库：Apache Doris、ClickHouse。
- 非关系型：MongoDB、Elasticsearch、Redis、HBase。

管理员先在“可信数据源”登记准确的类型、地址、端口和数据库范围，再登记连接。新增类型采用只读接入：测试连接 → 查看对象与字段 → 在原目录挂载 → 预览或申请加工 → 治理与质量检查 → 发布成果；已挂载资源也可作为 ETL 的授权输入。它们暂不支持 CDC、写回目标库或模型建表，不需要为同一数据的接口形式另建目录。

单次接入上限为 10,000 条、20 MiB、100 个字段；超限会明确失败，请在源端整理成适量的业务表、集合或索引。预览仍需完整读取并检查上限，不会把前 10,000 条冒充全量。普通数据库表需要真实主键才能直接挂载为共享资源；ClickHouse 的排序键不视为唯一主键，可通过治理输入形成成果。

MongoDB 使用集合，认证库可单独填写；Elasticsearch 使用单一索引或别名；Redis 使用 0–15 逻辑库（暂不接入 Cluster）；HBase 使用 REST 网关和命名空间，暂不支持 Kerberos。HTTP 来源以及 MongoDB、Redis 按页面选择 HTTPS/TLS 或普通连接；TLS 校验证书，SQL Server 默认使用证书校验。

MongoDB、Elasticsearch、HBase 保留 `record_key` 与完整 JSON `document`；Redis 另有 `value_type`，支持字符串、哈希、列表、集合、有序集合、流。二进制内容以 Base64 保留，治理前可按业务规则提取 JSON 字段；授权按实际列处理，不会把嵌套键自动当成独立授权字段。实时来源读取不保证跨记录的事务快照，变化或部分响应会尽可能阻断，但关键业务应先在源端准备稳定数据版本。

国产数据库需安装对应版本的官方 JDBC 驱动。页面会区分读取服务未就绪、驱动缺失和驱动损坏；驱动就绪不代表已验证目标库的版本、兼容模式或国密认证。正式接入前应使用实际实例验证连接、字段类型和业务数据。

## 选择 CDC 或 ETL 同步

### CDC 接入任务

入口：[CDC 接入任务](/platform/exchange/tasks)。适合需要持续捕获数据库变化、且来源满足接入条件的场景。

1. 选择已登记的数据源和需要同步的对象。
2. 按页面诊断完成来源侧条件准备，检查连接、日志与权限等实际要求。
3. 核对任务配置并启动，查看运行状态、异常与进度。
4. 核对下游实际结果，不能只凭“任务已保存”判断数据已经同步。

来源条件不满足或当前类型不支持时，先处理诊断提示，不能把示例或就绪检查当成已经创建的真实同步任务。

### ETL 数据交换

入口：[ETL 数据交换](/platform/exchange/etl)。适合按任务批量抽取、转换和交付数据。

1. 选择来源、目标以及本次处理范围，配置字段映射和必要转换。
2. 检查配置与权限后执行任务。
3. 查看实际运行、交付回执和对账信息，确认处理条数及失败原因。
4. 出现异常时先定位本次运行，再修正配置并按页面支持的方式重试。

## 编目前先核对组织和编码规则

管理员在[组织与部门](/platform/security/organizations)核实组织全称和正式单位代码，并在[人员与账号](/platform/security/accounts)维护人员归属。新建目录会自动带入所属组织信息；代码缺失时可以先保存草稿，再请管理员补录。

目录主管进入[目录编码配置](/platform/exchange/directory-coding)，为已核验字典维护生成模板和流水号位数。`{provider_code}` 表示所属组织正式代码，`{sequence}` 表示服务端分配的唯一流水号。模板必须符合该字典的实际规则；平台不会从校验正则猜测国家编码规范。未配置时可保存未编码草稿，配置完成后再次保存获得编码。

分类路径从所选字典选择；更新周期使用选项，表示约定的数据更新频率，不代表自动创建了采集或调度任务。资源编码在保存草稿时生成，已发布编码不变。各字段下方或标签旁的提示解释业务用途，数据项区分面向业务展示的名称和用于挂载映射的技术字段。

## 维护资源目录与挂载

入口：[资源目录](/platform/exchange/directory)。发现和申请使用数据看“已发布目录”，提供部门维护资源看“目录维护”。

1. 在目录维护中新建目录，填写业务名称、说明、分类、共享属性、数据项和责任信息。
2. 保存草稿后，从对应目录行打开“挂载资源”，选择真实资源并配置目录数据项与实际字段的对应关系。
3. 执行字段和挂载校验，处理名称、类型或字段范围不一致的问题。
4. 提交目录和挂载审核。目录发布、挂载审核通过及其他启用条件满足后，启用挂载。
5. 回到已发布目录，核对显示内容和资源可用状态。

目录说明“这份数据是什么”，挂载说明“这份目录对应哪项真实资源”。保存草稿和审核通过各有独立状态；没有启用的资源不能当成已可共享的数据。

## 审核目录和挂载

入口：[目录与挂载审核](/platform/exchange/reviews)。

1. 打开待处理事项，核对目录内容、数据项、真实资源和校验结果。
2. 材料不充分时按页面能力退回补正，并说明原因。
3. 审核通过后，再核对目录是否已发布、挂载是否已启用。
4. 修改已发布内容时，按修订流程办理，避免直接改变已经形成的共享和授权依据。

审核职责和申请维护职责分别检查；不能通过反复提交绕过审批要求。

## 取得数据加工授权

入口：[数据加工授权](/platform/exchange/processing)。这是供治理处理数据使用的授权，与最终使用方的数据使用授权分别办理。

1. 明确准备加工的来源、字段、用途和有效范围。
2. 由来源责任部门的审批人员点击“批准加工授权”，选择执行人、来源目录及表、文件或接口资源，核对契约版本和允许处理的字段，填写用途、期限及批准记录。历史原始对象可切换来源选择方式办理。需要形成治理成果时，还须批准允许派生；对外共享另需相应依据。
3. 获得有效加工权限后，到数据治理的治理空间中添加来源。
4. 来源或字段范围发生变化时，重新检查授权，不要默认新增字段也已获准加工。

能查看目录或字段说明，不代表能读取或加工数据。治理空间也不会自动授予来源权限。“版本一致”仅说明来源结构与引用契约一致。

管理员按现有平台权限直接治理，不会因此自动产生数据使用申请或加工授权记录；普通治理人员实际读取和处理仍须通过上述加工授权校验。

## 申请和使用数据

入口：[资源目录](/platform/exchange/directory)、[数据使用申请审批](/platform/exchange/applications)、[数据使用授权](/platform/exchange/grants)。资产使用者也可在[资产发现](/platform/assets/catalog)查看已共享的原始数据、治理成果、文件和 API，在[我的申请](/platform/assets/applications)跟踪审批，在[我的资产](/platform/assets/grants)查询、下载或调用。三个入口复用这里的同一份申请与授权，无需重复申请。

1. 在已发布目录中找到所需数据，阅读用途、提供部门和使用限制。
2. 同一目录有原始资源和治理后资源时，选择本次真正需要的一份。治理后资源会说明来源以及治理了哪些内容。
3. 选择所需字段，填写使用目的、范围、期限和页面要求的材料，再提交申请。
4. 在“我的申请”跟踪状态。需要补正时，补齐材料后重新提交。
5. 审批通过后，到数据使用授权中查看生效范围，按获准字段、期限和交付方式使用。

不同资源各自形成申请和授权依据。获得原始资源授权，不等于自动获得治理后资源授权，反过来也一样。

## 治理成果如何关联目录

单表质量治理完成后，成果仍归属于原提供部门。原始数据和原目录保留，治理后数据作为可单独申请的一项资源提供。

1. 在数据治理的“成果核验”中核对本次成果，确认质量、完整性和有效期，并由具备职责的人员完成成果发布。
2. 在共享关联选项中，默认选择“关联回原目录”；有独立业务分类需要时，也可选择“新建目录”。
3. 进入对应目录的挂载表单，核对治理后数据的字段映射、版本和治理说明，提交既有校验与审核流程。
4. 挂载启用后，在原目录中分别查看原始资源和治理后资源，并按选中的资源申请使用。

多来源关联成果可能没有唯一原目录，应结合成果用途选择合适目录，不强行归到某一个来源目录。历史成果没有记录原目录时，也应先确认来源和业务归属。

## 常见问题

### 目录已发布，为什么仍不可用？

检查真实资源是否就绪、挂载是否完成校验和审核、挂载是否启用，以及资源版本和授权是否仍有效。目录发布本身不会完成这些步骤。

### 为什么治理人员看得到数据，却不能加工？

查看元数据、读取数据、加工字段和维护资源是不同权限。请核对具体来源及字段的加工授权，再检查治理空间中的来源是否有效。

### 已经审批通过，为什么仍不能使用？

检查申请选中的真实资源、获准字段、授权期限、资源当前状态及交付方式。不要把另一份资源或旧版本的授权用于当前数据。

### 从哪里继续数据治理？

阅读[数据治理操作指南](/guides/governance)，再进入对应治理空间处理。操作指南只提供说明，实际校验、审批和授权始终以业务页面为准。

## 与治理批流处理的分工

共享交换的 ETL 用于按需或定时把授权数据搬运、映射到指定目标；CDC 用于持续采集来源的变更日志并写入 Kafka。需要清洗、质量检查、多表关联、统一口径或生成模型时，到数据治理的数据流处理：批量由 Doris SQL 执行，持续更新由 Flink 执行，最新治理结果统一落入 Doris。

治理成果经过核验发布后，再回到共享交换关联目录、挂载和申请使用。ODS / DWD / DIM / DWS / ADS 是技术数据分层，原提供部门和业务目录不会因此改变。RustFS 保存按需生成的固定快照，适合文件交付和归档；实时使用应读取 Doris 成果。

## 把治理成果提供为查询接口

在“数据共享与服务 → 数据服务”新建服务。数据治理负责产出和核验结果，共享交换负责定义对外查询、审批授权及调用审计；同一成果可以分别按库表、文件或 API 交付。

1. 选择有管理权限、已核验并发布的 Doris 治理成果。
2. 定义服务名称和查询。`result` 代表所选成果，例如 `SELECT code, name FROM result WHERE code = :code`。参数由平台识别，调用者只能传声明的参数，不能传入 SQL。当前支持单成果字段选择或 `SELECT *`、一个结尾分号、AND 比较条件和单字段排序；跨表关联、聚合等先在数据流完成。
3. 选择固定成果，或跟随同一数据流最新的已发布成果。自动更新要求完整字段契约不变、来源授权仍有效；不兼容的新成果会停止接口查询，需重新校验发布。连续分页始终读取同一次成果。
4. 填写校验参数，例如 `{"code":"001"}`，点击“校验并预览”。参数值使用文本；日期时间按 UTC 处理。
5. 选择来源成果已经挂载的业务目录，不需要另建 API 目录。SQL 可以返回该目录已审核数据项的子集，不能扩大字段范围或降低敏感级别。库表和接口共享业务目录，但各自保留挂载、审核、字段范围和使用授权。
6. 登记接口后，进入对应目录的“挂载资源 → 选择已登记资源”，选择刚登记的服务，按接口实际输出完成字段映射、挂载审核和启用；已发布的业务目录无需因新增接口重复编制。登记成功本身不会开放访问。原来源共享暂停或版本变化时，对应接口也会阻断，不能绕过来源约束。
7. 使用方从目录申请数据使用授权。审批通过后，在“数据使用授权 → 调用 API”测试查询或创建外部调用凭据。

外部程序使用 HTTPS，向 `/delivery/v1/services/{接口编号}/invoke` 发送 POST，请求头为 `Authorization: Bearer <调用凭据>` 和 `Content-Type: application/json`。请求包含 `contract_version: 1`、`parameters`，可选 `fields`、`page_size`。响应 `records` 仅含获批字段；若 `next_cursor` 非空，保持参数和字段不变，将其作为下一次请求的 `cursor`。

凭据完整内容只显示一次，平台仅保存哈希。凭据绑定账号、接口和签发时的授权，最长 90 天，且不超过原授权有效期；撤销后不可恢复。重新申请授权后需重新签发凭据。每次调用复核账号、部门、字段、授权期限和共享状态，敏感字段沿用现有脱敏策略。当前授权范围为资源、字段与期限；参数化查询不是逐用户行级授权策略。

接口每页最多 1000 条，由提供方设置上限；默认每页不超过 50 条，单页最多 8 MiB，查询超时 8 秒，每账号每接口每分钟最多 60 次，单实例最多 8 个并发查询。收到 429 后稍后重试。来源下架、共享暂停、授权撤销或成果契约改变时，调用会被拒绝。

已登记接口不覆盖修改。使用“复制为新接口”调整查询或来源，再完成新的挂载审核与授权，原接口保持原有查询及权限范围。已有“接入外部 API”仍用于登记其他系统提供的接口，两种方式互不替代。

## 从数据资产发现并使用

1. 进入“数据资产 → 资产发现”，按名称、资源编码或分类查找已共享目录。未共享的内部数据不进入此列表。
2. 打开详情，查看提供单位、更新周期、共享条件和字段。原始数据与治理成果分别选择；治理成果展示已有治理说明和质量结论，未提供结论不会显示为质量通过。资源信息更新时间不等于实时数据采集时间。
3. 选择数据并填写使用用途、依据、字段和期限。申请提交给共享交换的资源负责人，不能自行批准；只开通资产平台的使用者也可办理。
4. 在“我的申请”查看状态、处理意见，按要求补正材料或撤回申请。审批通过后进入“我的资产”。
5. 根据获批交付方式查询数据、下载文件或调用 API。平台生成的数据服务可在调用窗口创建、查看和撤销本人的调用凭据；凭据只能在创建时复制，后续调用仍受原授权的字段、期限与共享状态约束。

“我的申请”和“我的资产”只展示当前账号的记录。授权过期、撤销或共享暂停后不能继续使用；版本或共享条件变化时，返回资产发现核对后重新申请。数据提供方仍在共享交换维护目录、审核申请，治理人员在治理平台处理和核验成果。

## 业务初始化与迁移

初始化准备招生报名、人口基础库、法人基础库、死亡人口专项库、矛盾调解和不动产数据应用六个场景。来源包含21张关联表，每表1,200–9,000行，总计75,300行；人口编号、监护人编号、主体编号和不动产单元编号可用于跨场景关联。业务名称和字段值采用自然表达，记录为虚构业务样本，来源性质和版本保存在初始化清单。

管理员按部署说明执行 `scripts/dev-env.sh initialize-business`，先完成平台结构迁移，再初始化来源、目录、治理空间及已发布成果。重复执行会核对内容摘要并复用已有对象；发现人工维护过的源表时停止覆盖。旧初始化条目退出在用目录，保留历史运行和审计。

迁移现有环境时，平台库、来源库、Doris、对象存储和私密运行配置需一起备份恢复。初始化进度随平台库迁移，来源版本随来源库迁移；在目标环境运行同一初始化命令核对及续执行。干净环境可以根据版本重新生成基础业务记录，不能用初始化替代真实业务数据备份恢复。
