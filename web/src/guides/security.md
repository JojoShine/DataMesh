# 数据安全操作指南

数据安全围绕具体资源版本，管理分类分级、人员职责、防护策略、水印、风险处置和审计。它与共享交换、数据治理、数据资产共用资源和授权记录。配置安全策略不会生成数据使用授权，操作指南也不会自动执行任何安全配置。

## 开始之前与职责

管理员维护安全配置、执行扫描与预检、处置事件。审计员按获准入口只读核查，不自动取得取数或处置权限。资源负责人可从资产详情进入该资源版本的标签维护，后台分别核对管理和复核职责；进入安全平台并不等于具有每项资源的使用权限。

安全标签、识别规则、防护策略、水印模板和风险规则采用“保存草稿 → 提交复核 → 另一位有权人员批准发布”的流程。当前版本作者不能批准自己的版本；修改已发布配置时先新建版本，新草稿不替换仍在生效的发布版。每次提交、批准、退回或停用都要说明原因。

使用功能前确认选中了正确的资源类型、资源编号和版本。需要两人复核时，应由管理员按实际职责配置另一位有权人员，不能通过重复点击或更换草稿绕过分离要求。

## 先看安全工作台

[安全总览](/platform/security/overview)展示已发布标签、策略、水印模板、待复核版本、冻结事件与交付凭据。统计仅覆盖平台已有记录；没有采集的外部数据库访问不会被解释为风险评分。

先查看待复核项和冻结事件，再按业务进入对应分类。页面同时显示签名配置与当前能力；不可用时先核对运行配置，不能把“没有凭据记录”理解成已完成安全验证。总览中的数量也不等于所有资产都已完成分级。

## 分类分级与识别

1. 管理员进入[识别规则](/platform/security/recognition)，点击“新建识别规则”，填写名称、说明、安全级别和字段名称正则表达式，例如 `(?i)phone|email`。保存草稿并提交复核，由另一位管理员批准发布。
2. 进入[扫描与结果复核](/platform/security/scans)，点击“扫描资源”，搜索选择目标资源版本，再点击“开始识别”。扫描只检查字段元数据及已有敏感标记，不读取业务样本。
3. 点击扫描记录，核对候选字段、建议级别和规则依据。候选不会自动改变分级；名称匹配也不能证明实际数据一定敏感或不敏感。
4. 点击“为此资源起草安全标签”，或在[安全标签](/platform/security/classification)新建标签。填写名称、说明及安全级别；选择字段表示字段标签，留空表示资源标签。
5. 点击“保存草稿”，查看范围后“提交复核”。由另一位有权人员核对并“批准发布”，或填写依据“退回”。批准后才按发布标签执行保护；错误候选不要直接批准。

公开、内部、敏感、高敏是本项目业务分级口径。公开和内部仍检查原有授权，敏感字段按复核标签保护，高敏默认禁止下载、API与ETL外发；未分级保留原有敏感保护。“公开”标签本身不会让资产出现在匿名首页。

新资源版本不能静默沿用旧保护结论；存在旧版本标签或策略时须更新并复核对应范围。存量治理成果按字段血缘继承来源保护；缺少字段血缘时采取保守的整行字段保护。

## 身份与权限

### 组织、部门与人员

管理员从侧栏“身份与权限”进入[组织与部门](/platform/security/organizations)和[人员与账号](/platform/security/accounts)，也可从右上角账号菜单点击“组织与人员管理”。普通账号不能进入管理页面。

1. 先新增组织，填写完整名称及经核实的正式单位代码。历史部门标识已保留；尚未核实的单位代码可留空，不能用猜测值代替。
2. 新增部门，选择上级组织或部门，支持多级结构。所属层级创建后固定；名称和代码可维护，存在在用人员或下级部门时不能停用。
3. 在人员与账号中新增人员，填写登录账号、姓名及初始密码，从组织树选择归属，再配置平台入口和业务角色。一套账号共用四个平台。
4. 点击“维护人员”调整姓名、所属部门、平台或角色，并说明原因。修改后相关账号需要重新登录；调岗会撤销原资源范围和加工授权，需按新岗位重新配置。原资源、目录和审批历史仍归原部门。
5. 禁用账号会使现有会话失效；恢复使用时点击“启用账号”并填写原因。所属单位必须在用，系统禁止当前管理员禁用自己或取消自身管理角色。

目录的提供单位名称和代码取人员所属组织；组织资料修改不会直接改写已发布目录，应通过目录修订和审核更新。开通平台、配置角色、授予资源范围和批准数据使用是分别办理的权限事项。

### 资源权限与加工授权

在[资源权限](/platform/security/resource-access)的“岗位范围”页，管理员点击“配置岗位范围”，选择账号、部门、具体资源或部门资源范围、岗位职责、配置依据和有效天数。岗位涵盖资源管理、接入运维、治理质量、目录与挂载审核、共享审批等；岗位只授权相应管理操作，不直接授予数据使用权。

切到“加工授权”，由有权人员点击“批准加工授权”，选择来源目录、具体资源版本、加工执行人、字段、用途和期限，填写来源责任部门批准记录。需要形成成果时明确允许派生；需要共享成果时还应明确相应依据。普通账号不能批准自己的加工授权。已不再需要的有效岗位或加工授权，可从对应记录撤销并说明原因。

### 数据使用授权核查

在[授权管理](/platform/security/grants)按现有权限核对使用授权的资源、使用者、字段、交付方式、期限和状态。普通使用者从[数据资产](/guides/assets)申请使用，由共享交换的有权人员审批。加工授权、岗位职责、产品认证、安全标签和交付编号都不能代替使用授权；历史授权记录仍在，不代表现在可用。

## 防护策略与预检

1. 管理员进入[防护策略](/platform/security/policies)，点击“新建防护策略”，填写名称和保护目的。
2. 选择具体资源版本或适用安全级别，选择查询、下载、API调用、ETL交付等动作；按需限定接收部门和角色。先检查范围，避免误将策略用于过多资源。
3. 按业务选择拒绝交付、额外脱敏字段、签名交付凭据、页面可见水印或文件内容标记。需要水印模板时选择已发布的固定模板版本；原有敏感保护仍保留。
4. 保存草稿、提交复核，由另一位管理员批准发布。点击配置名称可核对当前发布版本、维护版本和版本记录。
5. 进入[策略预检](/platform/security/preflight)，选择同一资源版本，填写交付动作、模拟接收部门和角色，点击“核对已发布策略”。查看允许或阻止的原因、脱敏字段和标记要求。修改输入后应重新核对。
6. 再由实际有授权的使用者从资产平台办理对应交付，并核对实际结果及审计。预检只模拟当前已发布策略，不生成使用授权，也不保证实际交付一定成功。

调整策略时打开详情，点击“新建版本”，重新走保存、提交、独立复核。停用前检查关联资源及后续交付影响；停用某项配置不会撤销原有使用授权，也不会取消其他有效保护。

## 水印配置与交付核对

### 配置模板并关联策略

1. 管理员进入[水印管理](/platform/security/watermarks)，点击“新建水印模板”，填写名称、说明和模板文字。可使用 `{recipient}`、`{department}`、`{resource}`、`{version}`、`{time}`、`{delivery_id}` 变量。
2. 保存草稿后提交复核，由另一位管理员批准发布。模板只替换这些受支持变量，不执行代码、不加载外部资源；不要把真实密码或令牌写入模板。
3. 回到防护策略，选择已发布模板和具体交付动作，再勾选所需的页面水印、文件内容标记或签名交付凭据，完成策略的独立复核。仅发布一个模板不会自动给所有资产加水印。
4. 策略预检通过后，使用已有有效授权进行真实交付，在结果页面或交付凭据中核对接收主体、资源版本和交付编号。模板更新后，已有策略固定引用的旧版本不会自动替换，应更新策略并复核。

### 各交付方式的支持范围

| 交付方式 | 当前支持 | 核对重点 |
| --- | --- | --- |
| 页面查询 | 按策略显示可见标记，继续执行字段授权和脱敏 | 结果中的接收主体、资源版本与交付编号 |
| Excel文件 | 交付说明页和打印页眉标记，保留原文件及业务单元格 | 标记内容及实际输出文件摘要 |
| API调用 | 响应头提供交付编号，按策略生成签名溯源凭据 | 授权、响应交付编号与实际输出摘要 |
| ETL交付 | 保存提交前运行清单及签名凭据 | 来源、目标、运行和清单范围；摘要不是整个目标表内容摘要 |

PDF内容水印会叠加到每一页（最多200页、32MiB）；加密、数字签名或不安全的文件结构会被拒绝。Excel内容标记为说明页与打印页眉。

防护策略可以要求隐式溯源标识。PDF在页面内容中嵌入标识，Excel在文件包中保存标识；在“水印交付与溯源”中选择交付副本，点击“提取并核验”，核对标识归属、交付签名和实际文件摘要。编辑或重新保存可能移除标识，不能将它理解为抗任意篡改的隐写水印，也不能仅凭标识认定责任。

行级过滤条件须绑定具体资源版本。条件使用field（字段）、operator（比较方式）和value（比较值），多个条件按“并且”组合。可用eq、ne、lt、lte、gt、gte、in、is_null、not_null；文字值用双引号，普通数值不加引号；高精度整数或小数请加双引号，以免浏览器舍入。例如：`[{"field":"department","operator":"eq","value":"教育部门"}]`。保存后仍须独立复核发布，过滤不会代替使用授权。

行过滤在原生数据库表查询与ETL、Doris治理成果查询、未映射数据服务API的读取阶段执行，先过滤再分页、脱敏及后续处理。不支持的CDC快照、文件、外部API、映射服务和转换链路会拒绝受保护交付。整文件不能按字段脱敏或行裁剪时，应发布经过处理的独立文件资源。Oracle数值条件使用原生NUMBER绑定，日期使用原生DATE绑定；无法从契约确定时区语义的Oracle时间比较会拒绝执行，空值判断仍可使用。限期例外仍未开放。

强制标记格式不支持、签名密钥缺失或审计意图无法保存时，会阻止交付。治理执行或维护预览尚未适配新增保护要求时同样明确阻止，不把保护要求丢弃后继续运行。不要为完成演示而撤掉实际需要的保护。

## 风险事件处置步骤

1. 管理员进入[风险规则](/platform/security/risk-rules)，新建规则并选择资源版本，填写失败或拒绝次数阈值、观察窗口、名称和说明。阈值为1至100000次，窗口为1至1440分钟；保存并完成独立复核后生效。
2. 进入[安全事件](/platform/security/incidents)，点击“核对风险规则”。系统按已发布规则检查已有失败或拒绝审计，报告新增待核实事件数；没有新增事件不代表所有外部访问都没有风险。
3. 对人工发现的问题，可点击“登记事件”，选择资源版本，填写标题和观察证据。打开事件名称查看状态、处置原因和证据，先核实对象及版本。
4. 需要暂停该版本交付时，在待核实事件内点击“冻结对应资源”，填写依据并确认。冻结会限制对应版本的新交付和治理输入，不自动影响所有其他资源，也不抹除已经发生的交付。
5. 整改并补齐恢复依据后，由另一位有权管理员点击“复核并解除冻结”，核对后确认。事件登记人与冻结执行人不能自行完成恢复复核。
6. 复核关闭后，再核对资源的其他冻结、当前授权和有效策略，并按实际授权重新尝试交付。关闭一个事件不会绕过其他门禁。

风险规则需要主动核对，不是实时后台推送；失败次数达到阈值只形成待核实线索，不直接证明泄露或责任归属。

## 审计与交付验证

1. 在[审计记录](/platform/security/audit)搜索对象编号、操作或追踪号，点击“查看追踪”，核对操作者、时间、结果和对象。读到拒绝或失败时，保留对应追踪号再定位原因。
2. 在[水印交付与验证](/platform/security/proofs)打开交付编号，核对接收人、部门、资源版本、授权、保护版本、字段范围、实际摘要与状态。ETL还应查看运行清单和关联运行。
3. 取得待核对内容的SHA-256，输入64位十六进制摘要，点击“验证摘要与签名”。应使用实际收到的交付内容计算；ETL按记录中的提交前运行清单范围核对，不能用目标表摘要代替。
4. “记录匹配”表示摘要与签名记录匹配；“内容不同”应继续检查是否选错内容或内容被修改；“签名无效”交由管理员核查；“无法验证”表示当前证据或密钥不足，不能当作通过。旧签名密钥不可用也会显示无法验证。
5. 点击“查看关联审计”，继续查原申请、授权、策略和交付追踪；不要只凭一个交付编号下结论。

已准备、传输中断和结果未知不能解释为接收完成；服务端写出完成也不单独证明对方已经收妥或承担责任。ETL凭据附有运行清单，应按清单范围核对。

不要在处置说明中粘贴原始敏感数据、口令或令牌。

## 与其他平台联动

- 共享交换：先有资源目录和具体资源版本，再维护标签与策略；目录审核、共享启用、使用授权与安全复核分别办理。
- 数据治理：先有加工权限，再执行清洗或关联。来源保护通过字段血缘影响成果；输入冻结、保护证据缺失或计算适配不支持时，先查阻止原因，不丢弃保护后重跑。处理步骤见[数据治理操作指南](/guides/governance)。
- 数据资产：使用者在资产详情核对安全上下文，再按有效授权使用。产品认证、收藏或关注不会放宽保护；查询、下载、API和ETL均继续执行各自的安全检查。申请与反馈步骤见[数据资产操作指南](/guides/assets)。

当前两项“演示”资产可用于只读检查来源、版本和安全上下文。若要演练发布标签、策略、水印或冻结，应明确选中演示资源版本并按双人复核流程办理；现有样例不会自动配置这些保护。

## 常见问题

### 保存了模板，为什么没有水印？

检查模板是否已发布、是否被已发布策略引用、策略是否匹配当前资源版本及交付动作。草稿和待复核配置不生效，预检也不会生成交付或水印。

### 预检允许，为什么实际使用仍被拒绝？

预检只检查模拟条件下的已发布策略。继续核对实际使用授权、字段、期限、共享状态、冻结、格式和签名能力，并根据实际返回原因与追踪号定位。

### 为什么看不到批准或解除冻结按钮？

确认当前账号有相应权限、记录处于可办理状态，并且与当前版本作者、事件登记人和冻结执行人满足分离要求。请有职责的另一位人员复核，不通过创建同名记录规避审核。

### 资源升级后为什么要求重新复核？

安全结论与资源版本绑定。新版本需核对字段、标签和策略适用范围，不能把旧版本结论当作新版本已完成审查。
