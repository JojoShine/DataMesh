# Frontend design standard

- Read `../docs/design/interface-standard-v1.md` before changing a UI. Its user-approved typography table is the single source of truth, overriding historical rules and library defaults.
- Typography is fixed. Do not invent, propose, or apply a new font-size standard or per-page exceptions unless the user explicitly requests a change.
- Dialog commands (close, back, cancel, save, check, run, publish, approve) belong in a fixed bottom-right footer with 16px gaps and right-aligned wrapping on narrow screens. Do not duplicate them in the title or body. Keep only field edits, record links and pagination next to their content. Both exchange and governance dialogs use PlatformDialog (GovernanceDialog delegates to it), with no title-bar close icon or mask dismissal. Reuse DialogActions / GovernanceDialogActions for nested views; a moved submit button must retain its form association.
- Minimize stacked dialogs. Within a dialog, prefer replacing its content, inline expansion, or steps for details, diagnostics, selection, and editing; provide a return action and preserve form/selection state. Use a dedicated page for complex flows. Only genuinely high-risk actions may need a brief second confirmation dialog. Remove existing dialog stacking when changing the affected flow; do not introduce it for ordinary viewing or actions.
- Approved sizes: page titles 24px; dialog/section titles 18px bold; body and alert copy 15px; long-form reading 16px; form labels/input text/select options 15px; navigation/tabs/table content 14px; button text 14px; helper text/status tags 13px. Alert titles use 15px bold.
- Buttons are 32px high; single-line inputs and selects are 36px high. Textareas keep 15px text and content-appropriate height. Buttons must not inherit larger sizing from forms. The same rules apply in search rows, dialogs, login, and homepage controls.
- User-approved login exception (2026-11-04): the username/password controls and login submit button are all 40px high. Keep their existing 15px input and 14px button typography; the return button and other pages retain the standard sizes.
- Reuse `src/app/theme.ts` and shared styles to implement these exact sizes with component tokens. Do not increase global fontSize/controlHeight indiscriminately or add page-specific sizing themes. Existing Form size="large" and large search controls are legacy implementation to align, not an approved exception.
- Distinguish record navigation from business actions. Clickable data-source/task/dataset/object names and application IDs use blue links (Button type="link" when opening the existing detail drawer; real navigation uses href). Business actions such as apply/check/publish/withdraw/approve/disable use bordered Ant Design primary/default/danger buttons with a visible background and Space size={16} between actions. Do not turn record names into bordered buttons or operation commands into text links. Keep danger, disabled, loading, permissions, and confirmations. Toolbars and form/dialog footers use standard primary/default buttons. Keep the native background, border, padding, and interaction states; apply the approved typography and heights. Navigation icon/account triggers may retain their existing navigation treatment.
- Page composition remains independent: platform page titles 24px (including mobile), custom body 15px, helper copy 13px, workspace padding 16px/24px, custom business-panel padding 20px, header 64px. Dialog/drawer content widths may follow information needs; this does not justify enlarging their controls.
- Homepage presentation stays larger: hero 52px (32px mobile), entry title/description 22px/16px (20px/15px mobile), section title 28px (24px mobile), asset title/body 18px/16px. These existing presentation exceptions do not resize embedded controls or tags; do not add further typography exceptions. Login hero 44px (32px mobile).
- Preserve the approved 24px detail section spacing, responsive wrapping, internal table scrolling, real data, and all business/authentication behavior. Check changed screens at 1920×1080 and a narrow viewport. No new mockups or dependencies for routine style corrections.
